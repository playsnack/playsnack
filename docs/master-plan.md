## 0. 북극성
- **루프:** 숏폼 링크 → 3초 안에 첫 탭 → 결과 카드 → 공유/초대 → 친구가 들어와 같이 → 재공유.
  **실사용자 숫자로** 이 루프를 증명한 뒤에 엔진 · 3D · 생태계를 키운다.
- **지표 = 전파:** 첫 탭 시간, 결과 도달률, 공유율, 초대→입장 성공률, 2단계 재공유.
- **원칙:**
  - 포맷은 우리 것 · 기반은 오픈소스 · 사이는 어댑터.
  - 라이브를 깨지 않는다. 버그마다 회귀 케이스를 남긴다.
  - 측정 없이 엔진을 결정하지 않는다.
  - 되는 척 문구는 즉시 제거한다.

## 4. 로드맵 — 단계는 순서대로, 레인은 병렬로
**진행 방식**
- 각 레인은 서브에이전트가 **독립 워크트리(브랜치)**에서 맡는다.
- 레인끼리 **담당 파일이 겹치지 않게** 나누고, 레인 사이의 약속(인터페이스)은 시작 전에 고정한다.
- 단계가 끝나면 내가 레인들을 단계 브랜치(`claude/<단계>`)에 합친다.
- 그다음 **gate-all과 폰 확인**을 거쳐 PR을 연다. 주인이 merge하면 라이브에 반영된다.
- "크기"는 상대 규모(일 단위 추정)다.

### Q1 — 방 신뢰성 + 링크 구조
| 레인 | 담당 | 작업 | 크기 |
|---|---|---|---|
| **A 방 엔진** | `room.js`, `meshClient.js` | ① 공정 판정(MP-08) + 발행 묶기<br>② 인계 일치(MP-06)<br>③ 동점 · 나간 사람 · 콘솔 경고 · 그룹 월드컵 조기 진행(MP-11/12/13, T-21) | 5.5 |
| **B 링크** | 라우팅, `backend.ts` 링크부, `vercel.json` | 경로형 링크 `/p/:slug`(옛 `#/p/…`는 자동 전환) + 친구끼리 방 코드(8자 이상) → 긴 닉네임 처리(T-22) | 2 |

**공정 판정(MP-08) 방식**
- 반응 시간: 각자 기기에서 "초록 표시→탭" 시간을 재고, 방장은 범위만 검증한다.
- 탭 배틀: 250ms마다 누적 수와 최종값을 보내고 방장은 최대값을 채택한다. 상한은 초당 15탭.
- 카운트다운: "N ms 뒤 종료"를 보내고 각자 로컬로 진행한다.

**통과 기준**
- 손실 sim 13/13 × 3회.
- 실기기 20회 입장: p75 ≤ 2초, p95 ≤ 4초.
- 방장 교체 결과 일치 4/4.
- 반응 점수가 기기 측정값임을 sim으로 증명.
- 카운트다운 차이 ≤ 150ms(두 화면을 240fps로 촬영).

**레인 A 상태 (2026-10-13, `claude/q1-lane-a`)** — ①②③ 구현 완료. 반응 `reaction {ms}`·탭 `taps {count}` 액션(`docs/bite-format.md` §6.1), `countdown` 메시지 + 클라이언트 로컬 3·2·1(`packages/snack-room/src/countdown.js`), 인계 시 액션 재전송·즉시 스냅샷, 동점·나감·미선언 변수 0건·월드컵 조기 진행. 회귀 테스트 17건(기준 커밋 6094454에서 13건 실패 확인). 증거: 손실 sim 10/10 ×3(병합으로 사라진 3개 제외하면 10개가 전부), 방장 교체 6/6(E·F 추가, E는 옛 코드에서 실패), 반응 점수 = 기기 측정값 sim 행(`session:reaction:device-measured`), 카운트다운 메시지 손실 시에도 3·2·1 순서 유지·편차 ≤ 100ms(mesh 단위 테스트; 실기기 240fps 촬영은 미실시). 실기기 입장 20회·p75/p95는 미측정.

이 단계의 방은 공개 브로커 + 추측 불가 방 코드로만 보호된다. 그래서 닫힌 테스트(U1)까지만 허용한다.
