## 0. 한 줄 판정

**지금 이 계획대로 가면 안 된다.** 방향(포맷=계약, 오픈소스 벽돌, 어댑터, 채점표, 스파이크로 결정)은 좋다.
하지만 (1) "엔진 전체가 Rust여야 한다"는 핵심 전제가 사실이 아니고, (2) 동기 세 가지 중 두 가지가 이미 확정한 제품/디자인 결정과 부딪치며,
(3) 위험이 가장 큰 질문(웹 첫 로딩·안드로이드 웹뷰 GPU·한글/이모지 렌더링)을 뒤로 미루고 가치가 가장 작은 일(이미 같은 코드로 도는 서버 검증을 Rust로 다시 짜기)을 먼저 한다.
그리고 **버그 많은 라이브 서비스·꺼진 AI 빌더·인증 없는 공개 브로커**라는 지금의 진짜 병목을 건드리지 않는다.

권장: **품질 트랙을 앞에, 측정을 첫날부터, 엔진은 시간 상자(time-box) 스파이크로만** → 증거가 나올 때만 Rust 렌더러로 간다.

## 2. 이슈 (심각도 순)

### 🟥 BLOCKER

**B1. 핵심 전제가 틀렸다 — "네이티브엔 JS가 없으니 엔진 전체 Rust"**
- 근거: F1, F14. iOS JavaScriptCore, Android Hermes/QuickJS, React Native(+Yoga 네이티브, +react-native-skia로 블러/백드롭)로 **지금 TS 런타임 ~900줄 + Yoga 레이아웃을 그대로** 네이티브에서 돌릴 수 있다. 앱스토어 4.7은 오히려 HTML5/JS 미니게임을 명시적으로 허용한다.
- 영향: 계획 전체(§0 목적지, §2 벽돌 지도, §4 서버 공유 코어)가 이 전제 위에 서 있다.
- 수정: §0을 "네이티브 앱이 필요해지면 ①웹뷰 셸(4.7 준수) ②RN+Hermes+Skia(TS 런타임 재사용) ③Rust 코어 중 측정으로 고른다"로 바꾼다. Rust는 "필요가 증명된 곳"에만.

**B2. 순서와 기회비용 — 라이브 서비스가 버그투성이인데 엔진 재작성부터**
- 근거: 사용자 본인 진술("버그·어색한 부분이 많다"), AI 빌더 꺼짐(키 없음·서버리스, 메모리 serverless-mesh), 멀티가 **공개 테스트 브로커(EMQX public)**에 인증 없이 올라가 있음, Vercel Hobby = 비상업 전용. 그리고 **Bite 엔진 자체가 5일 전(2026-10-07) TROS에서 갈아탄 것**(git log B0–B7). 6월 TROS → 10월 Bite → 이번 Rust = 엔진 교체 3회 연속 패턴.
- 영향: Rust 재작성은 수개월간 사용자 지표(플레이 수·공유율·방 입장 성공률)를 하나도 안 움직인다. 엔진이 문제라는 증거(사용자가 못 해서 떠난 기능)가 하나도 제시되지 않았다.
- 수정: 품질 트랙(Q)을 용량의 ≥70%로 먼저. 엔진은 Q에도 이득인 일(채점표 = 버그 수정 회귀망)과 시간 상자 스파이크만. §4 로드맵 참조.

**B3. 북극성이 확정된 제품 정체성·디자인 시스템과 정면충돌**
- 근거:
  - 정체성(2026-06-23 확정): "휘발성/스낵 — 계정·스트릭·시즌·누적 진척 거부". 마인크래프트/로블록스형 = 계정·상시 월드·저장·크리에이터 경제·진척. **반대말이다.**
  - 디자인 시스템(2026-06-26 확정): "청키 블록, **blur:0 하드 오프셋 그림자(필터 비용 0)**". 계획의 동기 1번은 "블러·글라스를 겹겹이".
  - 즉 Rust 전환 동기 3개(글라스 / 네이티브 / 3D) 중 하나는 디자인 결정과, 하나는(B1) 사실과 어긋난다. 남는 건 3D뿐인데 3D는 웹에서 three.js(MIT)로 이미 된다.
- 수정: 계획 맨 앞에 "정체성 조정" 절을 두고 둘 중 하나를 명시적으로 고른다. 리뷰어 추천 = **"휘발성 UGC"**: 링크로 퍼지는 AI 제작 스낵(만들기 = 채팅 한 번), 3D는 "스낵 크기의 3D 노드"이지 상시 월드가 아님. 상시 월드는 별도 제품 결정으로 분리.

**B4. 단계 1은 혼자서 가치가 없고, 통과 기준은 설계상 실패한다**
- 근거: F11, F12, F18. 서버 검증은 이미 브라우저와 같은 JS 코드다. Rust 코어로 바꾸면 **같은 엔진의 두 번째 구현**을 단계 3(단계 2에서 취소될 수도 있음)까지 동기화 유지해야 한다 → 순수 비용. 그리고 parley를 쓰면 measure.js와 일부러 다르게 나오고, taffy는 Yoga와 기본값·min-size·반올림이 다르다.
- 수정: 단계 1과 2의 순서를 뒤집는다(렌더러/웹 전달 위험부터). 코어 포팅을 하게 되면: 측정은 measure.js 알고리즘을 그대로(셰이핑은 렌더링용으로만), 레이아웃은 "Yoga 흉내"가 아니라 **Bite 포맷 레이아웃 의미론을 스펙으로 쓰고 마이크로 픽스처로 고정**한 뒤 taffy를 맞춘다(필요하면 Yoga C++ 바인딩).

### 🟧 MAJOR

**M1. 실제 유입 경로(인앱 브라우저)에서의 GPU 현실을 모른다**
- 근거: F2–F4. 한국 숏폼 링크는 카카오톡·인스타 인앱 브라우저(= WKWebView / Android System WebView)로 열린다. 안드로이드 웹뷰 WebGPU는 확인 불가, Chrome도 Android 12+ 특정 GPU만. → **안드로이드 대다수가 WebGL2 폴백**일 수 있고, 그러면 vello 본체는 못 쓰고 vello_hybrid(더 새롭고 덜 성숙)나 자체 패스가 주 경로가 된다.
- 수정: 오늘 라이브 앱에 **익명 기능 텔레메트리**(`navigator.gpu` 유무·`requestAdapter` 성공·WebGL2 유무·인앱 브라우저 UA 분류·DPR·기기 메모리 등급)를 넣고 2주 모은다. 단계 2의 "실기기"는 반드시 **카카오톡 인앱 브라우저 안에서** 잰다.

**M2. 번들/첫 로딩 예산이 기준선 없이 정해졌다 (+ 이모지·폰트 누락)**
- 근거: 현재 기준선(실측, gzip): 메인 247KB + mqtt 107KB + Pixi 렌더러 청크 ~50KB, 폰트는 문서별 지연 로딩 굵기당 ~270KB. 계획의 2.5초/2MB는 **현재 앱의 실측 p75와 비교되지 않은** 절대값이다. F5–F7.
- 수정: 예산을 "현재 대비"로: 예) 인앱 브라우저 4G 중급 안드로이드 **p75 첫 상호작용 가능 시점이 현재 +300ms 이하**, 추가 다운로드 +600KB gz 이하(폰트 별도). 이모지 전략을 스파이크 항목으로 추가(①브라우저 캔버스로 이모지를 비트맵 렌더 후 텍스처 업로드 = 하이브리드, ②COLRv1 폰트 탑재, ③이모지 금지 린트 — ③은 콘텐츠 정체성상 비추천).

**M3. 식(expression)의 의미론 = JavaScript 의미론 — 진짜 포팅 위험은 여기**
- 근거: `bite/src/expr.js:41-87,94-122`. `+` 문자열 강제변환·truthiness·`Array.prototype.sort` 기본 사전순 정렬(`[10,9,1].sort()` → `[1,10,9]`)·`toFixed`·`toLocaleString("ko-KR")`(`fmt`)·`String(number)` 서식(1e21 등)·`padStart`·`split`·`Intl.Segmenter`·`Math.imul`. Rust 포팅 = **JS 부분집합을 버그까지 똑같이 재구현**.
- 수정: (a) 식 차등 퍼징 코퍼스(아래 §5) 없이는 포팅 금지. (b) 대안: Rust 코어 안에 JS 엔진 내장(QuickJS via rquickjs, MIT / Boa) — 의미론 일치가 공짜. (c) 포맷 v1.1에서 JS 특이점을 스펙으로 못 박기(정렬 규칙, 숫자 서식) + 마이그레이션.

**M4. 스크립트 언어: 빌드 문제 + 생성/검증 보장 붕괴**
- 근거: F8. Luau(emscripten) + wgpu(wasm-bindgen, unknown-unknown) 한 모듈 결합 불가. 더 큰 문제: 튜링 완전 스크립트는 지금 품질 게이트("validate + 헤드리스 플레이 + 레이아웃 린트")의 보장을 약화시키고(무한루프·CPU·메모리), 포맷 원칙 3 "AI가 틀리기 어려운 모양"과 충돌.
- 수정: **실제 템플릿이 선언형으로 불가능함이 증명될 때까지 스크립트 보류**. 그때 후보에 "JS 부분집합 + QuickJS-wasm"을 추가(LLM 최강 언어, 식이 이미 JS-like, 웹에선 브라우저 엔진 Worker로). 어떤 언어든 명령 수 예산(Luau interrupt / rhai max_operations / QuickJS interrupt handler)·메모리 상한·결정적 시간 주입을 필수 요건으로.

**M5. 멀티플레이: 결정론 개념 혼동 + 지금 당장의 보안 구멍**
- 근거: F9. 권위 서버는 "사용자는 서버를 못 돌린다"(serverless-mesh 메모)와 모순이고 비용 모델이 없다. 더 급한 것: 현재 방이 **인증 없는 공개 브로커** — 토픽만 알면 누구나 상태를 덮어쓸 수 있다(치팅·방해·스팸), 무료 공개 브로커는 테스트 용도(약관 [U]), SLA 없음. 방장 기기가 권위 = 방장 치팅 무방비.
- 수정: Q 트랙 항목으로 올린다 — 자체/관리형 브로커(또는 Cloudflare Durable Objects 같은 방 단위 저가 권위자), 방 비밀 토큰, 메시지 서명/시퀀스. 3D 액션용 권위 서버는 "필요가 증명된 뒤 비용표와 함께" 별도 결정.

### 단계 (각 = 산출물 · 통과 기준 · 취소 조건 · 시간 상자)

**Q0 (지금~2주) 안정화** — 감사 P0 전부 + P1 상위. 통과: gate-all 초록 + 실기기 2대(카톡 인앱) 수동 체크리스트 44/44 + 신규 회귀 케이스 수 = 수정 수.

**E0 (Q0과 병행, 3~5일) 채점표 v1** — §5 설계대로. 통과: 2회 실행 바이트 동일, 실브라우저 오라클 상태와 차등 일치, bless 규약 문서화. *이게 Q 트랙의 회귀망이 되므로 가장 먼저.*

**M0 (1주차, 2~3일) 텔레메트리** — 통과: 2주 데이터로 "WebGPU 사용 가능 비율(인앱 브라우저별)", "현재 p75 첫 상호작용 시간" 숫자가 나옴.

**E1 (3~4주차, 시간 상자 합계 8일) 위험 제거 스파이크 — 양쪽을 같은 화면으로**
- E1a (2일) Pixi v8: 글라스/백드롭 카드 + three.js 복셀 500개, 카톡 인앱 실측.
- E1b (4~5일) Rust: §6의 최소 스파이크.
- E1c (1일) 이모지 전략 비교.
- **게이트 G1**: Rust 렌더러로 갈 조건 = (E1a가 예산 실패) **AND** (E1b가 예산 통과: 추가 ≤600KB gz, p75 TTFF 현재 +300ms 이하, WebGL2 경로 포함 p95 프레임 ≤16.7ms, 한글 SSIM ≥0.98, 이모지 해결). 아니면 → **Rust 렌더러 계획 보류**(채점표·스파이크 결과는 문서로 남김).

**E2 (G1 후, 1~2주) 포맷 v1.1 위생** — 버전·마이그레이션 체인, JS 특이점 스펙화(정렬·숫자 서식), 제스처 소켓 스펙(관성 포함), 접근성 DOM 레이어. *어느 엔진이든 필요.*

**E3 (2~3주) 3D 스낵 프로토타입 2종** (three.js 노드, 지금 스택) — 통과: 오라클 통과 + 공유율/완주율이 2D 평균 대비 측정됨. 취소: 완주율이 2D 하위 25% 미만이면 3D 우선순위 내림.

**E4 (조건부) 네이티브 셸** — 진입 조건 예: 주간 활성 링크 열기 N 이상 + "설치 필요" 근거(예: 공유 시트·푸시 없이도 재방문 문제) [J]. 먼저 웹뷰 셸(4.7.1/4.7.4/4.7.5 준수), 부족하면 B.

**E5 (조건부) Rust 코어/렌더러** — G1 통과 시에만. 순서: 렌더러를 기존 TS 코어 옆에 소켓으로(코어 포팅은 나중) → 채점표+이미지 비교로 템플릿 단위 점진 전환 → 플래그로 A/B 배포(서비스 중단 없음). 시간 상자 3개월, 2개월 시점 44개 중 30개 미만이면 취소.

**생태계(상시 월드)** — 진입 조건: B3 정체성 결정 + 주간 크리에이터 수 N + 안전/법률 검토 완료. 별도 계획.

### 순서 요약
1) Q0 버그 + E0 채점표(동시) → 2) M0 측정 → 3) E1 양쪽 스파이크 → G1 → 4) E2 포맷 위생 → 5) E3 3D 스낵 → 6) 조건부 E4 네이티브 셸 / E5 Rust.

### 공통 취소(kill) 규칙
- P0 버그가 열린 주에는 E 트랙 0%.
- 어떤 엔진 단계든 시간 상자 150% 초과 → 자동 중단·재검토.
- 측정 데이터 없이 내린 엔진 결정은 무효(원칙 6).

## 5. 단계 0 채점표 — 무엇을 기록해야 다른 구현을 채점할 수 있나

### 입력(트레이스 헤더) — 전부 고정해야 재현됨
- `doc` 해시, 엔진 커밋, `frame`, 포맷 버전.
- **난수**: `Math.random` 대신 스펙에 명시한 시드 PRNG(예: sfc32/xorshift128+, 알고리즘을 스펙에 기록) — 런타임에 이미 주입점 있음(`bite/src/runtime.js:29`, `snack-room/src/room.js:47`). Rust가 비트 단위로 같은 수열을 낼 수 있어야 함. 난수 호출 횟수도 기록.
- **시계**: 가상 시계(`now = t0 + 스크립트 진행`), onFrame 틱은 고정 dt. `Date.now` 직접 호출 0개를 린트로 강제.
- **데이터**: `data.url`/`/api/content`/콘텐츠 뱅크 응답을 픽스처로 동결(매시 바뀌는 LLM 콘텐츠 그대로 쓰면 재현 불가).
- 닉네임·방 메시지 등 외부 입력도 트레이스 이벤트로.

### 이벤트 스크립트
- `{tap: nodeId}`(좌표 아님 + 별도로 좌표 탭 샘플 몇 개로 히트테스트 검증), `{advance: ms}`, `{frame: n}`, `{input: text}`, `{scroll: dy}`, `{room: msg}`.
- 생성 3종: ① 템플릿별 **결과 페이즈까지 가는 정답 경로**(오라클 시나리오 재사용) ② 시드 랜덤 워크(템플릿당 ~50개: 보이는 탭 대상 무작위 + 무작위 시간 진행) ③ 엣지(연타, 페이즈 전환 중 탭, 타이머 경계 ±1ms).

### 출력(단계마다)
- `phase`, `vars` 정규화 JSON(키 정렬, 숫자는 최단 왕복 표현, `-0`/NaN/Infinity 태그), 경고 목록, 난수 호출 수.
- 펼친 트리: 노드 id·종류·보임 여부·`box`(지금 정수), 텍스트 줄(문자열 + 폭 소수 3자리), 스크롤 콘텐츠 크기.
- 히트테스트 탐침: 화면을 20×40 격자로 찍어 각 점의 최상위 탭 대상 id.
- (렌더러 교체용) 오라클의 단계별 스크린샷 → 이미지 비교 기준.

### 단위 코퍼스(템플릿 트레이스보다 먼저 깨지는 곳)
- **식 코퍼스**: 44 템플릿 + AI 생성물의 모든 식 + 퍼저 생성 식 × 무작위 변수 환경 → 값 비교(M3).
- **레이아웃 마이크로 픽스처**: 포맷 레이아웃 키(column/row/free/grid × fill/hug/grow/min/max/pad/gap/align/justify) 조합별 소형 문서(F11).
- **측정 코퍼스**: 한글·영문·숫자·이모지·혼합·줄바꿈·말줄임 문자열 × 크기·굵기·폭.
- **방 트레이스**: room.js 시드 시뮬의 메시지 로그(m4).

### 허용 오차
- 변수·페이즈·경고: 완전 일치. 레이아웃: 정수 완전 일치(다른 구현이면 차이는 이유 붙은 허용 목록으로만). 텍스트 폭: 1e-3. 이미지: SSIM 기준.

### Q 트랙과의 공존 규약 (bless)
- `conformance --bless <템플릿>`은 차이 보고서를 만들고, 커밋 메시지에 버그 ID가 있어야 통과. 의도된 변경(버그 수정)과 회귀를 구분.
- 옛 문서 묶음(링크에 박힌 v1 문서 표본)은 bless 금지 — 하위 호환 고정.

## 6. 위험을 가장 많이 줄이는 최소 Rust 스파이크 (4~5일)

**코어 포팅이 아니다**(코어는 작고 위험이 낮다). 가장 불확실한 건 "웹에서 Rust가 그린 한 화면이 브라우저/Pixi만큼 빨리·예쁘게 뜨는가"다.

- 화면 1개: 결과 카드 — 한글 제목(Galmuri11) + 본문(Pretendard 2굵기) + **이모지 3개** + 둥근 사각형 + 하드 그림자 + 블러 그림자 1개 + 이미지 1장 + 탭 반응.
- 구성: wgpu **WebGL2 강제 경로**와 WebGPU 경로 둘 다, 2D는 vello_hybrid(또는 단순 쿼드 렌더러), 글자는 parley(+skrifa), 폰트는 기존 woff2 서브셋, 이미지는 `createImageBitmap`.
- 측정: ① wasm gz 크기(코드/폰트 분리) ② 카톡 인앱 브라우저 콜드 TTFF(중급 안드로이드·아이폰) ③ 3분 p95 프레임 ④ Pixi 같은 화면 대비 SSIM ⑤ 이모지 결과(어떤 방식으로 됐나/안 됐나).
- 같은 화면을 Pixi+pixi-filters로 2일 안에 만들어 같은 표에 올린다(E1a).
- 결과는 G1 게이트의 입력. 숫자가 나쁘면 Rust 렌더러는 깔끔히 보류 — 4~5일 손실로 끝남.
