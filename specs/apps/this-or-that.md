# 라면 vs 김밥 `this-or-that`  ·  vote

**Verdict:** broken  ·  **Mode:** multi (vote (라이브 일인일표 폴, 서버 집계 votesByOption broadcast))

## 주제 매력도
"라면 vs 김밥"(현 구현은 떡볶이 vs 피자) 같은 음식 양자택일은 한국인이 가장 즉각 반응하는 취향 주제다 — 분식파 논쟁, 'MBTI보다 정확한 취향테스트' 밈처럼 의견이 갈리고 공유 욕구가 강하다. 다만 '라면 vs 김밥'은 보완재(같이 먹는 조합)라 대립 긴장감이 약하다. 더 매력적인 대결은 진짜 파가 갈리는 쌍: 민트초코 vs 반민초, 부먹 vs 찍먹, 물복 vs 딱복, 라면국물에 밥 vs 면, 아침 vs 안먹음. '극단적으로 갈리는 한 입거리' 주제일수록 탭 욕구와 결과 확인 욕구가 커진다.

## 레퍼런스 (검증된 인기 포맷 모방)
- **모방 대상:** 인스타그램/유튜브 라이브 양자택일 투표 (This or That poll) + 트위터 폴
- **구조 100% 복제:** 검증된 라이브 폴 구조 100% 모방: (1) 질문 헤더, (2) 두 후보를 나란히 큰 탭 타깃으로, (3) 탭 즉시 내 픽 하이라이트 + 서버 집계, (4) 두 개의 가로 막대로 실시간 % 비율 표시(다른 사람 표가 들어오면 막대가 움직임), (5) 총 참여수 LIVE 뱃지. 일인일표(중복 시 재투표로 교체), 결과는 탭 직후 바로 공개.
- **우리 콘텐츠/디자인:** 콘텐츠: 대립이 진짜 갈리는 한국형 음식 대결 쌍(민초 vs 반민초, 부먹 vs 찍먹 등)과 우리 카피. 디자인: 블랙(#0b0c0e) 배경 + 라임(#d9ff00) 강조, 다크 카드, 라임 막대 채움 — 우리 톤 그대로.

## 목적
링크를 받자마자 '나는 어느 파?'를 한 번 탭해서 답하고, 같은 링크를 보는 사람들의 실시간 비율로 '내가 다수파인지 소수파인지'를 즉시 확인하는 휘발성 스낵. 30초 안에 끝나는 취향 확인 + 약한 소속감/우월감의 재미.

## 핵심 루프
두 후보 중 하나를 탭 → 내 픽이 라임색으로 표시되고, 서버가 모든 참여자 표를 집계해 두 막대의 실시간 비율이 즉시 갱신된다.

## 시나리오
1. 사용자가 공유 링크를 열면 질문 헤더('오늘 뭐 먹지?')와 두 후보 카드(떡볶이/피자), 하단에 0% 막대 2개와 LIVE 뱃지가 보인다
2. 사용자가 '떡볶이' 카드를 탭한다 → 앱이 즉시 그 카드를 라임색으로 하이라이트하고 하단 '내 선택은 떡볶이'로 바뀐다
3. 동시에 emitHostEvent('vote') 발생 → 서버가 내 표를 기록하고 votesByOption 집계를 전체에 broadcast
4. 앱이 두 막대를 실제 비율(예 떡볶이 64% / 피자 36%)로 즉시 채워 보여주고 총 참여수가 +1 된다
5. 다른 참여자가 투표하면 내 화면의 막대 비율과 총 참여수가 추가 탭 없이 실시간으로 움직인다
6. 사용자가 마음을 바꿔 '피자'를 다시 탭하면 내 픽이 피자로 교체되고(일인일표) 비율이 재계산된다
7. 사용자는 결과를 확인하고 링크를 친구에게 공유하거나 닫는다 — 1회성 소비로 종료

## 성공 기준
- 헤더/후보/막대/총표가 한 화면에 스크롤 없이 또는 자연스러운 한 화면 안에 들어오고 텍스트가 안 겹친다
- 탭하면 데드타임 없이 즉시 내 픽 하이라이트 + 비율 반영(snappy)
- 두 막대 비율의 합이 항상 약 100%이고, 표가 늘면 라임 막대가 눈에 보이게 움직인다
- 총 참여수와 각 % 숫자가 실제 서버 집계와 일치한다(가짜/고정 0% 금지)
- 후보 라벨/이모지가 실제 그 음식과 일치한다
- 다른 사람 표가 추가 인터랙션 없이 실시간 반영된다
- 블랙+라임 톤 일관, 내 픽만 라임으로 구분된다

## QA 검증 시나리오
- [ ] **QA1** 두 후보 카드를 각각 탭했을 때 응답하는가 → `탭한 카드가 라임 하이라이트되고 하단 '내 선택은 X'로 바뀌며 emitHostEvent('vote') 전송`
- [ ] **QA2** 투표 후 두 막대의 pct/라임 채움이 실제 비율로 변하는가 → `votesByOption 기준 비율로 fill이 늘고 % 숫자가 갱신됨(두 막대 합 ≈100%)`
- [ ] **QA3** 총 참여수 텍스트가 표가 늘 때 증가하는가 → `'총 N표 참여 중'의 N이 투표마다 +1`
- [ ] **QA4** 막대 % 숫자와 막대 fill 길이가 서로 일치하는가 → `예: 피자 64%면 피자 막대 fill이 트랙의 64% 차지(숫자=시각 일치)`
- [ ] **QA5** votesByOption 키가 후보 키(tteokbokki/pizza)와 정확히 일치하는가 → `서버 tally가 tteokbokki/pizza 키로 집계되어 바인딩이 0이 아닌 값을 받음`
- [ ] **QA6** 일인일표·재투표가 동작하는가 → `같은 사용자가 다른 카드 탭 시 표가 교체되고 총수는 증가하지 않음`
- [ ] **QA7** 텍스트 겹침/오버플로가 없는가 → `헤더/후보/막대/내픽 카드가 화면 안에서 안 겹침`
- [ ] **QA8** 후보 라벨이 실제 음식과 일치하는가 → `'떡볶이 🌶️' '피자 🍕' 라벨/이모지가 대상과 일치`

## 현재 깨짐 (진단)
- **[high]** 라이브 결과 막대가 표가 있는데도 영구히 0%로 멈춤 — 핵심 메커닉(실시간 비율)이 완전히 죽음. 스크린샷 2/3에서 '총 11표 참여 중'인데 떡볶이 0% / 피자 0%, 라임 막대 채움이 전혀 없음. 표가 11개면 두 막대 합이 ≈100%여야 하므로 수학적으로 불가능한 상태
  - 근거: shot 2·3: '총 11표 참여 중' 표시 + 떡볶이 0%·피자 0% 동시. 막대 트랙(track)에 라임 fill이 0폭. totalText 바인딩(votesByOption.tteokbokki+votesByOption.pizza)은 11로 동작하는데 ResultBar 인스턴스 prop 바인딩(barTteokbokki.pct/.value, barPizza.pct/.value)은 반영 안 됨 → 컴포넌트 인스턴스 propValues 바인딩이 런타임에서 내부 레이어(fill.flexGrow='$props.pct', val.content='$props.value')로 재전파되지 않음
  - 수정: ResultBar 컴포넌트 의존을 버리고 make-vote.mjs의 검증된 인라인 막대 방식으로 교체(rect width를 직접 state 바인딩: bar.width = Math.round(votesByOption.key/total*W), pct.content를 같은 식으로 직접 텍스트 바인딩). 즉 인스턴스 prop 경유 없이 state-level 바인딩이 실제 레이어 prop을 직접 건드리게 한다(MEMORY: bindings must be state-level)
- **[high]** 서버에 남은 stale 표가 현재 후보 키와 불일치 — 떡볶이 표가 영원히 0. 영속 votes 파일 tpl-this-or-that.json이 과거 옵션 키(A:25, B:22, pizza:11)로 채워져 있고 tteokbokki 키는 0개. tally()가 {tteokbokki:0, pizza:11, A:25, B:22}를 반환해 떡볶이 비율이 절대 안 올라가고 총표 집계도 오염됨
  - 근거: snack-server/data/votes/tpl-this-or-that.json: Counter({'A':25,'B':22,'pizza':11}), tteokbokki 0개. index.mjs:88 tally는 옵션 '값'을 키로 카운트하므로 옛 A/B 표가 그대로 남음. totalText가 0+11=11표로 나온 것과 정확히 일치
  - 수정: 이 슬러그의 votes 파일을 현 후보 키로 초기화/리셋(또는 템플릿 옵션 키를 재정의 시 서버가 기존 표를 마이그레이션/폐기). 템플릿 시드 데모표는 항상 현재 옵션 키로만 생성하고, 옵션 변경 시 stale 표 폐기 로직 추가
- **[medium]** 제목/주제 불일치 — 카탈로그 제목은 '라면 vs 김밥'인데 실제 앱은 '오늘 뭐 먹지? / 떡볶이 vs 피자'. 본보기 템플릿으로서 메타데이터-콘텐츠 정합성이 깨짐
  - 근거: 과제 명시 제목='라면 vs 김밥', metadata.name='취향 양자택일 라이브 투표', 헤더 content='오늘 뭐 먹지?', 후보=떡볶이/피자 (this-or-that.bite.json:5,59,151,166)
  - 수정: 제목·헤더·후보를 하나의 주제로 통일. 권장: 대립이 강한 쌍(예 민초 vs 반민초)으로 통일하고 metadata.name·NavBar.title·옵션 라벨·votesByOption 키를 일치시킴
- **[low]** heroCard 내부 여백 과다 + moodCard 큰 빈 영역 — 정보 밀도 대비 데드 스페이스가 많아 결과 막대가 화면 중하단으로 밀림. heroBody와 다음 요소 사이, moodCard(height:fill) 안에 텍스트 2줄만 있어 넓은 빈 카드
  - 근거: shot 1~3: heroCard(170px) 안 텍스트 사이 큰 공백, 하단 moodCard가 height:'fill'(this-or-that.bite.json:263)로 남은 세로를 다 먹어 안내문 2줄만 띄운 빈 박스
  - 수정: moodCard height를 'hug'로 바꾸거나 픽 상태/소수파 여부 같은 정보를 더 채워 빈 영역 제거. 핵심(후보+막대)을 상단으로 끌어올려 첫 화면에서 바로 보이게
