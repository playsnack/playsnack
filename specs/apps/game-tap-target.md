# 빠른 탭 챌린지 `game-tap-target`  ·  game

**Verdict:** needs-fix  ·  **Mode:** single

## 주제 매력도
반응속도/순발력 챌린지는 "내 반사신경 몇 점?"이라는 자가측정 욕구를 자극하는, 검증된 캐주얼 장르다. 10초 안에 점수 경쟁 → 친구에게 점수 자랑하기로 자연스럽게 바이럴된다. 한국에서 "반응속도 테스트"는 꾸준히 검색·공유되는 포맷이라 주제 매력은 충분하다. 다만 단색 ◎ 타겟만 반복되면 단조로우니, 콘텐츠 측면에서 타겟에 가끔 보너스/함정(예: 빨간 타겟은 누르면 감점) 같은 변주를 넣으면 더 끈적해진다.

## 레퍼런스 (검증된 인기 포맷 모방)
- **모방 대상:** Whack-A-Mole / 표준 reflex-tap 미니게임 (Aim Trainer류)
- **구조 100% 복제:** 제한시간(10초) 동안 무작위 위치에 등장하는 타겟을 빠르게 탭 → 탭마다 +1점·타겟 재배치 → 시간 종료 시 결과/최고기록 → 다시하기. 시작→플레이→결과 3-스테이트 루프와 점수·타이머·베스트 기록 갱신 흐름을 100% 모방.
- **우리 콘텐츠/디자인:** 콘텐츠: 한국어 카피(보이면 바로 탭!, 멋진 집중력이에요 등)와 점수 격려 메시지. 디자인: 블랙(#0b0c0e) 배경 + 라임(#d9ff00) 타겟/버튼, 둥근 카드 톤은 우리 디자인 시스템 그대로. 룰은 reflex-tap이지만 룩앤필과 문구는 우리 것.

## 목적
지루한 1분, 자기 반사신경이 얼마나 빠른지 즉석에서 확인하고 싶을 때 여는 휘발성 스낵. 10초만에 점수가 나오고, 그 숫자를 캡처해 친구에게 '나 이거 나왔는데 너는?' 하고 던지는 재미를 준다.

## 핵심 루프
10초 동안 화면에 무작위로 튀어나오는 라임색 타겟을 최대한 빨리·많이 탭해서 점수를 쌓는다.

## 시나리오
1. 사용자가 앱을 연다 → ready 화면: 큰 라임 오브, '보이면 바로 탭!', 최고기록 칩(0점), '시작' 버튼 노출
2. '시작' 탭 → score=0, startedAt=$now 세팅, 타겟 무작위 위치로 이동, play 스테이트로 전환
3. play 화면: 상단에 점수/남은시간 StatCard 2개, 가운데 플레이 영역에 라임 타겟 등장
4. 사용자가 타겟을 탭 → score+1, 타겟이 즉시 새 무작위 위치로 점프 (즉시 피드백)
5. onFrame이 매 프레임 남은 시간 계산 → 타이머 카드가 10→0초로 카운트다운
6. 10초 경과 → score>bestScore면 bestScore 갱신 → result 스테이트로 전환
7. result 화면: ⚡ 배지, 최종 점수·최고기록 카드, 신기록/격려 메시지 노출
8. '다시하기' 탭 → 즉시 play로 재시작, 또는 '시작 화면으로' 탭 → ready로 복귀

## 성공 기준
- 점수·남은시간 StatCard 값이 탭/시간에 따라 실시간으로 변한다
- 타겟을 탭하는 순간 데드타임 없이 즉시 점수가 오르고 타겟이 점프한다 (snappy)
- 타겟이 항상 플레이 영역(둥근 카드) 내부에만 등장하고 화면 밖으로 잘리지 않는다
- 어떤 텍스트도 서로 겹치지 않고 각자 자리에 또렷이 읽힌다
- 결과 화면의 최종 점수·최고기록이 실제 플레이 결과와 일치한다
- 블랙+라임 톤이 일관되고 플레이 영역의 카드 프레임이 명확히 보인다

## QA 검증 시나리오
- [ ] **QA1** '시작' 버튼 탭 시 play 스테이트로 전환되고 타이머가 작동하는가 → `ready→play 전환, 남은 시간이 10초부터 1초씩 감소`
- [ ] **QA2** 타겟 탭 시 점수가 +1 되고 점수 카드 값이 갱신되는가 → `score 변수 증가, scoreCard.value가 '1점','2점'... 으로 변함`
- [ ] **QA3** 타겟 탭마다 타겟이 새 위치로 이동하는가 → `target.x/y가 무작위로 변경되어 위치가 매번 바뀜`
- [ ] **QA4** 10초 경과 시 result 스테이트로 자동 전환되는가 → `onFrame if $now-startedAt>=duration 충족 시 goToState result`
- [ ] **QA5** result의 최종 점수/최고기록이 플레이 점수와 일치하는가 → `finalScore=score, bestScoreCard=max(이전best,score)`
- [ ] **QA6** 모든 텍스트가 겹치지 않고 화면 안에 들어오는가 → `playHint와 playCaption이 분리되어 보임 — 현재 FAIL`
- [ ] **QA7** 타겟이 항상 플레이 영역 내부에 등장하고 잘리지 않는가 → `타겟이 카드 경계 안에 위치 — 현재 FAIL(우측/하단 잘림)`
- [ ] **QA8** 플레이 영역 카드(#16181c, stroke)가 화면에 보이는가 → `둥근 테두리 카드 프레임 표시 — 현재 FAIL(미표시)`
- [ ] **QA9** '다시하기'/'시작 화면으로' 버튼이 각각 동작하는가 → `retry→play 재시작, home→ready 복귀`

## 현재 깨짐 (진단)
- **[high]** 플레이 영역(playArea) 컨테이너가 절대좌표 자식을 담는 positioned box로 기능하지 못해, target의 x/y가 카드 기준이 아니라 화면 기준으로 해석된다. 그 결과 타겟이 플레이 영역 밖(우측 절반/하단)에 등장하고 화면 가장자리에서 잘린다.
  - 근거: shot 3에서 타겟이 화면 우측 끝(x≈600px대)·세로로 카드 영역보다 훨씬 아래(y≈900px)에 떠 있고 우측이 잘림. 문서 L254-311: playArea(height:470)에 layout 없이 자식 playHint(x:49,y:18)/target(x:147,y:210)을 절대좌표로 둠 → 카드 상대좌표가 안 먹음.
  - 수정: playArea를 절대좌표 자식의 기준 컨테이너로 명시(positioned/relative 보장)하고, target의 무작위 범위를 playArea 실제 폭/높이(약 358x405)에서 타겟 크기(64) 차감한 안전 범위로 clamp. 엔진이 자식 절대좌표를 부모 기준으로 처리하도록 playArea에 명시적 position 컨텍스트 부여.
- **[high]** playHint('타겟을 찾아 탭하세요')와 playCaption('정확히 누를수록 리듬이 살아나요')이 동일한 한 줄에서 정확히 겹쳐 둘 다 판독 불가.
  - 근거: shot 2·3 모두 두 회색 텍스트가 같은 y(약 600px)에 포개져 글자가 뭉개짐. 원인: playArea가 자식을 절대좌표로 흘려보내 flex 흐름상 0높이처럼 동작 → 다음 형제 playCaption(L312-320)이 hint 위로 올라붙음.
  - 수정: playArea collapse 해소(위 항목)로 hint가 카드 안에 갇히면 자연 해결. 추가로 playHint는 카드 내부 절대좌표, playCaption은 카드 아래 flex 흐름으로 분리 보장.
- **[medium]** 플레이 영역의 카드 프레임(#16181c 배경 + #2a2d33 stroke, cornerRadius 24)이 화면에 전혀 보이지 않아 '어디를 탭해야 하는지' 시각 경계가 사라짐.
  - 근거: shot 2·3에서 ready 화면의 readyHero 카드와 달리 play 화면 가운데에 둥근 테두리 카드가 없음. playArea가 레이아웃상 무너지면서 배경/테두리도 렌더 영역을 못 가짐.
  - 수정: playArea가 height:470의 가시 컨테이너로 정상 렌더되도록 레이아웃 수복(첫 항목과 동일 원인).

## 멀티 변형 아이디어 (별도 앱)
별도 멀티 버전으로 'live-race' 메커닉이 매우 잘 어울린다: 같은 방의 N명이 동시에 10초 카운트다운으로 각자 탭, 서버가 setVar로 모두의 실시간 점수를 라이브 리더보드(막대 경주)로 동기화. 종료 시 1위 강조. 단순 reflex가 '누가 더 빠른가'로 즉시 경쟁이 되어 폭발력이 크다. 지금 앱을 바꾸지 말고 game-tap-target-race로 분리 제작 권장.
