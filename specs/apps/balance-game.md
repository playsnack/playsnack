# 밸런스 게임 `balance-game`  ·  vote

**Verdict:** needs-fix  ·  **Mode:** multi (vote — 같은 방의 모두가 같은 딜레마에 투표하고 emitHostEvent('vote')로 서버에 합산, votesByOption이 setVar로 전원에게 동기화되어 LIVE RESULT 막대가 실시간 갱신된다. 카테고리=vote의 정석 메커닉이며, 이미 헤더 우상단에 참여 인원(1)이 표시된다.)

## 주제 매력도
밸런스 게임(딜레마 양자택일)은 한국에서 검증된 초강력 소셜 포맷이다 — "평생 하나만", "둘 중 하나 포기" 같은 질문은 카톡/인스타 스토리/유튜브에서 끝없이 소비되고, 답이 정해져 있지 않아 "남들은 뭐 골랐을까"라는 호기심이 핵심 동력이다. 현재 문항(자기 vs 놀기, 계획 vs 즉흥, 커피 vs 배달, 과거 vs 미래)은 무난하지만 평범하다. 더 끌리려면 "논쟁이 갈리는" 자극적/공감형 문항(연애·돈·인간관계·소름 딜레마, KR 밈 결합)을 섞어 50:50으로 팽팽하게 갈리는 질문 위주로 큐레이션하는 게 좋다. 50:50에 가까울수록 "헐 반반이네"의 재미가 폭발한다.

## 레퍼런스 (검증된 인기 포맷 모방)
- **모방 대상:** 밸런스 게임 / 딜레마 양자택일 (인스타 스토리 투표 스티커, 카톡 밸런스게임 포맷)
- **구조 100% 복제:** A vs B 양자택일 → 탭 즉시 내 선택 확정 → 실시간 양쪽 선택 비율(%) 막대로 공개 → 다음 문항으로 진행. 이 '선택→집계 공개→다음' 루프가 검증된 핵심 구조. 인스타 스토리 투표 스티커가 정확히 이 모델(탭하면 즉시 결과 %가 뜸).
- **우리 콘텐츠/디자인:** 우리가 채울 것: 4개 딜레마 문항/선택지 콘텐츠(KR 공감·논쟁형으로 고도화). 디자인은 블랙(#0b0c0e)+라임(#d9ff00) 톤, iOS 카드 레이아웃, ResultBar 라임 막대. 구조는 인스타 투표 스티커와 동일하되 콘텐츠와 비주얼은 우리 것.

## 목적
지루한 틈에 열어 "평생 하나만 가능하다면?" 같은 딜레마에 직감으로 한쪽을 탭하고, 같은 방에 들어온 사람들의 선택 비율이 실시간 막대로 합쳐지는 걸 보며 "나만 이래?" 혹은 "역시 다들 그렇구나"의 즉석 공감/반전을 얻는 휘발성 스낵. 4문항이면 30초 안에 끝나고 다시 처음으로 도는 가벼운 소비.

## 핵심 루프
A/B 두 선택지 중 하나를 탭 → 내 선택이 즉시 하이라이트되고 실시간 양쪽 비율이 막대로 공개 → '다음 딜레마'로 넘어가 반복.

## 시나리오
1. 사용자가 링크로 입장 → Q1 '평생 하나만 가능하다면?'과 A('매일 1시간 더 자기')/B('매일 1시간 더 놀기') 카드, 하단 LIVE RESULT(아직 선택 전, 0%/0%)가 보인다
2. A 카드를 탭 → myVote='q0A'로 설정되고 vote 이벤트가 서버로 전송, 결과 헤더가 'A를 골랐어요'로 바뀐다
3. 서버가 votesByOption을 합산해 전원에 동기화 → barA/barB의 %와 라임 막대가 실시간으로 차오른다(다른 참여자가 투표하면 비율이 즉시 움직임)
4. 마음을 바꿔 B를 탭하면 'B를 골랐어요'로 갱신(현재 재투표 시 중복 집계 가능성 — QA 확인 필요)
5. '다음 딜레마' 버튼 탭 → myVote 초기화 후 Q2로 전환, chip이 'QUESTION 2/4'로 바뀌고 새 문항/선택지가 로드된다
6. Q2~Q4를 같은 방식으로 진행, Q4의 버튼은 '처음으로'
7. '처음으로' 탭 → Q1(q0)로 되돌아가 루프 재시작

## 성공 기준
- A/B 카드 탭 시 선택한 쪽이 라임 색으로 즉시 하이라이트되어 '내가 뭘 골랐는지' 한눈에 보인다
- LIVE RESULT 막대가 실제 비율로 차오르고 양쪽 % 합이 100%가 된다
- ResultBar의 라벨이 'A'/'B'가 아니라 실제 선택지 문구(예: '매일 1시간 더 자기')로 표시되어 무엇에 투표했는지 자명하다
- 문항/선택지 텍스트가 카드 안에서 겹치거나 잘리지 않고 다 들어온다
- 4문항이 끊김 없이 진행되고 처음으로 되돌아 루프가 닫힌다
- 다른 참여자의 투표가 내 화면 막대에 실시간 반영된다

## QA 검증 시나리오
- [ ] **QA1** A 카드, B 카드, 다음 딜레마 버튼이 모두 탭에 반응하는가 → `A 탭→selectedText 'A를 골랐어요', B 탭→'B를 골랐어요', 버튼 탭→다음 문항 전환 (3 shot에서 selectedText A→B 변화로 클릭 자체는 동작 확인됨)`
- [ ] **QA2** 선택한 OptionCard가 시각적으로 하이라이트되는가 (accent) → `선택한 카드가 라임 테두리/배경으로 강조되어야 함 — 현재 FAIL: shot-2/3에서 A·B 어느 쪽을 골라도 두 카드 모두 동일한 다크 #16181c, 라임 강조 전혀 없음`
- [ ] **QA3** ResultBar 라벨이 실제 선택지 문구로 표시되는가 → `barA='매일 1시간 더 자기', barB='매일 1시간 더 놀기' — 현재 FAIL: 세 shot 모두 'A'/'B'만 표시(state binding barA.label이 instance propValue를 덮어쓰지 못함)`
- [ ] **QA4** 투표 후 막대/퍼센트가 변하고 합이 100%인가 → `최소 1표 이상이면 채워진 쪽 %>0, 양쪽 합=100%. 현재 1인 단독 shot이라 0% 자체는 비정상 아님 — 단, 내 표가 들어가면 100/0으로 보여야 하는데 shot-2(A 선택)에서도 0%/0% 유지 → 내 투표가 막대에 반영 안 됨 의심(서버 라운드트립/집계 검증 필요)`
- [ ] **QA5** 문항·선택지·설명 텍스트가 겹치거나 잘리지 않고 화면 안에 들어오는가 → `PASS — 모든 shot에서 제목/설명/카드 라벨이 깔끔히 들어오고 겹침 없음`
- [ ] **QA6** 4문항이 순서대로 전환되고 q3→q0로 루프가 닫히는가 → `chip이 1/4→4/4로 진행, 마지막 버튼 '처음으로'가 q0로 복귀`
- [ ] **QA7** 재투표(A→B 변경) 시 서버 집계가 중복되지 않는가 → `같은 라운드에서 A→B로 바꾸면 A 표가 차감되고 B가 +1 (또는 1인 1표 보장). 현재 트리거는 매 탭마다 vote를 emit하므로 중복 집계 가능 — 서버 핸들러 검증 필요`
- [ ] **QA8** 콘텐츠가 진짜 양자택일로 성립하는가 (이미지 없음, 텍스트 딜레마) → `PASS — 4문항 모두 A vs B가 명확히 대립, 정답 없는 취향 문항으로 카테고리에 적합`

## 현재 깨짐 (진단)
- **[high]** 선택한 OptionCard에 시각적 하이라이트가 전혀 없다. bindings에서 optionA.accent/optionB.accent를 myVote로 계산하지만, OptionCard componentDef의 layers(루트 container)가 $props.accent를 어디에도 사용하지 않음 — 색/테두리에 accent 조건 바인딩이 없어 prop이 죽은 값이다.
  - 근거: balance-game.bite.json:285-286 optionA.accent 바인딩 존재 vs 689-723 OptionCard layers에 $props.accent 미사용. shot-2(A 선택)·shot-3(B 선택)에서 두 카드 모두 동일한 다크 #16181c, 라임 강조 0. 유일한 피드백은 결과 헤더의 작은 'A를 골랐어요' 텍스트뿐 — 양자택일 앱의 핵심 만족감(내 선택 강조)이 사라짐.
  - 수정: OptionCard 루트의 color와 stroke를 accent에 바인딩: color는 accent면 라임틴트/스트로크 #d9ff00·strokeWidth 2, 아니면 기본. 컴포넌트가 prop 조건부 스타일을 지원하지 않으면 인스턴스 레벨에서 optionA.stroke/optionA.color를 state binding으로 직접 토글.
- **[high]** ResultBar 라벨이 실제 선택지 문구 대신 'A'/'B'로만 표시된다. state binding이 instance propValue를 덮어쓰지 못하고 있다.
  - 근거: balance-game.bite.json:288-289 barA.label='매일 1시간 더 자기' / barB.label='매일 1시간 더 놀기' 바인딩 존재. 그러나 인스턴스 propValues(225,236)는 label 미지정이라 ResultBar default가 아니라… shot 3장 전부 막대 위 라벨이 'A'/'B'로 고정. selectedText 등 다른 state binding은 적용되는데 컴포넌트 인스턴스의 prop 바인딩(barA.label)이 반영 안 됨 → 무엇에 투표했는지 결과창만 봐선 알 수 없다.
  - 수정: 컴포넌트 인스턴스 prop 바인딩 경로(barA.label)가 런타임에서 propValue를 갱신하도록 확인/수정. 안 되면 propValues에 직접 옵션 텍스트를 넣고 라운드마다 goToState로 라벨 동기화.
- **[medium]** 내 표가 LIVE RESULT 막대에 즉시 반영되지 않는다(낙관적 갱신 부재). 1인 단독 세션에서 A를 골라도 0%/0% 유지.
  - 근거: shot-2: A 선택 후에도 barA=0% barB=0%, 막대 빈 채. snappy(즉시 피드백) 원칙상 내 탭 직후 적어도 내 쪽이 차오르거나 100%로 보여야 함. 현재는 서버 vote 라운드트립에만 의존해 데드타임 발생 가능.
  - 수정: votesByOption을 setVar로 로컬에서도 즉시 +1 한 뒤 서버 동기화로 정정, 또는 emitHostEvent 응답이 빠르게 돌아오는지 확인. 최소한 내 선택 막대는 탭 즉시 시각 반응.
- **[medium]** 라운드 내 재투표 시 중복 집계 위험. 매 OptionCard 탭마다 무조건 emitHostEvent('vote')를 발사.
  - 근거: balance-game.bite.json:296-336 optionA/optionB 트리거가 클릭마다 vote를 emit, A→B 변경 시 차감 로직이 클라이언트에 없음. shot-2(A)→shot-3(B) 전환이 가능하므로 같은 사람이 양쪽 다 표를 넣을 수 있음.
  - 수정: 서버 vote 핸들러에서 (방·유저·라운드) 단위 1표 보장 + 변경 시 이전 표 차감. 또는 myVote가 이미 같은 라운드 값이면 재emit 억제.
