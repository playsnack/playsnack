# 우리 중 누가? `who-most-likely`  ·  vote

**Verdict:** needs-fix  ·  **Mode:** multi (vote (라이브 타일리: 탭=내 표, 서버가 votesByOption 합산을 전체에 setVar 동기화해 막대·% 실시간 공유. vote 카테고리 유일 검증 컨트랙트 emitHostEvent→onHostEvent→setVar 사용))

## 주제 매력도
"우리 중 누가 ~할 사람?"은 한국 친구/회식/MT 자리에서 검증된 초인기 술자리·밸런스 포맷이다. 지목당하면 웃기고, 결과가 사람을 향하므로 즉시 대화가 터진다. 현재 문항(갑자기 여행 가자며 10분 뒤 항공권 찾아올 사람)은 캐릭터가 살아있어 좋다. 더 끌어올리려면 동적 콘텐츠로 'MBTI 빌런/단톡방 읽씹왕/탕비실 간식 도둑/회식 끝까지 남을 사람' 같은 공감·폭로형 문항 풀을 정시마다 교체하면 재방문 동기가 커진다.

## 레퍼런스 (검증된 인기 포맷 모방)
- **모방 대상:** 이상형 월드컵·인스타 스토리 투표 스티커(특히 'Most Likely To' 파티 게임)
- **구조 100% 복제:** 검증된 라이브 투표 포맷 구조 100% 모방: ① 하나의 질문 + ② 4개 후보를 세로 리스트로 ③ 후보를 탭하면 즉시 내 표 반영(선택 하이라이트) + ④ 막대그래프가 실시간으로 채워지고 % 갱신 + ⑤ 재탭으로 표 변경. 'Most Likely To' 파티게임의 '한 명을 지목한다' 룰과 인스타 투표 스티커의 '탭=즉시 집계+막대' UX를 그대로 가져옴.
- **우리 콘텐츠/디자인:** 콘텐츠는 우리 것: 한국 친구 그룹을 겨냥한 캐릭터형 질문/후보(이름+이모지). 디자인은 블랙(#0b0c0e)+라임(#d9ff00) 톤, 선택 시 행 전체가 라임으로 점등, 막대는 라임 계열로 채워짐. 인물 사진 대신 이름+이모지 칩으로 가벼운 스낵 톤 유지.

## 목적
친구/단톡방에서 "우리 중에 OO할 사람 한 명만 찍어" 라는 지목 놀이를 30초 안에 끝내는 휘발성 투표 스낵. 누가 1등으로 지목됐는지 막대가 실시간으로 갈리는 걸 보며 깔깔 웃고, 결과를 캡처해 단톡방에 던지는 재미를 준다.

## 핵심 루프
후보 한 명을 탭 → 그 행이 라임으로 점등되고 막대·퍼센트가 실시간 갱신(다른 사람 표도 합산) → 마음 바뀌면 다른 후보 재탭으로 즉시 변경.

## 시나리오
1. 사용자가 링크로 진입 → 질문('갑자기 여행 가자며 10분 뒤 항공권까지 찾아올 사람은?')과 4명의 후보 리스트, 우상단 접속 인원(👥1)이 즉시 보인다(idle 상태, 데드타임 0).
2. 민지/준호/서하/태윤 중 한 명(예: 준호) 행을 탭한다.
3. 앱이 myVote='o1' 설정 + vote 호스트 이벤트 emit → 준호 행이 라임으로 점등되고 라벨 색이 반전된다.
4. 서버가 votesByOption 합산을 전체에 setVar 동기화 → 모든 후보의 막대 width와 % 텍스트가 실시간으로 다시 계산되어 채워진다.
5. 사용자가 마음을 바꿔 민지 행을 재탭한다 → 준호 점등 해제, 민지 점등, 집계가 즉시 다시 갈린다(되돌릴 수 있는 가벼움).
6. 다른 참가자가 들어와 투표하면 % 막대가 실시간으로 출렁이며 1등이 바뀌는 걸 함께 지켜본다.
7. 결과 화면을 캡처해 단톡방에 공유하고 끝낸다(별도 결과 단계 없이 그 자체가 결과).

## 성공 기준
- 질문·후보가 한 화면에 다 들어오고 스크롤 없이 즉시 읽힌다(390:844 안에 4행+헤더).
- 탭 즉시(0 지연) 선택 행이 라임으로 점등되어 '내 표'가 명확히 보인다.
- 막대 width와 % 텍스트가 votesByOption 합산에 비례해 정확히 갱신된다(합 100% 근사).
- 여러 명이 동시에 투표할 때 막대가 실시간으로 함께 움직인다(multi 라이브 타일리의 핵심).
- 후보 라벨·퍼센트가 어떤 진행 상태에서도 겹치거나 잘리지 않고 읽힌다.
- 후보가 실제 사람 이름처럼 캐릭터가 살아있어(이모지 매칭) 지목 재미가 있다.

## QA 검증 시나리오
- [ ] **QA1** opt0~opt3 각 행을 탭하면 myVote가 해당 옵션으로 바뀌고 그 행만 라임 점등되는가 (모든 컨트롤 응답) → `탭한 행만 bar.color=#d9ff00 + label.color 반전, 나머지는 원래 색 유지`
- [ ] **QA2** vote emit 후 votesByOption 합산이 전체 참가자에게 setVar 동기화되어 막대·%가 변하는가 → `막대 width와 pct 텍스트가 새 집계에 맞춰 즉시 재계산됨`
- [ ] **QA3** 막대 width 식 Math.max(6, round(share*358))과 % 식이 같은 분모를 쓰는가 → `막대 길이와 표시 %가 서로 일치(예: 82%면 막대도 ~82% 길이)`
- [ ] **QA4** 선택 행(라임 막대가 길게 찬 상태)에서 후보 라벨과 우측 % 텍스트가 잘리거나 막대에 가려지지 않는가 → `라벨·% 모두 끝까지 읽힘, 클리핑 없음`
- [ ] **QA5** 재탭으로 표 변경 시 이전 선택 점등이 해제되는가 → `한 번에 한 행만 점등(단일 지목 룰)`
- [ ] **QA6** vote 카테고리 특유: 우상단 접속 인원이 실제 참가자 수를 반영하고 라이브 집계가 0표일 때도 깨지지 않는가(분모 Math.max(1,...)) → `0표 시 전부 0%, 인원수 정확 표시, NaN/division 에러 없음`

## 현재 깨짐 (진단)
- **[high]** 선택 행에서 막대가 길게 차면 우측 % 텍스트가 막대에 가려지거나 잘림. shot 3에서 준호 행이 라임으로 풀로 채워지자 우측 퍼센트가 '%'만 남고 숫자가 클리핑됨(컨테이너 clip:true + 막대 width가 358까지 자라 pct3(x230,w110) 위를 덮음).
  - 근거: shot 3: 준호 행 라임 막대가 거의 끝까지 차고 오른쪽 퍼센트가 '%'로 잘려 숫자 안 보임. shot 2: 준호 82% 막대가 퍼센트 칩 뒤까지 침범.
  - 수정: 막대 max width를 358 대신 퍼센트 영역을 비우도록 ~250으로 제한하거나, pct 텍스트를 막대 위 z-order 최상단으로 올리고 막대 fill을 라벨/퍼센트 영역과 겹치지 않게 트랙 안쪽(예: x0~232)으로 한정. 또는 선택 행에서 % 텍스트 색을 막대 대비 가독 색(#0b0c0e)으로 강제.
- **[medium]** 선택 행 점등 시 % 텍스트 색 대비 문제: 라임 막대(#d9ff00) 위에 라임색 퍼센트(#d9ff00)가 올라가면 거의 안 보임.
  - 근거: shot 3 준호 행: 막대가 라임으로 차면서 같은 라임색 % 텍스트가 배경과 동화. label.color는 반전 바인딩이 있으나 pct.color는 반전 바인딩이 없음(구조상 pct0~3.color 바인딩 부재, line 282/286/290/294는 content만 갱신).
  - 수정: pct0~3.color에도 myVote 기반 반전 바인딩 추가(선택 시 #0b0c0e).
- **[low]** 막대가 행 전체 height(62) + cornerRadius(14)로 그려져 선택 시 행 전체가 단색 라임 블록처럼 보임 — 막대그래프가 아니라 단순 하이라이트로 읽힐 수 있어 '집계 비율' 정보가 약화됨.
  - 근거: shot 2 준호 82%: 막대가 행 높이 전체를 채워 진행 막대인지 선택 배경인지 모호. 선택+긴 막대가 겹칠 때 비율감 저하.
  - 수정: 선택 하이라이트(테두리/얇은 글로우)와 집계 막대(채움)를 시각적으로 분리하거나, 막대를 행 하단의 얇은 트랙으로 두어 % 정보가 별개로 읽히게.
