# 메뉴 정하기 룰렛 `wheel-menu`  ·  random

**Verdict:** broken  ·  **Mode:** single

## 주제 매력도
"오늘 뭐 먹지?"는 한국인 일상 최강 결정장애 주제다 — 점심·야식·회식 메뉴 고르기는 매일 반복되는 보편적 고민이고, 친구/동료와 "그냥 룰렛 돌려"는 검증된 밈이다. 메뉴 룰렛 앱은 카톡/인스타에서 꾸준히 바이럴되는 포맷이라 주제 매력은 충분. 다만 현재 후보가 김치찌개·초밥·파스타 등 8개 고정이라 살짝 평범 — '점심 vs 야식 vs 해장' 같은 상황 탭이나 KR 트렌드 메뉴(마라탕후루·요아정·탕후루 같은 신조어)를 섞으면 공유 욕구가 더 커진다.

## 레퍼런스 (검증된 인기 포맷 모방)
- **모방 대상:** 메뉴 결정 룰렛 / Spin the Wheel (wheelofnames 식 픽커)
- **구조 100% 복제:** 검증된 룰렛/픽커 룰을 100% 모방: 후보 리스트 → 단일 트리거(탭/버튼)로 랜덤 1개 선택 → 큰 결과 표시 → 즉시 재시도(다시 돌리기). 데드타임 0, 1탭 1결과의 즉석 소비 루프.
- **우리 콘텐츠/디자인:** 콘텐츠는 KR 식문화 메뉴(한식/분식/양식/마라탕 등 + 신조어 메뉴)로 우리가 채우고, 비주얼은 블랙(#0b0c0e)+라임(#d9ff00) 톤. 룰렛 휠 그래픽·결과 카드·통계 카드는 우리 디자인 시스템(NavBar/Button/StatCard/Chip 컴포넌트)으로 구현.

## 목적
메뉴 못 정할 때 1초만에 열어 탭 한 번으로 "오늘은 이거 먹어"를 정해주는 즉석 결정장애 해결 스낵. 고민을 룰렛에 떠넘기는 가벼운 재미 + 결과가 마음에 안 들면 바로 다시 돌리는 중독성이 핵심.

## 핵심 루프
큰 룰렛(또는 돌리기 버튼)을 탭하면 후보 메뉴 중 하나가 랜덤으로 뽑혀 크게 표시되고, 마음에 안 들면 바로 다시 탭해 재추첨한다.

## 시나리오
1. 앱을 열면 블랙 배경에 큰 원형 룰렛(라임 글로우)과 '탭해서 뽑기' 안내, 하단에 '룰렛 돌리기' 버튼이 보인다
2. 사용자가 '룰렛 돌리기' 버튼 또는 룰렛 원을 탭한다
3. 앱이 menus 배열에서 랜덤으로 하나(예: 마라탕)를 골라 selected에 넣고, 룰렛 중앙에 결과 메뉴명을 크게 표시한다
4. 동시에 pickedCount가 +1 되어 '뽑은 횟수' 통계 카드가 1회로 갱신되고, 글로우 색이 라임→연노랑으로 바뀌며 '뽑힘' 상태를 알린다
5. 버튼 라벨이 '룰렛 돌리기'→'다시 뽑기'로 바뀐다
6. 결과가 마음에 안 들면 다시 탭 → 새 메뉴가 즉시 다시 표시되고 횟수가 또 +1 된다
7. 상단 카테고리 칩(한식/분식/양식/랜덤)으로 후보군을 좁혀 다시 돌릴 수 있다(현재 미구현)

## 성공 기준
- 탭→결과까지 체감 지연 0, 1탭 1메뉴가 즉시 큰 글자로 표시된다
- 결과 메뉴명이 룰렛 중앙에 또렷하게(충분한 대비로) 읽힌다 — 어두운 카드 위 어두운 글자 금지
- '뽑은 횟수' 통계가 탭할 때마다 실제로 0→1→2…로 증가해 진행감을 준다
- 룰렛 글로우/원/이모지/결과텍스트가 원형 컨테이너 안에 정렬되고 NavBar·다른 영역을 침범하지 않는다
- 후보 메뉴가 실제로 먹을 만한 KR 메뉴이고, '후보 8개' 같은 통계가 실제 배열 길이와 일치한다
- 마음에 안 들 때 재시도가 직관적(버튼 라벨이 '다시 뽑기'로 명확히 안내)

## QA 검증 시나리오
- [ ] **QA1** '룰렛 돌리기' 버튼 탭 → selected가 menus 중 하나로 바뀌고 룰렛 중앙 텍스트가 갱신되는가 → `매 탭마다 결과 메뉴명이 바뀜(idle 트리거 pickBtn/rouletteWrap click → setVar selected)`
- [ ] **QA2** 탭할 때마다 '뽑은 횟수' StatCard 값이 0회→1회→2회로 증가하는가 → `pickedCount 증가가 pickedStat.value 바인딩을 통해 화면에 반영(현재 FAIL — 0회 고정)`
- [ ] **QA3** 버튼 라벨이 1회 뽑은 뒤 '룰렛 돌리기'→'다시 뽑기'로 바뀌는가 → `pickBtn.label 바인딩 동작(pickedCount===0 ? ...). 횟수 미갱신 시 라벨도 안 바뀜 — 동반 검증`
- [ ] **QA4** 룰렛 글로우 원이 원형 wrap(250px) 안에 들어오고 화면 위로 넘치지 않는가 → `글로우는 결과 텍스트 뒤 배경. 현재 FAIL — 글로우가 카드 밖 NavBar까지 침범`
- [ ] **QA5** 결과 메뉴명(예:마라탕)이 충분한 대비로 읽히는가 → `라임/연노랑 글로우 위 검정(#0b0c0e) 텍스트가 또렷. 현재 FAIL — 글로우가 떠올라 텍스트가 어두운 카드 위 검정으로 거의 안 보임`
- [ ] **QA6** '후보 메뉴' 값(8개)이 menus 배열 길이(8)와 일치하는가 → `일치(현재 PASS, 단 하드코딩 '8개'라 menus 변경 시 깨질 위험)`
- [ ] **QA7** 카테고리 칩(한식/분식/양식/랜덤) 탭 시 후보군이 필터링되는가 → `칩 선택→해당 카테고리 메뉴만 후보. 현재 트리거 없음(장식용) — 명세상 인터랙티브여야 하면 FAIL`

## 현재 깨짐 (진단)
- **[high]** 룰렛 글로우 원(rouletteGlow, 188px)이 원형 wrap(250px) 밖으로 위쪽으로 폭발해 heroCard 상단을 뚫고 NavBar '고민은 룰렛에게 맡겨요' 자막까지 덮는다. 글로우는 결과 텍스트 뒤 배경이어야 하는데, flex 컬럼 자식으로 들어가 위로 밀려나 레이아웃이 붕괴됨.
  - 근거: wheel-menu-1~3 모두: 라임/연노랑 거대 원이 카드 상단 경계를 넘어 헤더 영역까지 올라와 있고, 그 아래에 이모지·결과텍스트가 따로 떨어져 배치됨
  - 수정: rouletteGlow를 flex 자식이 아니라 rouletteWrap 안의 절대배치 배경 레이어로(혹은 position 무시되는 엔진이면 emoji/selectedText를 글로우 위에 z-순서로 겹치게) 재구성. 글로우를 wrap과 같은 중심에 두고 width/height를 wrap보다 작게 고정, layout 흐름에서 제외(pointerEvents none + 중앙 absolute). 메모리의 'absolute 자식이 flex 부모에 들어가 뭉침/터짐' 패턴과 일치.
- **[high]** 결과 메뉴명(selectedText)과 이모지가 color #0b0c0e(거의 검정)인데, 글로우가 위로 떠버려 어두운 카드(#1e2127) 위 검정 글자로 렌더 → 마라탕/햄버거가 거의 안 보임(저대비).
  - 근거: wheel-menu-2 '마라탕', wheel-menu-3 '햄버거'가 어두운 원형 배경 위 검정으로 흐릿하게만 보임. 글로우와 분리된 결과
  - 수정: 글로우 겹침 버그(위 항목) 수정으로 텍스트가 밝은 글로우 위에 오게 하거나, selectedText 색을 라임(#d9ff00)/흰색으로 바꿔 배경과 무관하게 가독 보장.
- **[high]** '뽑은 횟수' StatCard가 탭을 여러 번 했는데도 '0회'에 고정(pickedCount 증가가 화면에 반영 안 됨). 진행감·피드백이 죽음.
  - 근거: wheel-menu-2/3에서 결과는 마라탕/햄버거로 바뀌었으나(=setVar/추첨은 동작) '뽑은 횟수'는 여전히 0회. 즉 selected 바인딩은 살아있는데 pickedStat.value 컴포넌트-인스턴스 prop 바인딩이 내부 val 텍스트로 전파되지 않음
  - 수정: StatCard 내부 val.content 바인딩을 인스턴스 propValue가 아니라 state 레벨에서 직접 nested 레이어(pickedStat.val.content 또는 그에 해당하는 경로)로 바인딩하거나, 컴포넌트 prop 재전파가 되는 형태로 수정. 메모리 '레거시 엔진 bindings must be state-level / validate 통과해도 런타임 무음 실패'와 정확히 일치.
- **[medium]** 카테고리 칩(한식/분식/양식/랜덤)이 트리거 없는 순수 장식 — 탭해도 후보군이 안 바뀜. 사용자는 누를 수 있을 것처럼 보이는데 무반응.
  - 근거: 레거시 엔진 idle.triggers에 chip1~4 click 핸들러 없음(pickBtn/rouletteWrap만 존재). 칩은 인터랙티브해 보이는 pill UI라 오해 유발
  - 수정: 각 칩에 click 트리거 추가해 menus를 카테고리별 부분집합으로 setVar(예: 한식→[김치찌개,제육덮밥...]) 후 '후보 메뉴' 카운트도 갱신. 또는 명세상 비인터랙티브면 칩을 정적 라벨로 톤다운(테두리/색 약화)해 '못 누르는 것'임을 시각적으로 명확히.

## 멀티 변형 아이디어 (별도 앱)
멀티 버전이 매우 재밌을 주제다. 메커닉: live-race/vote 혼합 — 같은 방의 여러 명이 각자 '먹고 싶은 메뉴'를 후보에 던져넣고(co-op tally), 모두 모이면 호스트가 룰렛을 돌려 한 명의 메뉴가 당첨되는 '회식 메뉴 룰렛'. 고도화: 당첨 확률을 '안 걸린 사람 가중'으로 조정(공정 룰렛), 결과에 '오늘 쏘는 사람' 룰렛까지 이어붙이면 회식 밈으로 바이럴.
