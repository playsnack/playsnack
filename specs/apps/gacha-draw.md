# 뽑기 가챠 `gacha-draw`  ·  random

**Verdict:** needs-fix  ·  **Mode:** single

## 주제 매력도
가챠/뽑기는 KR에서 검증된 강력한 도파민 포맷이다(게임 확률 뽑기, 랜덤박스, 운세 뽑기). "한 번 더"의 중독성이 휘발성 스낵과 완벽히 맞는다. 다만 현재 "별빛 가챠"의 노멀/레어/에픽/전설 등급은 추상적이라 결과를 받아도 "그래서 뭐?"가 된다. 더 매력적인 주제로 바꾸면 좋다: 오늘의 운세 가챠("대박/평범/조심"), 점심 메뉴 가챠, MBTI 캐릭터 가챠, K-아이돌 최애 뽑기처럼 결과 자체가 의미·공유거리가 되는 콘텐츠. 등급만 뽑는 지금은 결과가 비어있다.

## 레퍼런스 (검증된 인기 포맷 모방)
- **모방 대상:** 모바일 게임 가챠/확률 뽑기 (원신·페그오식 캡슐 가챠)
- **구조 100% 복제:** 100% 모방: (1) 명시된 가중 확률표(노멀65/레어25/에픽8/전설2)를 화면에 공개, (2) 단발 뽑기 버튼 1개, (3) 뽑기→캡슐 오픈 연출→등급 공개→희귀도별 차등 비주얼(색/이펙트/임팩트), (4) 누적 횟수 카운트, (5) 즉시 '한 번 더' 재시도 루프. 이 진행 흐름과 룰은 그대로 가져간다.
- **우리 콘텐츠/디자인:** 콘텐츠는 추상 등급 대신 의미있는 결과로 교체(예: 오늘의 운세 가챠 — 전설='인생 대박의 날', 에픽='행운이 따른다' 등 결과 카피와 한 줄 풀이). 디자인은 블랙(#0b0c0e)+라임(#d9ff00) 톤 유지, 희귀도별 색(전설=라임, 에픽=보라, 레어=블루, 노멀=그레이)으로 차등 강조.

## 목적
버튼 하나로 가중 확률 뽑기를 돌려 노멀/레어/에픽/전설 중 무엇이 나오는지 즉석에서 확인하는 운빨 스낵. 잠깐의 두근거림과 '전설 떴다'의 짜릿함, 그리고 '한 번 더'의 반복 도파민을 준다.

## 핵심 루프
뽑기 버튼 탭 → 가중 랜덤으로 등급 공개(색·이모지·카피 변화) → 누적 횟수 +1 → 다시 뽑기.

## 시나리오
1. 사용자가 앱을 연다 → 상단 '별빛 가챠' 타이틀, 통계 카드(뽑은 횟수 0회 / 현재 결과 대기), 중앙 캡슐 스테이지(빈 오브+✨+소환 준비), 확률칩 4종, 하단 '첫 뽑기' 버튼이 보인다.
2. 사용자가 '뽑기' 버튼을 탭한다 → roll=Math.random() 계산, 가중표로 rarity 결정, drawCount+1.
3. 앱이 결과를 공개한다 → 오브 색·이모지·등급 텍스트·풀이 카피가 등급에 맞게 변한다(예: 노멀이면 🪙 회색 오브 '작은 행운의 코인').
4. 통계 카드가 갱신된다 → 뽑은 횟수 '1회', 현재 결과 '노멀'로 바뀐다.
5. 사용자가 결과를 보고 다시 버튼('다시 뽑기')을 탭한다 → 새 등급이 공개되고 카운트가 누적된다.
6. 전설(2%)이 떴을 때 → 오브가 라임으로 빛나고 👑 '별빛 왕관' 카피와 함께 강한 임팩트 연출이 나온다.
7. 사용자는 만족할 때까지 반복 탭하거나 앱을 닫는다(휘발성 소비).

## 성공 기준
- 뽑기 한 번에 결과가 즉시(데드타임 0) 공개되고 등급별로 색·이모지·카피가 분명히 다르다.
- 뽑은 횟수와 현재 결과 통계 카드가 매 뽑기마다 실제로 갱신된다.
- 확률표(65/25/8/2)가 실제 가중 랜덤 동작과 일치한다(콘텐츠 진실성).
- 모든 텍스트가 겹치지 않고 화면 안에 들어온다(하단 힌트 잘림 없음).
- 등급 이모지가 의도한 글리프(🪙⭐💎👑)로 렌더된다 — 엉뚱한 스톡 사진이 아니다.
- 결과 카피가 결과 자체로 공유·자랑할 만한 의미를 가진다.

## 현재 깨짐 (진단)
- **[high]** 통계 카드가 뽑기 후에도 갱신되지 않음. shot 2에서 등급 텍스트는 '노멀', 풀이는 '작은 행운의 코인이 반짝입니다'로 바뀌었는데 '뽑은 횟수'는 여전히 '0회', '현재 결과'는 여전히 '대기'다. idle state 바인딩(gacha-draw.bite.json:305-306)이 countStat.value/rateStat.value를 가리키지만, StatCard 인스턴스가 propValues로 리터럴('0회'/'대기')을 받고(line 88,103) 내부 val 텍스트 layer로 바인딩이 재전파되지 않음. 직접 text layer 바인딩(rarityText.content line 311, flavorText.content line 313)은 동작하는 반면 component propValues 경로는 동작 안 하는 레거시 엔진 알려진 함정. 핵심 진행 표시가 거짓 정보를 보여주는 치명 결함.
  - 근거: shot 2: 결과 패널은 '노멀'로 갱신됐으나 통계 카드 '0회'/'대기' 그대로. shot 2와 shot 3 파일이 바이트 단위 동일(148198) — 갱신이 멈춤.
  - 수정: StatCard 내부 val text layer를 직접 바인딩 타깃으로 노출하거나(예: countStat.children.val.content 같은 도달 가능한 경로), StatCard 대신 stage처럼 직접 text layer + state binding 구조로 통계를 다시 짠다. component propValues에 의존한 state binding을 제거하고 검증된 직접-layer 바인딩 패턴 사용.
- **[high]** 등급 이모지가 emoji 글리프 대신 엉뚱한 스톡 사진으로 렌더됨. emoji text layer content '🪙'(line 310 분기)가 shot 2에서 'THE CRAZY ONE 2020' 글자가 새겨진 실제 은화 스톡 사진으로 표시됨. 이미지-치환 파이프라인이 emoji 텍스트를 이미지 검색 쿼리로 오인. 콘텐츠 진실성/디자인 톤 붕괴.
  - 근거: shot 2 중앙: ✨ 이모지 자리에 사진풍 은화 이미지가 박혀 있음. shot 1(대기, ✨)은 정상 글리프인데 결과 등급 이모지만 사진화됨.
  - 수정: emoji/이모지성 text layer는 이미지-치환 대상에서 제외(이모지 유니코드만 있는 content는 그대로 텍스트 렌더). 또는 등급 비주얼을 사진이 아닌 색상 오브+이모지 글리프로만 구성하도록 파이프라인 가드 추가.
- **[medium]** orb 원(128px)이 glowPanel 상단 경계 밖으로 밀려 패널 위 모서리와 겹침. glowPanel이 column center 정렬인데 orb+emoji+rarityText+flavorText 콘텐츠 합이 패널 높이(294)를 초과해 오브 상단이 패널 밖으로 잘려 보임.
  - 근거: shot 1·2: 회색 오브 상단이 glowPanel 둥근 모서리 위로 튀어나와 패널 테두리와 겹쳐 보임.
  - 수정: glowPanel height 294를 hug로 바꾸거나 콘텐츠 gap/패딩 축소, 또는 orb 크기를 줄여 패널 내부에 안전하게 수용.
