# 야식 월드컵 `worldcup-food`  ·  worldcup

**Verdict:** needs-fix  ·  **Mode:** single

## 주제 매력도
야식(치킨/피자/족발/보쌈/떡볶이/라면…)은 한국인이 밤마다 실제로 고민하는 보편적·즉각공감 주제다. "오늘 뭐 먹지"를 토너먼트로 풀어주니 진입장벽 0이고, 결과를 캡처해 공유하기 좋다. 주제 자체는 매우 강하므로 바꿀 필요 없음 — 다만 후보를 매번 신선하게(야식 신조어/배달앱 인기메뉴) 채우면 재방문 가치가 올라간다.

## 레퍼런스 (검증된 인기 포맷 모방)
- **모방 대상:** 이상형 월드컵 (피쿠/이상형월드컵 바이럴 포맷)
- **구조 100% 복제:** 16강→8강→4강→결승 싱글 엘리미네이션 토너먼트. 매 라운드 두 후보를 위/아래(또는 좌/우)로 보여주고 하나를 탭하면 승자가 다음 라운드로, 패자는 탈락. 라운드 라벨(16강 N번째 대결)로 진행 표시. 결승 승자는 '오늘의 1위' 결과 화면 + 다시하기. 이 진행 흐름·룰을 100% 그대로 따른다.
- **우리 콘텐츠/디자인:** 콘텐츠=야식 메뉴 16종(치킨/피자/족발/보쌈/떡볶이/라면/곱창/마라탕 등 실존·인지도 높은 대상)을 LLM이 신선하게 채우고 각 후보는 실제 그 음식 사진(/api/img, Wikipedia 우선)을 매칭. 디자인=블랙(#0b0c0e) 배경 + 라임(#d9ff00) VS/CTA, 큰 사진 카드 + 하단 그라데이션 위 굵은 흰 이름 라벨.

## 목적
밤에 "야식 뭐 먹지"를 고민할 때 열어, 둘 중 하나를 본능적으로 탭하는 30초~1분짜리 토너먼트로 오늘의 야식 1위를 정하는 휘발성 스낵. 고르는 재미 + 내 취향 확인 + 결과 캡처/공유의 작은 쾌감을 준다.

## 핵심 루프
두 야식 사진 중 더 끌리는 쪽을 탭 → 승자가 다음 대결로 넘어가고 라운드가 좁혀지며 → 결승 우승자가 '오늘의 1위'로 발표된다.

## 시나리오
1. 사용자가 앱을 연다 → 16강 1번째 대결, 위 카드 사진+이름(치킨)과 아래 카드(피자)가 즉시 보인다.
2. 사용자가 위 카드(치킨)를 탭한다 → 치킨이 승자로 기록되고 16강 2번째 대결의 새 두 후보가 나타난다.
3. 사용자가 8개 대결을 거쳐 16강을 끝낸다 → 라벨이 8강 1번째 대결로 바뀌고 승자들끼리 다시 붙는다.
4. 8강→4강→결승까지 매번 한 쪽을 탭하며 좁혀간다 → 라운드 라벨이 16강→8강→4강→결승으로 갱신된다.
5. 결승에서 한 쪽을 탭한다 → result 상태로 전환, '🏆 최종 우승' + 우승 야식 큰 사진 + 이름 + 한 줄 카피가 뜬다.
6. 사용자가 결과를 캡처/공유하거나 '다시하기' 버튼을 탭한다 → 시드가 초기화되어 16강 1번째 대결부터 다시 시작된다.

## 성공 기준
- 매 대결의 위/아래 사진이 그 후보 이름과 실제로 일치한다(치킨=치킨 사진, 떡볶이=떡볶이 사진).
- 후보가 바뀔 때마다 사진과 이름이 함께 즉시 갱신된다(데드타임 0, 캐시된 옛 사진이 남지 않음).
- 라운드 라벨(16강/8강/4강/결승 · N번째 대결)이 진행에 맞게 정확히 변한다.
- 이름 라벨이 사진 하단 그라데이션 위에서 안 겹치고 한 줄로 또렷이 읽힌다.
- 결승 후 우승자 화면이 우승 후보의 사진/이름을 정확히 보여주고 다시하기가 동작한다.
- 후보 16종이 실존하고 인지도 높은 야식으로, 매번 신선하게 채워진다.

## 현재 깨짐 (진단)
- **[high]** 라운드/이름은 진행되는데 후보 사진이 첫 후보에서 절대 바뀌지 않음 — 모든 대결에서 위 카드는 동일한 프라이드치킨 사진, 아래 카드는 동일한 피자 사진. 이름만 떡볶이/라면/족발/보쌈으로 바뀌어 사진과 이름이 완전히 불일치한다.
  - 근거: shot-1(16강 1번째)=치킨/피자 사진. shot-2(2번째)=라벨/이름은 떡볶이·라면으로 바뀌었으나 사진은 여전히 동일 치킨·피자. shot-3(3번째)=족발·보쌈 이름인데 사진은 또 같은 치킨·피자. topImg.imageUrl 바인딩은 current[matchIndex*2].q로 후보마다 다른 URL을 만들지만(server /api/img는 q별로 구분된 이미지를 반환, index.mjs:165-193) 화면 텍스처는 첫 로드값에 고정됨.
  - 수정: image 레이어의 imageUrl 바인딩이 런타임에 변할 때 Pixi 텍스처를 재로드하도록 렌더러 image 핸들러를 수정(이전 텍스처 unload→새 URL 로드). 텍스처 키를 imageUrl로 잡아 변경 감지. 회귀 방지로 'matchIndex 변경 시 두 카드 사진이 실제로 교체되는가'를 precise-tap E2E 오라클에 추가.

  - 근거: shot-1·2·3 상단 카드 우하단에 'yelp' 워터마크가 보임. /api/img 폴백 소스(loremflickr 등)에서 워터마크 박힌 이미지가 들어온 것으로 추정(index.mjs:178-179).
