# 사다리 타기 `ladder-game`  ·  random

**Verdict:** needs-fix  ·  **Mode:** ?

## 주제 매력도
사다리 타기는 한국인이라면 누구나 아는 국민 추첨/벌칙 정하기 포맷이다. 점심 내기, 커피 사기, 청소 당번, 술자리 벌칙 정할 때 즉석으로 "사다리 한 판"은 압도적으로 익숙하고 바이럴성 높은 주제다. 무엇을 고를지 모를 때 운에 맡기는 즉석 결정 도구로서 스낵앱 정체성(휘발성·즉석 소비)과 완벽히 맞는다. 주제 자체는 최상급이라 바꿀 필요 없음. 다만 결과 라벨이 지금은 꽝/당첨/벌칙으로 추상적인데, "내가 직접 결과를 적는" 커스텀 슬롯(예: 아메리카노/라떼/내가 쏨)으로 콘텐츠를 채우면 공유·재미가 훨씬 커진다.

## 레퍼런스 (검증된 인기 포맷 모방)
- **모방 대상:** 네이버/카카오 사다리타기 (온라인 사다리타기)
- **구조 100% 복제:** 검증된 사다리타기 룰을 100% 모방: N개의 세로줄 + 무작위 가로 가교(rung), 시작 칸을 고르면 위에서 아래로 내려가며 만나는 모든 가로줄에서 옆 줄로 이동, 바닥의 결과 칸에 도착. 한 칸 선택→경로 애니메이션 트레이스→결과 공개의 진행 흐름. 시작 칸/결과 칸 1:1 대응, 경로는 결정론적이고 시각적으로 추적 가능해야 한다는 핵심 규칙을 그대로 따른다.
- **우리 콘텐츠/디자인:** 콘텐츠: 결과 칸을 추상 라벨(꽝/당첨/벌칙) 대신 상황별 진짜 내기 결과(예: '아메리카노/라떼/공짜/내가 쏨')로 채움. 디자인: 블랙(#0b0c0e/#16181c) 바탕 + 라임(#d9ff00) 경로 트레이스 + 화이트 타이포. 형광 경로가 어두운 배경 위를 흐르는 우리 톤 비주얼.

## 목적
무엇을/누가 정할지 운에 맡기고 싶을 때 즉석으로 여는 한국 국민 추첨 도구. 시작 칸 하나를 탭하면 형광 경로가 사다리를 따라 흘러내려 내 운명(꽝/당첨/벌칙)을 즉시 보여주는, 데드타임 0의 한 판짜리 재미를 준다.

## 핵심 루프
시작 칸(1~4 중 하나)을 탭하면 형광 경로가 사다리를 따라 트레이스되며 도착한 결과 칸이 공개되고, '다시하기'로 즉시 새 판.

## 시나리오
1. 앱을 열면 4개의 시작 원(1~4)과 무작위 가로 가교가 그려진 사다리, 바닥에 결과 칸(꽝/꽝/당첨/벌칙)이 보인다. 힌트: '4개의 시작 칸 중 하나를 골라보세요'
2. 사용자가 시작 칸(예: 원 '2')을 탭한다
3. 선택한 원이 라임색으로 하이라이트되고, 해당 경로(path1)가 라임색으로 켜져 사다리를 따라 내려가는 길을 보여준다
4. 경로가 도착한 바닥 결과 칸이 사용자의 결과가 된다 (start 2 → 꽝)
5. 상단 상태 카드의 '결과'와 '선택' 값이 실제 결과/선택 번호로 갱신되어 텍스트로도 확인된다 (현재 결함: 갱신 안 됨)
6. 힌트 문구가 '형광색 길을 따라 결과를 확인하세요'로 바뀐다
7. '다시하기'를 탭하면 선택/결과/경로가 초기화되어 같은 사다리로 다른 칸을 다시 고를 수 있다

## 성공 기준
- 네 시작 칸 어느 것을 탭해도 즉시(데드타임 0) 라임 경로가 켜지고 결과가 드러난다
- 경로가 사다리 규칙을 정직하게 따른다 — 시작 칸에서 출발해 만나는 가로 가교마다 옆 줄로 이동하며 한 결과 칸에 정확히 도착하고, 트리거가 지정한 결과 라벨과 경로 도착 칸이 일치한다
- 상단 '결과/선택' 상태 카드가 실제 선택·결과로 갱신되어 시각(경로)과 텍스트가 일치한다
- 블랙 배경 위 라임 경로의 대비가 명확하고 한글 타이포(사다리 타기, 결과 라벨)가 안 겹치고 화면 안에 들어온다
- '다시하기'로 깔끔히 초기화되어 반복 플레이가 매끄럽다

## QA 검증 시나리오
- [ ] **QA1** 네 시작 원(s0~s3) 각각을 탭하면 selected/result/revealed가 바뀌고 해당 pathN.visible이 true가 되어 경로가 표시된다 → `각 원 탭 시 대응 라임 경로가 켜지고 원이 라임으로 하이라이트된다`
- [ ] **QA2** 상단 상태 카드 '결과' 값(resultStat.value←result)과 '선택' 값(pickedStat.value)이 선택 후 갱신된다 → `선택 2번 탭 후 '결과: 꽝', '선택: 2번'으로 표시 (현재 FAIL: '대기 중'/'-' 고정)`
- [ ] **QA3** 각 경로의 기하학적 도착 칸이 트리거가 set하는 result 문자열과 바닥 라벨과 일치한다 → `s0→col3=벌칙, s1→col1=꽝, s2→col2=당첨, s3→col0=꽝 모두 일치 (구조상 일치 확인됨)`
- [ ] **QA4** 경로가 사다리 규칙을 지켜 만나는 가로줄을 빠짐없이 타고 한 결과 칸에만 도착한다 → `두 경로가 같은 결과 칸에 도착하거나 가로줄을 건너뛰지 않는다`
- [ ] **QA5** '다시하기' 탭 시 selected=-1, result='시작 칸을 탭하세요', revealed=false로 초기화 → `모든 경로 숨김, 원 하이라이트 해제, 힌트 원복`
- [ ] **QA6** 한글 텍스트(타이틀/결과 라벨/힌트)가 겹치지 않고 컨테이너 안에 들어온다 → `겹침/잘림 없음 (스크린샷상 OK)`
- [ ] **QA7** statusRow 두 StatCard와 하단 ladderCard가 시각적으로 분리되어 보인다 → `카드 경계가 명확 (현재 두 StatCard 하단이 ladderCard와 한 덩어리로 붙어 보임)`

## 현재 깨짐 (진단)
- **[high]** 상단 상태 카드가 죽어있음 — 선택/결과가 갱신되지 않는다. 시작 칸을 골라 경로가 켜진 상태(shots 2·3)에서도 '결과: 대기 중', '선택: -'로 고정. idle.bindings의 resultStat.value←result, pickedStat.value←(selected expr)가 컴포넌트 인스턴스 propValue로 재전파되지 않는 알려진 레거시 엔진 결함.
  - 근거: ladder-game-2.png(선택1)·ladder-game-3.png(선택2) 모두 상단이 '대기 중'/'-' 그대로. 문서 L82-110(StatCard 인스턴스) + L750-752(bindings)
  - 수정: StatCard 인스턴스 propValue 바인딩에 의존하지 말고, 결과/선택을 표시할 자체 text 레이어(예: resultText, pickedText)를 sharedLayers에 직접 두고 state-level binding으로 content를 묶어라(s0t 등 텍스트 색 바인딩은 정상 동작하므로 text.content 직접 바인딩이 안전). 또는 StatCard 대신 상단을 단순 text 2개로 교체.
- **[low]** 두 StatCard와 ladderCard가 시각적으로 한 덩어리로 붙어 보임 — statusRow 카드 하단 라운드가 아래 ladderCard 상단과 맞물려 '큰 카드 위에 노치가 파인' 형태로 읽힌다. 카드 간 위계가 모호.
  - 근거: 세 스크린샷 모두에서 결과/선택 카드 하단과 ladder 카드 상단 사이 간격(gap14)이 두 카드 색(#16181c)이 같아 경계가 사라짐
  - 수정: statusRow 카드와 ladderCard 배경색을 살짝 분리하거나 카드 간 gap을 키우고, StatCard 모서리를 명확히 끊어 위계를 만든다.
- **[low]** 멀티 표시(우상단 '인원 1')가 붙어 있으나 이 앱에는 멀티 메커닉이 없다 — 함께 보는 spectate조차 동기화/공유 결과 없이 단지 카운터만 떠 있어 오해를 준다.
  - 근거: 세 스크린샷 우상단 'people 1' 배지. 문서에는 멀티/공유 트리거 없음(scope 전부 scene, 로컬)
  - 수정: single 전용임을 분명히 하고 멀티 배지를 숨기거나, 멀티 변형은 별도 앱으로 분리(multiVariantIdea 참고).
