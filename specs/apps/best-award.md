# 우리 모임 베스트 `best-award`  ·  vote

**Verdict:** needs-fix  ·  **Mode:** multi (vote (실시간 동시 집계 — emitHostEvent 'vote' → 서버 setVar votesByOption 전체 동기화))

## 주제 매력도
"우리 모임 베스트"는 모임/회식/동아리/단톡방에서 "오늘의 MVP 누구냐"를 즉석에서 뽑는 보편적이고 강한 소셜 훅이다. 연말 시상식·예능 시청자 투표·아이돌 팬투표처럼 한국인에게 익숙한 '실시간 라이브 투표' 포맷이라 진입 장벽이 0이고 결과를 같이 보며 떠드는 재미가 크다. 다만 현재 후보가 "베스트 스타/명장면 메이커/스타일 아이콘/라이징 루키"처럼 추상적 어워드 명칭이라 "내 모임 사람"과 연결이 약하다 — 후보를 실명/별명 슬롯(예: '제일 텐션 높았던 사람', '먹방 1등', '오늘 MVP')로 바꿔 모임 맥락에 꽂히게 하면 훨씬 매력적이다.

## 레퍼런스 (검증된 인기 포맷 모방)
- **모방 대상:** 네이버/예능 실시간 시청자 투표 + 아이돌 팬덤 라이브 투표(예: 프로듀스/엠카운트다운 실시간 집계)
- **구조 100% 복제:** 단일 화면에 N개 후보를 세로 막대로 나열 → 탭 1번으로 즉시 투표 확정 → 전체 막대가 실시간 비율(%)로 동시에 차오름 → 내가 찍은 항목은 강조색으로 표시, 재탭으로 변경 가능 → 별도 결과 화면 없이 '투표=결과'가 한 화면에서 동시에 일어나는 라이브 폴 구조를 100% 모방
- **우리 콘텐츠/디자인:** 콘텐츠: 모임 시상식 어워드 4개 카테고리(베스트 스타/명장면 메이커/스타일 아이콘/라이징 루키)를 우리가 채움 — 단 모임 맥락에 더 붙는 후보 슬롯으로 개선 권장. 디자인: 블랙(#0b0c0e) 배경 + 라임(#d9ff00) 강조, 선택 항목 라임 하이라이트로 우리 톤 적용.

## 목적
모임에서 '오늘의 베스트는 누구냐'를 다 같이 한 화면에서 실시간으로 뽑고, 표가 차오르는 걸 보며 즉석에서 떠드는 재미를 주는 휘발성 라이브 투표 스낵. 한 탭으로 참여, 결과가 바로 눈앞에서 움직여 '같이 보는' 순간의 쾌감을 준다.

## 핵심 루프
4개 후보 막대 중 하나를 탭 → 내 표가 즉시 반영되고 전체 막대가 실시간 비율로 차오르며 내 선택이 라임으로 강조된다(재탭으로 변경).

## 시나리오
1. 링크로 입장 → 검은 화면에 '베스트 어워즈' 타이틀과 4개 후보 막대가 보이고 우상단에 접속 인원(👥 1) 표시
2. 후보 막대를 눈으로 훑음 → 각 막대 끝에 현재 비율(%)이 표시되어 누가 앞서는지 즉시 파악
3. 원하는 후보(예: 명장면 메이커)를 탭 → 해당 막대가 라임으로 강조되고 myVote가 'o1'로 설정, vote 이벤트가 서버로 emit
4. 서버가 votesByOption 집계 후 전체 동기화 → 모든 참가자 화면의 4개 막대 width와 %가 동시에 갱신됨
5. 마음이 바뀌면 다른 후보를 재탭 → 이전 선택 해제, 새 선택이 라임으로 바뀌고 집계가 다시 갱신(스낵=결과 화면 없이 즉석 반복)
6. 다른 사람이 투표할 때마다 내 화면의 막대 비율이 실시간으로 출렁이며 라이브 시상식 느낌으로 함께 관전

## 성공 기준
- 4개 후보 막대가 화면 안에 겹침 없이 들어오고 라벨·%·막대가 정렬됨
- 탭 즉시(데드타임 0) 선택이 라임으로 강조되고 막대/%가 변함
- 막대 width와 표시 %가 항상 일치한다(예: 라임 가득 찬 막대가 0%로 표시되면 안 됨)
- 최초 입장 시 아무도 안 찍었으면 모든 후보가 0%이고 막대가 비어 있어야 함(특정 후보가 100%로 시작하면 안 됨)
- 막대가 진행률처럼 자연스럽게 읽혀야 함 — 낮은 %에서 둥근 알약 덩어리로 깨져 보이면 안 됨
- 선택 강조 색(라임)과 비율 막대가 시각적으로 충돌하지 않고 둘 다 동시에 읽혀야 함
- 후보 명칭이 '우리 모임' 맥락에 맞고 진짜처럼 느껴짐

## QA 검증 시나리오
- [ ] **QA1** 4개 후보(opt0~opt3) 각각을 탭하면 myVote가 해당 옵션으로 바뀌고 라임 강조가 그 행으로 이동하는가 → `4개 모두 반응, 강조는 항상 1개 행에만`
- [ ] **QA2** 투표 시 emitHostEvent 'vote'가 발사되고 서버 집계 후 votesByOption 동기화로 막대 width와 %가 변하는가 → `탭 후 즉시 해당 막대/% 증가`
- [ ] **QA3** 각 막대의 width가 표시된 % 숫자와 비례 일치하는가 (bar.width = round(share*358), pct = round(share*100)) → `라임 가득 막대 = 높은 %, 빈 막대 = 0% — 가득 찬데 0% 같은 모순 없음`
- [ ] **QA4** 아무 투표도 없는 초기 상태에서 모든 후보가 0%이고 막대가 최소폭(6px)인가 → `초기 4개 모두 0%, 특정 후보 100% 선출되어 있으면 fail`
- [ ] **QA5** 낮은 비율(예: 9%) 막대가 진행 막대로 읽히는가, 둥근 알약 덩어리/분리된 블록으로 깨지지 않는가 → `막대가 좌측에서 비율만큼 차오른 직사각 진행바로 보임`
- [ ] **QA6** 선택된 라임 행에서도 %와 라벨이 가독성 있게 보이는가(라임 배경 위 텍스트 대비) → `라벨 다크(#0b0c0e), % 가독 — 라임 행에서 % 사라지지 않음`
- [ ] **QA7** vote 카테고리: 재탭으로 표 변경 시 이전 표가 빠지고 새 표가 더해지는가(중복 카운트 없음) → `총 표 수 유지, 한 사람=한 표`
- [ ] **QA8** 텍스트(타이틀/서브/라벨/%)가 겹치지 않고 390폭 안에 들어오는가 → `줄바꿈 깨짐·겹침·잘림 없음`

## 현재 깨짐 (진단)
- **[high]** 선택된 라임 막대와 비율 막대가 시각적으로 충돌·모순 — best-award-3.png에서 '명장면 메이커'가 행 전체가 라임으로 꽉 차 있는데 다른 행은 0%이고 그 라임 행엔 % 표시가 없다. 즉 '가득 찬 막대'와 '실제 집계'가 어긋나 라이브 폴의 핵심(막대=비율)이 깨진다. 원인: 선택 강조(myVote→bar.color 라임)와 비율 width가 별개로 동작하면서 선택 시 막대가 비율과 무관하게 꽉 찬 것처럼 보이고, pct가 라임 위에서 사라짐.
  - 근거: best-award-3.png: '명장면 메이커' 행 100% 라임 풀필 + % 미표시, 동시에 '베스트 스타/스타일 아이콘/라이징 루키'는 0%
  - 수정: 선택 강조는 막대 채움이 아니라 행 테두리/배경 톤 변화 등 비율과 독립된 신호로 분리하고, bar.width는 항상 비율만 반영. 선택 행에서도 pct/라벨이 항상 보이도록 색 대비를 보장(라임 위 다크 텍스트로 % 포함).
- **[medium]** 비율 막대가 cornerRadius:14를 가진 채 width로 진행률을 표현해 낮은 비율에서 둥근 알약 덩어리로 깨져 보임 — best-award-2.png에서 9% 막대가 좌측에 분리된 통통한 라운드 사각형으로 보여 진행바가 아니라 별도 버튼처럼 읽힌다.
  - 근거: best-award-2.png: '베스트 스타' 9% 막대가 폭 대비 과도하게 둥근 라임 블록(약 80px 폭의 알약)으로 렌더, 진행률로 안 읽힘 (bar0 cornerRadius:14, best-award.bite.json:100)
  - 수정: 진행 막대는 cornerRadius를 0 또는 좌측만 라운드로, 부모 clip에 맞춰 우측은 직각이 되게 하거나 트랙 위에 채움바를 얇게 깔아 비율감 확보.
- **[medium]** 초기 진입 화면이 0%가 아니라 특정 후보가 100%로 선출된 상태로 보임 — best-award-1.png에서 아무 인터랙션 전인데 '명장면 메이커' 100%, 막대 풀필. 신규 입장자에게 '이미 결판난 투표'처럼 보여 라이브 폴의 즉석 참여 동기를 해친다.
  - 근거: best-award-1.png: 초기 화면에서 '명장면 메이커' 100% + 라임 테두리 풀필, 나머지 0%
  - 수정: 세션 시작 시 votesByOption 전부 0으로 시드하고, 총합 0일 때는 모든 행 0%·빈 막대로 표시(현재 Math.max(1,...) 분모 처리는 0%를 만들지만 화면엔 100%가 떠 있어 잔존 상태/시드 데이터 의심 — 서버 초기화 확인 필요).
- **[low]** 하단 약 60% 영역이 빈 검은 공간 — 4개 막대가 화면 상단 1/3에만 모여 있고 나머지가 비어 허전하다. 휘발성 스낵으로서 '꽉 찬 한 화면' 밀도가 부족.
  - 근거: best-award-1~3.png 공통: opt3(라이징 루키) 아래로 화면 끝까지 빈 검은 영역
  - 수정: 막대 height/gap을 키우거나, 하단에 현재 1위 배지·총 투표 수·라이브 펄스 등 라이브 폴 요소를 추가해 화면 밀도와 관전 재미를 확보.
