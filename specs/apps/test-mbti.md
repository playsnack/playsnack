# MBTI 빠른 테스트 `test-mbti`  ·  psych

**Verdict:** needs-fix  ·  **Mode:** single

## 주제 매력도
MBTI는 한국에서 자기소개·소개팅·밈의 공용어 수준으로 검증된 초강력 주제다. "내 4글자 유형이 뭔지" 즉석으로 확인하고 캡처해 공유하는 행동이 이미 문화로 자리잡아 휘발성 스낵과 완벽히 맞는다. 다만 현재 6문항/4축 구성은 MBTI의 핵심 매력인 "4글자 + 유형 이름 + 짧은 설명"을 어설프게 모방해 정확도와 진실성이 깨져 있다. 주제 자체는 최상급이므로 바꿀 필요 없고, 16Personalities식 정통 4축 구조로 로직만 제대로 모방하면 된다.

## 레퍼런스 (검증된 인기 포맷 모방)
- **모방 대상:** 16Personalities 간이 MBTI 테스트 (및 KR 바이럴 '성격유형 12문 테스트')
- **구조 100% 복제:** 한 화면당 1문항·2지선다(또는 동의/비동의)로 탭 즉시 다음 문항으로 진행 → 4개 축(E/I·N/S·T/F·J/P) 각각을 동일 개수 문항으로 채점 → 마지막에 다수결로 4글자 확정 → 4글자 코드 + 유형 닉네임 + 한 줄 설명 + 다시하기. 진행도(n/총문항)를 항상 노출.
- **우리 콘텐츠/디자인:** 문항·선택지 카피와 16개 유형 닉네임/설명은 KR 정서로 새로 작성(현재 카피 톤은 좋음). 비주얼은 블랙(#0b0c0e) + 라임(#d9ff00) 톤 유지. 결과 4글자를 라임으로 크게, 유형 닉네임/설명을 그 아래.

## 목적
사용자가 1분 안에 6번 탭만으로 자기 'MBTI 4글자 유형'을 즉석으로 뽑아 보고, 결과 화면을 캡처해 친구에게 공유하는 가벼운 자기진단 스낵. 재미의 핵심은 마지막에 튀어나오는 라임색 4글자 + 유형 닉네임의 '맞아 나 이거야' 순간이다.

## 핵심 루프
질문마다 두 선택지 중 하나를 탭하면 즉시 다음 문항으로 넘어가고, 6문항을 마치면 4글자 유형과 닉네임 결과가 나오며 다시하기로 반복한다.

## 시나리오
1. 앱 진입: '성격 테스트' 타이틀, '1/6 · 에너지' 칩, 문항 '주말 오후, 나는 더 끌리는 쪽은?', 선택지 카드 2개 표시
2. 선택지 탭 → setVar로 축 점수 +1, goToState로 q2 화면 즉시 전환
3. 문항 2~6을 차례로 탭, 상단 칩의 진행도/축 라벨 갱신
4. 6번 문항 탭 → result 상태 전환
5. 결과 화면: 라임색 4글자, 닉네임, 설명, 균형 점수
6. '다시 테스트하기' 탭 → 변수 0 리셋 후 q1 복귀

## 성공 기준
- 6문항이 끊김 없이 탭 한 번에 다음으로 넘어가고 데드타임이 없다
- 진행도(1/6~6/6)가 항상 보이고 매 문항 정확히 갱신된다
- 결과의 4글자 코드가 실제 사용자 선택을 정확히 반영하고, 그 아래 유형 닉네임/설명이 그 4글자와 논리적으로 일치한다
- 모든 텍스트가 화면 안에 들어오고 겹치지 않으며, 긴 문항도 2줄 안에 깔끔히 줄바꿈된다
- '다시하기'가 점수를 초기화해 새 결과를 낼 수 있다(반복 가능)
- 혼자 하는 자기진단이라는 single 정체성에 맞게 군더더기(불필요한 멀티 UI) 없이 결과까지 직진한다

## 현재 깨짐 (진단)
- **[high]** 4글자 채점 로직이 불균형하고 부정확하다. 6문항이 4축에 불균등 매핑됨 — e는 q1A+q5A(2문항), n은 q2A+q6A(2문항), t는 q3A(1문항), j는 q4A(1문항). 그런데 result 바인딩(line 1077)은 모두 일괄 '>=1' 임계값을 쓴다. 즉 2문항 축도 단 1번의 A선택이면 글자가 뒤집히고, T/J축은 애초에 1문항으로만 결정된다. MBTI 모방이 핵심인데 채점이 다수결도 아니고 축별 문항 수도 제각각이라 결과 코드의 진실성이 깨진다.
  - 근거: line 1077 resultType.content의 'e>=1','n>=1','t>=1','j>=1' 임계값; q1A(line 834)·q5A(line 1003)가 모두 e++, q2A(877)·q6A(1045)가 모두 n++, t는 q3A(918)만, j는 q4A(960)만 증가
  - 수정: 각 축당 문항 수를 동일하게(예: 축당 2문항=총 8문항, 또는 4문항으로 축당 1문항씩 명확히) 재배치하고, 임계값을 '해당 축 문항 수의 과반'으로(예: 2문항이면 >=1 대신 동점 처리 규칙 명시, 혹은 +1/-1 누적 후 >0) 통일. scoreLine의 'E e/2 · N n/2 · T t/1 · J j/1'(line 1080)처럼 축별 만점이 다른 것도 동일하게 맞춘다.
- **[high]** 결과 닉네임/설명이 4글자 코드와 분리되어 모순이 생긴다. resultName(line 1078)과 resultDesc(1079)는 오직 e와 n만 보고 4가지 중 하나를 고른다. 정작 코드(resultType)는 t,j까지 반영한 16종. 따라서 코드가 ESTJ여도 닉네임은 e>=1만 보고 '따뜻한 연결가'(E계열) 식으로 나와, 화면의 4글자와 닉네임이 서로 안 맞는 인지부조화가 발생한다.
  - 근거: resultType은 e,n,t,j 4개 모두 사용(line 1077), 그러나 resultName(1078)/resultDesc(1079)는 'e>=1 && n>=1 / e>=1 / n>=1 / else'로 t,j를 전혀 안 본다
  - 수정: 닉네임/설명을 최소한 표시되는 4글자 코드와 정합하게 매핑(이상적으로 16유형 닉네임 테이블, 최소한 코드와 같은 변수 집합으로 분기). 16개가 부담이면 결과를 4유형으로 줄이고 4글자 코드 노출을 그 4유형과 일치시킨다.
- **[medium]** 포맷 버전이 1.10.0으로 프로젝트 표준 1.14.0과 불일치. 본보기 템플릿으로서 부적합하다.
  - 근거: line 2 "포맷 버전": "1.10.0" (CLAUDE.md는 포맷 버전 1.14.0을 단일 표준으로 명시)
  - 수정: 1.14.0으로 정렬하고 1.14.0에서 검증.
- **[low]** single 자기진단 앱인데 우상단에 멀티용 인원수 배지('사람 아이콘 1')가 떠 있어 정체성과 어긋난다. 혼자 하는 테스트에 동석자 수 UI는 의미 없는 노이즈다.
  - 근거: 스크린샷 test-mbti-1/2/3 우상단 공통으로 보이는 파란 인물아이콘+'1' 배지 (구조 .문서에는 정의 없음 → 플레이어 셸이 모든 앱에 일괄 주입하는 것으로 추정)
  - 수정: playMode가 single인 템플릿에서는 인원수 배지를 숨기도록 플레이어 셸에 조건 처리(앱 메타의 모드에 따라). 이 .bite.json 자체 수정은 불필요.
