# 우리 중 누가? (멀티 · 세션)  —  id: most-likely-roster-vote

## 한 줄
방 안의 실제 사람을 몰래 지목해, 최다 득표자가 그 라운드의 주인공이 된다.

## 왜 인기 (근거)
- "Most Likely To"는 회식·MT·술자리·단톡방에서 검증된 파티 게임 포맷이다. 정답·실력이 필요 없어 진입장벽 0, 지목당하면 웃기고 결과가 "방 안 실제 사람"을 향하므로 그 자리에서 즉시 대화가 터진다.
- 기존 `who-most-likely`(가상 후보 4명 고정 리스트)와의 결정적 차이: 후보가 **방에 같이 들어온 진짜 멤버(roster)**다. 내 옆 사람을 찍는다는 점에서 폭로/놀림의 강도와 몰입이 훨씬 높다 — "익명 지목 + 라이브 리빌"의 SNS 투표 스티커 재미를 오프라인 모임에 그대로 얹는다.
- 멀티라운드라 한 번 모이면 질문을 갈아끼우며 계속 돈다(재플레이성). 매 라운드 다른 사람이 주인공이 되며 "이번엔 누구?"의 긴장이 반복 소비된다.

## 세션 흐름 (화면별)
- **대기실(lobby)**: 방 코드/링크로 들어온 멤버의 닉네임이 그리드(roster)로 쌓인다(👥 N명). 각 멤버는 닉네임 칩으로 표시. 방장(또는 누구나)에게 **시작하기** 버튼. 최소 2명, 최대 8명. roster가 1명이면 시작 비활성(혼자서는 지목 불가) + "한 명 더 들어와야 시작돼요" 안내.
- **카운트다운**: 서버 broadcast로 3·2·1 동기화. 모든 클라가 같은 숫자를 동시에 본다. 카운트 동안 이번 라운드 프롬프트(질문)를 크게 노출해 "누구 찍을지" 미리 생각하게 함.
- **플레이(play)**: **멀티라운드**. 화면 상단에 라운드 프롬프트("우리 중 가장 늦잠 잘 것 같은 사람?"), 그 아래 **방 멤버 닉네임 그리드(roster 그대로)**. 각자 한 명을 탭해 몰래 지목(= 본인의 표). 탭하면 그 칩이 라임으로 점등(내 표 표시), 재탭/다른 칩 탭으로 변경 가능. 라이브로 각 멤버 칩에 **득표 수/막대**가 실시간으로 차오른다(서버가 votesByName 합산을 전체에 setVar 동기화). 자기 자신 지목 허용 여부는 콘텐츠팩 플래그(`allowSelfVote`, 기본 true — 셀프 디스 재미). 서버 타이머 종료(또는 전원 투표 완료) 시 자동으로 결과로 전환.
- **결과(result)**: 이번 라운드 **최다 득표자(주인공) 공개** — 닉네임 크게 + 득표수 + 라임 스포트라이트 연출. 동률이면 공동 주인공 다중 표시. 막대 랭킹으로 2~3등도 노출. **다시** 버튼 → 다음 라운드 프롬프트로 카운트다운 재시작(서버가 라운드 인덱스++, votesByName 리셋, 새 roundContent broadcast). 콘텐츠팩 소진 시 셔플/처음으로 순환.

## 컨트랙트 매핑
- **컨트랙트: `vote`** (one-per-person tally). 단, 후보가 고정 옵션이 아니라 **roster의 멤버(playerId/nickname)**라는 점이 핵심 — `roster` 컨트랙트(누가 들어왔나)와 `vote`를 함께 사용한다.
- host event emit 시점:
  - **start**: 대기실에서 시작하기 탭 → `start` emit → 서버가 sessionPhase=countdown으로 전환·broadcast.
  - **vote**: 플레이에서 멤버 칩 탭 → `vote{ targetId }` emit. 서버가 1인 1표로 votesByName 갱신(같은 사람이 재탭하면 이전 표 차감 후 새 표 가산) → setVar로 votesByName + 우상단 인원 전체 동기화. 라이브 막대/카운트는 이 broadcast에 반응.
  - tally/score/tap: **미사용**(이 게임은 순수 지목 투표라 co-op 누적·퍼플레이어 카운트 불필요).
- **라운드 필요: 예 (멀티라운드).** 서버가 roundIndex를 들고 결과 후 **다시** 시 roundIndex++ → 새 prompt를 roundContent로 broadcast + votesByName 리셋 + sessionPhase=countdown 재진입. 단일 라운드로도 동작 가능(다시 안 누르면 1라운드로 끝).
- 클라 레거시 엔진 상태(lobby/countdown/play/result)는 서버 broadcast `sessionPhase` var를 onFrame guard로 감시해 전환.

## 콘텐츠
- 후보는 **콘텐츠가 아니라 roster**(런타임 실제 참가자)에서 채워진다 — 후보 명단을 콘텐츠팩에 넣지 않는다. 콘텐츠팩은 **프롬프트(질문) 풀**만 서버 권위로 보유·broadcast.
- 서버 콘텐츠팩 형식(JSON) 제안:

```json
{
  "packId": "most-likely-ko-v1",
  "contract": "vote",
  "rosterBased": true,
  "allowSelfVote": true,
  "prompts": [
    { "id": "p01", "text": "우리 중 가장 늦잠 잘 것 같은 사람은?", "emoji": "😴" },
    { "id": "p02", "text": "단톡방에서 읽씹할 것 같은 사람은?", "emoji": "📵" },
    { "id": "p03", "text": "갑자기 여행 가자며 10분 뒤 항공권 찾아올 사람은?", "emoji": "✈️" },
    { "id": "p04", "text": "회식 끝까지 남을 것 같은 사람은?", "emoji": "🍻" },
    { "id": "p05", "text": "연락 제일 안 될 것 같은 사람은?", "emoji": "👻" }
  ]
}
```

- 서버가 라운드마다 broadcast하는 `roundContent` 형식:

```json
{
  "roundIndex": 0,
  "prompt": { "id": "p01", "text": "우리 중 가장 늦잠 잘 것 같은 사람은?", "emoji": "😴" },
  "allowSelfVote": true
}
```

- 라이브 집계 broadcast(`votesByName`): `[{ "playerId": "a1", "nickname": "민지", "count": 2 }, ...]` (서버 권위, 모든 클라 동일). roster 자체도 서버가 들고 broadcast(입·퇴장 반영).
- KR 신조어/공감·폭로형 질문 풀을 정시(KST)마다 동적 콘텐츠로 교체하면 재방문 동기가 커진다(프로젝트의 dynamic content 규칙과 정합).

## 성공 기준
- 대기실에서 실제 입장 멤버 수가 roster 그리드에 정확히 반영되고(👥 N), 2명 이상일 때만 시작된다.
- 카운트다운 3·2·1이 모든 클라에서 ±0.3s 이내로 동기화되어 동시에 플레이로 진입한다.
- 멤버 칩 탭 즉시(0 지연) 내 표가 라임으로 점등되고, 다른 참가자 표가 내 화면의 득표 막대에 실시간 합산된다(1인 1표, 재탭 시 표 이동 정확).
- 결과에서 최다 득표자가 정확히 1명(또는 동률 시 공동) 공개되고, 득표수 합 = 투표한 인원 수와 일치한다.
- **다시** 시 새 프롬프트로 다음 라운드가 시작되고 이전 라운드 득표가 0으로 리셋된다(라운드 누수 없음).
- roster 멤버 닉네임/득표 막대가 8명까지 390x844 한 화면에 스크롤 없이 겹치지 않고 들어간다.

## QA 검증 시나리오 (멀티클라이언트)
3개 클라이언트(A=방장, B, C)로 같은 `/p/tpl-most-likely-roster-vote` 링크 접속.

- **1. 입장 → roster N**: A 접속 후 B, C 순차 접속.
  - PASS: 세 기기 모두 대기실에서 닉네임 칩 3개(A·B·C)가 roster 그리드에 보이고 우상단 👥3 동일. A 화면의 시작하기 버튼 활성(2명 이상). C 입장 전(2명 시점)에도 이미 활성, 1명일 땐 비활성/안내 노출 확인.
- **2. 시작 → 카운트 싱크**: A가 시작하기 탭.
  - PASS: 세 기기 모두 거의 동시에 카운트다운 화면으로 전환되고 3→2→1 숫자가 함께 떨어진다. 카운트 중 동일한 라운드 프롬프트("우리 중 가장 늦잠 잘 것 같은 사람?")가 세 기기에 똑같이 보인다.
- **3. 플레이 입력(라이브 집계)**: 카운트 종료 후 A가 B를, B가 A를, C가 A를 탭.
  - PASS: 각 기기에서 자기가 탭한 칩이 라임으로 점등(내 표). 세 기기 모두 A 칩에 득표 2, B 칩에 득표 1로 라이브 막대가 동일하게 차오른다. C가 탭을 A→B로 재탭하면 A=1, B=2로 세 기기에서 즉시 재집계(1인 1표·표 이동 검증).
- **4. 결과 집계/리빌**: 서버 타이머 종료(또는 전원 투표 완료).
  - PASS: 세 기기 모두 결과 화면으로 동시 전환, 최다 득표자(예: B, 2표)가 스포트라이트로 동일하게 공개. 득표 합(=투표 인원)과 랭킹이 세 기기에서 일치. 동률 상황을 별도로 만들면(A=1,B=1,C=1) 공동 주인공 다중 표시 확인.
- **5. 다시(다음 라운드)**: 결과에서 다시 탭.
  - PASS: 세 기기 모두 새 프롬프트("단톡방에서 읽씹할 것 같은 사람은?")로 카운트다운 재시작, 모든 멤버 칩 득표가 0으로 리셋되어 표시(이전 라운드 막대 잔존 없음).
