# 오늘 컨디션 슬라이더 `mood-slider`  ·  reaction

**Verdict:** needs-fix  ·  **Mode:** single

## 주제 매력도
"오늘 컨디션/기분 0~100"은 한국 SNS에서 매일 쓰이는 친숙한 소재(인스타 스토리 "오늘의 기분", MBTI식 자가진단, 컨디션 체크)다. 누구나 0초 학습으로 즉시 자기 상태를 매핑할 수 있어 진입장벽이 없다. 다만 현재 구현은 '컨디션 + 건강 조언(스트레칭/물/낮잠)'으로 다소 자기관리 앱처럼 진지해져 스낵의 가벼움을 깎아먹는다. 더 매력적인 방향: "오늘 텐션 게이지" 같이 밈/공감형 카피(예: 100='오늘 못 막음', 0='영혼 가출')로 바꿔 캡처해서 공유하고 싶은 위트 결과물로 만들면 휘발성 스낵에 훨씬 잘 맞는다.

## 레퍼런스 (검증된 인기 포맷 모방)
- **모방 대상:** 인스타그램 스토리 슬라이더 스티커 (이모지 슬라이더)
- **구조 100% 복제:** 단일 연속 슬라이더(0~100)를 손가락으로 움직이면 위치에 따라 이모지/라벨이 실시간 변하고, 멈춘 값이 곧 '내 답'이 되는 1탭 자기표현 포맷. 슬라이더 채움바 + 핸들 + 실시간 이모지 반응 = 100% 모방. 결과를 캡처/공유하는 휘발성 흐름까지 그대로.
- **우리 콘텐츠/디자인:** 콘텐츠는 '오늘 컨디션' 한국어 5구간 카피(이모지+코멘트+한 줄 추천)로 새로 채우고, 비주얼은 블랙(#0b0c0e)+라임(#d9ff00) 톤. 인스타가 핸들 드래그라면 우리는 드래그 슬라이더를 핵심 컨트롤로 두고 단계 탭/±버튼은 보조로.

## 목적
지금 내 컨디션/텐션을 0~100 한 숫자로 즉석 매핑해, 위치에 따라 바뀌는 이모지·코멘트·한 줄 추천을 보고 '아 맞아 오늘 나 이래' 하고 공감하는 10초짜리 자기표현 스낵. 결과 화면을 캡처해 친구에게 '오늘 나 이 정도'라며 던지는 가벼운 공유 재미.

## 핵심 루프
컨디션 게이지를 드래그(또는 단계 탭/±10 버튼)로 움직이면 숫자·채움바·이모지·코멘트·추천이 실시간으로 바뀐다.

## 시나리오
1. 앱을 열면 기본값 50에서 🙂 이모지, '50', '무난한 컨디션' 코멘트, 채움바 절반이 보인다
2. 사용자가 슬라이더(현재는 단계 탭/± 버튼)로 값을 내린다 → 숫자가 40으로 줄고 채움바가 즉시 짧아진다
3. 계속 30까지 내리면 이모지가 🙂→😮‍💨로 바뀌고 코멘트가 '조금 무거운 날이에요'로, 하단 추천 카드도 '꼭 필요한 한 가지에 집중'으로 동시 갱신된다
4. 값을 0/25/50/75/100 단계 칩으로 점프하면 해당 칩이 라임으로 강조(accent)되고 모든 표시가 그 구간에 맞게 점프한다
5. 사용자가 자기 실제 상태와 맞는 위치를 찾으면 멈추고 결과(이모지+숫자+코멘트+추천)를 확인한다
6. 마음에 드는 결과 화면을 캡처해 공유하거나, 다시 값을 움직이며 가볍게 만지작거린다

## 성공 기준
- 모든 컨트롤(단계 탭 0/25/50/75/100, −10/+10)이 즉시 응답하고 데드타임이 0이다
- 숫자·채움바·이모지·코멘트·추천 5요소가 값 변화에 한 프레임 안에 함께 변한다
- 구간별 카피가 진짜 그 상태에 공감되는 한국어이고 이모지가 코멘트 톤과 일치한다(예: 30=😮‍💨 무거운 날)
- 모든 텍스트가 화면 안에 들어오고 서로 겹치지 않으며 두 줄 코멘트도 깨끗하게 읽힌다
- 블랙+라임 톤이 일관되고 강조색(라임)이 '현재 값/주 액션'에만 쓰여 시선이 한곳에 모인다

## QA 검증 시나리오
- [X] **QA1** −10/+10 버튼 탭 시 mood가 10씩 변하고 0/100에서 클램프되는가 → `값이 0 미만/100 초과로 가지 않고 숫자·채움바가 갱신된다`
- [X] **QA2** 단계 칩(0/25/50/75/100) 탭 시 해당 값으로 점프하고 그 칩만 라임 accent 처리되는가 → `탭한 칩이 라임 강조, 나머지는 기본색; mood가 정확히 그 값`
- [X] **QA3** 채움바(barFill) 폭이 값에 비례해 보이고 0에서도 최소폭(2px)으로 보이는가 → `barFill.width = round(max(2,mood)/100*320), 시각적으로 비례`
- [X] **QA4** 구간 경계(20/40/60/80)에서 이모지·코멘트·추천이 정확히 바뀌는가 → `mood<20 🪫 / <40 😮‍💨 / <60 🙂 / <80 😊 / else ⚡️ 및 매칭 카피`
- [X] **QA5** heroCard 안 5개 텍스트(emoji/score/label/comment/miniHint)가 서로 겹치지 않는가 → `두 줄 코멘트 상황에서도 miniHint와 겹침 0, 모두 카드 안`
- [X] **QA6** 콘텐츠 진실성 — 코멘트와 추천이 해당 컨디션 구간에 실제로 부합하는가 → `숫자/이모지/코멘트/추천 4요소가 같은 구간 의미로 일관`
- [X] **QA7** reaction 카테고리 특성 — 입력→피드백 지연이 체감 0인가 → `탭 즉시(애니메이션 없이도) 모든 표시 갱신, 멈칫 없음`

## 현재 깨짐 (진단)
- **[high]** heroCard 안에서 2줄짜리 comment 텍스트가 바로 아래 miniHint('0은 완전 방전, 100은 최고 에너지')와 세로로 겹친다. 스크린샷 3장 모두 '유지해요./쪼개보세요.' 두 번째 줄이 miniHint 글자를 관통한다.
  - 근거: mood-slider-1/2/3.png 모두: 코멘트 둘째 줄 '유지해요.'·'쪼개보세요.'가 '0은 완전 방전, 100은 최고 에너지' 줄과 픽셀 단위로 겹쳐 가독성 깨짐. 원인: heroCard가 고정 height:292(line 62) + justifyContent:center(line 75)인데 comment가 2줄로 늘어나면 자식 합산 높이가 카드를 초과해 다음 줄로 흐르며 겹침. comment(width:300, line 115)와 miniHint(width:300, line 126) 사이 gap:10이 2줄 케이스를 흡수하지 못함.
  - 수정: heroCard.height를 고정 292 대신 'hug'로 바꿔 내용에 맞게 늘어나게 하거나, 코멘트를 한 줄에 들어오게 카피를 짧게(예: '무난한 컨디션이에요') 줄인다. 가장 안전: height:'hug' + minHeight로 카드 형태 유지하고 justifyContent center 제거(direction column 자연 흐름).
- **[medium]** 핵심 컨트롤이 진짜 '슬라이더'가 아니라 단계 칩 + ±10 버튼이다. 제목/장르(slider, reaction)와 인터랙션이 불일치 — 연속 드래그의 손맛(스낵의 핵심 재미)이 없다.
  - 근거: 문서에 click 트리거만 있고(line 352-444) drag/슬라이더 핸들 없음. barTrack(line 143)은 표시용 채움바일 뿐 탭/드래그 입력을 받지 않음. 하단 안내문도 '단계 탭 또는 버튼으로'(line 328)라 슬라이더 부재를 자인.
  - 수정: barTrack에 핸들 + drag/탭 입력을 붙여 연속 슬라이더로 만들어 인스타 이모지 슬라이더 포맷을 제대로 모방. 단계 칩/±버튼은 보조로 남기거나 제거. 최소한 barTrack 탭으로 위치 점프라도 추가.
- **[low]** miniHint(설명문)가 hero 결과 영역 안에 상시 표시되어 시각적 노이즈를 더하고, 겹침 사고의 직접 원인이 된다.
  - 근거: miniHint '0은 완전 방전, 100은 최고 에너지'(line 120)가 결과(숫자/코멘트)와 같은 카드 안에 있어 정보 위계가 흐려짐. 이미 슬라이더 양끝 라벨(0/100 칩)이 같은 정보를 줌.
  - 수정: miniHint를 heroCard 밖(슬라이더 근처 캡션)으로 옮기거나 제거. 결과 카드는 이모지+숫자+코멘트만 남겨 위계 단순화.
