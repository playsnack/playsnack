# 눈치게임 (멀티 · 세션)  —  id: nunchi-tap

## 한 줄
1, 2, 3… 다음 숫자를 누가 먼저 — 동시에 누르면 둘 다 탈락.

## 왜 인기 (근거)
- **검증된 오프라인 포맷의 디지털화**: '눈치게임'은 한국 술자리·MT·예능(런닝맨/아는형님 등)에서 수십 년간 굴러온 국민 파티게임이다. 룰 설명 0초("순서대로 숫자 외치되 겹치면 죽음")로 누구나 즉시 이해한다.
- **휘발성 스낵에 최적**: 한 판 10~20초, 입장만 하면 바로 긴장감. 단톡방에 링크 하나 던지면 "야 눈치게임 ㄱㄱ" 식으로 즉석 모임이 성립한다.
- **멀티가 본질**: 혼자서는 성립 불가 — 타인의 타이밍을 읽는 '눈치'가 코어 재미라 2~8인 같은 링크 모델과 정확히 맞는다. 동시 입력 충돌이라는 긴장 구조가 라이브 멀티에서만 살아난다.
- **도발·재도전 루프**: 누가 먼저 죽었는지가 한눈에 보여 "ㅋㅋ 너 또 죽음" → '다시'로 무한 반복되는 휘발성 경쟁이 자연 발생.

## 세션 흐름 (화면별)
- **대기실(lobby)**: 제목 '눈치게임', 한 줄 룰("순서대로 1, 2, 3… 다음 숫자를 먼저 누르세요. 동시에 누르면 둘 다 탈락!"), 현재 입장한 사람 roster 리스트(닉네임 + 인원수 'N명 대기 중'), 호스트(또는 누구나)에게 보이는 **'시작하기'** 버튼. 2명 미만이면 '2명 이상 모이면 시작할 수 있어요' 안내로 시작 버튼 비활성.
- **카운트다운**: 전 클라 동기화된 3·2·1 풀스크린 카운트. 서버가 `sessionPhase=countdown` + `countdownEndsAt` 타임스탬프를 브로드캐스트하고, 클라는 onFrame으로 남은 초를 그린다.
- **플레이(play)**: **싱글라운드** (한 번의 play 페이즈에서 한 명의 최종 생존자가 가려지면 끝 — 라운드를 서버가 재발행하지 않음).
  - 화면 중앙에 거대한 **공동 상승 카운터**(현재 외쳐야 할 '다음 숫자' = `nextNumber`)와 그 아래 라임색 거대 **선점 버튼**('다음 숫자 누르기 — N').
  - 누구든 버튼을 탭하면 → 그 숫자를 선점. 서버가 같은 숫자에 대한 탭들을 **타임스탬프 충돌 윈도(예: 150ms)**로 묶어, 윈도 안에 2명 이상이 같은 숫자를 누르면 **그 인원 전원 탈락(eliminated)**, 정확히 1명만 누르면 그 사람이 그 숫자를 **선점 성공**하고 카운터가 +1 상승한다.
  - 라이브로 보이는 것: 현재 숫자, 살아있는 사람 / 탈락한 사람 roster(탈락자는 회색+취소선 'OUT'), 방금 누가 어떤 숫자를 선점/충돌했는지 짧은 토스트("민수 → 3 선점!", "지수·현우 동시 → 탈락!").
  - 생존자가 1명 남거나 더 누를 사람이 없으면 자동으로 result로 전환.
- **결과(result)**: 최후 생존자(승자) 크게 리빌('🏆 최후의 생존자: 민수'), 도달한 숫자(어디까지 셌나), 탈락 순서 리스트(누가 몇 번 숫자에서 죽었나). 동률/전원 동시 탈락 시 '승자 없음 — 모두 탈락 ㅋㅋ' 표시. **'다시'** 버튼 → 서버가 roster 리셋 없이 생존상태/카운터만 초기화하고 다시 countdown으로.

## 컨트랙트 매핑
- **주 컨트랙트 = `tap` (per-player 선점 이벤트 → 서버 충돌 판정)**. 점수판이 아니라 '누가 어떤 숫자를 언제 눌렀나'의 타임스탬프 집계가 핵심이라, score/tap 계열을 충돌-판정 변형으로 쓴다. 보조로 `roster`(누가 살아있나/탈락했나).
- **host event emit 타이밍**:
  - `start`: lobby에서 '시작하기' 탭 시 1회 emit → 서버가 `sessionPhase=countdown`, `countdownEndsAt` 브로드캐스트.
  - `tap`: play에서 선점 버튼 탭마다 emit. payload = `{ number: nextNumber, clientTs: $now }`. 서버는 같은 `number`에 대해 도착 타임스탬프를 **150ms 충돌 윈도**로 그룹핑 → (a) 단독이면 그 senderId를 `nextNumber` 선점자로 확정하고 `nextNumber+1`로 올린 뒤 `roundState`(현재 숫자·생존자·토스트) 브로드캐스트, (b) 2명 이상이면 해당 인원 전원을 `eliminated`에 추가하고 같은 숫자 유지(다음 생존자가 다시 도전) — 또는 룰 변형상 그 숫자는 '불탄 숫자'로 처리해 +1.
  - `vote` / `tally`: **사용 안 함**(이 게임은 단일 집계나 투표가 아니라 순차 선점 + 충돌 판정).
  - `score`: 직접 점수 누적은 없음. 대신 서버가 tap 충돌 판정 결과로 파생하는 '도달 숫자/생존 여부'만 broadcast.
- **라운드 필요 여부**: **불필요 (싱글라운드)**. `multiRound:false` — 한 play 페이즈에서 생존자가 1명으로 좁혀지면 종료. '다시'는 서버가 같은 roster로 생존상태·카운터만 리셋해 새 세션을 시작하는 것이지, 같은 세션 내 멀티라운드 진행이 아니다.

## 콘텐츠
- **서버 콘텐츠팩 불필요** — 이 게임의 '콘텐츠'는 1부터 오르는 정수 시퀀스(동적 생성)와 **roster 기반 참가자 닉네임**뿐이다. 외부 질문/매치업/후보/정답 팩이 없으므로 `roundContent` 브로드캐스트가 필요 없다.
- 서버가 권위적으로 들고 broadcast 하는 라이브 상태(`roundState`, 콘텐츠팩 아님) 제안 JSON:
```json
{
  "sessionPhase": "play",          // lobby | countdown | play | result
  "countdownEndsAt": 1750000000000,
  "nextNumber": 4,                  // 지금 눌러야 할 공동 상승 카운터 값
  "alive": ["민수", "지수"],          // 생존자 닉네임(roster 파생)
  "eliminated": [                    // 탈락자 + 죽은 숫자
    { "name": "현우", "diedAtNumber": 3 },
    { "name": "보라", "diedAtNumber": 3 }
  ],
  "lastEvent": { "type": "collision", "names": ["현우","보라"], "number": 3 },
  // type: "claim"(단독 선점) | "collision"(동시 탈락)
  "collisionWindowMs": 150,
  "winner": null                     // result에서만 채워짐. 전원탈락이면 "" (승자 없음)
}
```
- roster(닉네임)는 lobby 입장 시점에 확정되며, play/result 내내 alive/eliminated 분류의 소스로 쓰인다.

## 성공 기준
1. **충돌 판정 정확도**: 2개 이상 클라가 같은 숫자를 충돌 윈도(150ms) 안에 누르면 해당 전원이 모든 클라 화면에서 동시에 'OUT' 처리된다(누락·오판 0건).
2. **선점 진실성**: 정확히 1명이 누른 숫자는 그 사람 선점으로 확정되고 `nextNumber`가 모든 클라에서 +1 동기화된다(클라 간 카운터 불일치 0).
3. **싱글라운드 종결**: 생존자가 1명으로 좁혀지면(또는 전원 탈락) 모든 클라가 1초 내 동일한 result(같은 승자/같은 도달 숫자)로 전환된다.
4. **카운트다운 싱크**: 3·2·1이 전 클라에서 ±300ms 이내로 일치하게 끝나고 동시에 play로 진입한다.
5. **스낵 즉답성**: 선점 버튼 탭 → 본인 화면 피드백(눌림/대기 인디케이터)이 데드타임 없이 즉시 뜬다(서버 확정 전 낙관적 표시, 충돌 시 OUT으로 정정).

## QA 검증 시나리오 (멀티클라이언트)
3개 클라이언트(A·B·C, 같은 `/p/tpl-nunchi-tap` 링크)로 진행.

- **1단계 — 입장 / roster**: A, B, C가 순차로 링크를 연다.
  - PASS: 세 클라 모두 lobby에서 roster에 A·B·C 닉네임 3개가 보이고 'N명 대기 중'이 **3명**으로 일치. 2명 입장 시점에는 시작 버튼 활성, 1명일 때는 '2명 이상 모이면…' 비활성 안내가 보인다.
- **2단계 — 시작 / 카운트다운 싱크**: A가 '시작하기' 탭.
  - PASS: 세 클라가 거의 동시에 lobby → 3·2·1 카운트다운 화면으로 전환되고, 숫자가 같은 박자로 줄어 동시에 play로 진입(육안상 동시). 어느 클라도 lobby에 남아있지 않음.
- **3단계 — 정상 선점(단독 탭)**: play에서 카운터가 '1'. A만 선점 버튼을 누른다.
  - PASS: 세 클라 모두 카운터가 '2'로 오르고, 'A → 1 선점!' 토스트가 뜨며 A·B·C 전원 아직 alive(roster에 OUT 없음). B가 '2'를 단독으로 누르면 다시 모든 화면 카운터 '3', 'B → 2 선점!'.
- **4단계 — 동시 입력 충돌(코어)**: 카운터가 '3'일 때 B와 C가 거의 동시에(150ms 윈도 안) 선점 버튼을 누른다.
  - PASS: 세 클라 모두에서 B·C가 동시에 회색+취소선 'OUT'으로 바뀌고 'B·C 동시 → 탈락!' 토스트가 뜬다. alive에는 A만 남는다. 한쪽만 OUT 되거나 카운터가 어긋나면 FAIL.
- **5단계 — 결과 집계 / 다시**: 생존자가 A 1명으로 좁혀진 직후.
  - PASS: 세 클라 모두 result로 전환되어 '🏆 최후의 생존자: A', 도달 숫자(예: '3까지'), 탈락 순서(B·C가 3번에서 탈락) 리스트가 **동일하게** 보인다. A가 '다시'를 누르면 세 클라 모두 같은 roster(A·B·C) 유지한 채 생존상태·카운터 리셋 후 다시 카운트다운으로 진입한다(roster 재입장 불필요).
