# 연타 배틀 (멀티 · 세션)  —  id: tap-war-score

## 한 줄
3·2·1 후 10초 다 같이 연타 — 내 막대가 리더보드를 타고 오른다.

## 왜 인기 (근거)
- **0초 학습**: "10초 동안 누가 제일 빨리 연타하나"는 손가락만 빠르면 되는 검증된 캐주얼 포맷(CPS 테스트 / 탭 연타 스피드 테스트 계열). 설명 없이 누구나 즉시 참여.
- **단톡방 도발 루프**: 같은 링크 하나 던지고 "야 이거 누가 제일 빨라"로 바로 경쟁이 붙는다. 결과 비교 → 재도전 → 다시 도발의 휘발성 루프가 강력.
- **라이브 경주의 쾌감**: 카운트다운으로 전원이 동시에 출발하고, per-player 막대가 실시간으로 서로를 추월하는 장면 자체가 구경거리. 내 막대가 남의 막대를 제치는 순간이 스크린샷/공유 동기를 만든다.
- 이미 `tap-battle.bite.json`로 구현·검증 완료 (sessionPhase 모델 + raceBoard 라이브 막대 경주).

## 세션 흐름 (화면별)
- **대기실(lobby)**: 제목 '연타 배틀', ⚡ 라임 배지, 룰 안내('3·2·1 카운트 후 10초 동안 최대한 빠르게 연타'), 현재 입장자 roster(닉네임 칩 N명), 그리고 라임 **시작하기** 버튼. `sessionPhase === 'lobby'` 동안 노출.
- **카운트다운**: `sessionPhase === 'countdown'` 동안 화면 중앙에 **3 → 2 → 1** 큰 숫자(서버 broadcast `sessionCountdown` 값 바인딩). 전원 동일 타이밍에 시작하도록 동기화.
- **플레이(play)**: **싱글라운드** (한 번의 10초 play 페이즈, multiRound=false). 화면 하단~중앙 라임 거대 **TAP** 버튼을 연타. 매 탭마다 `myTaps`가 즉시 +1(snappy, 데드타임 0). 라이브로 보이는 것:
  - 내 연타 수(큰 숫자) + 격려 문구(구간별: 속도를 올려요→더 빠르게→상위권 페이스→미친 속도).
  - **per-player 라이브 막대 경주**: 서버가 setVar로 동기화한 `raceBoard`(닉네임+탭수 배열)를 막대 길이로 렌더. 내 막대와 남의 막대가 실시간으로 길어지며 순위가 바뀐다.
  - 남은 시간(10→0초) 카운트다운.
- **결과(result)**: `sessionPhase === 'result'` 진입 시 최종 `raceBoard`를 순위로 정렬해 표시 — 1위(👑 우승자 닉네임 + 탭수), 내 최종 기록·등수·CPS(초당 탭수). **다시** 버튼 → host event `start` 재emit → 서버가 다시 countdown으로 전환해 같은 멤버로 재대결.

## 컨트랙트 매핑
- **컨트랙트: `tap`** (per-player count → 서버가 named leaderboard `raceBoard`로 집계·broadcast). 보조로 **`roster`**(입장자 명단).
- **host event emit 시점** (검증된 `tap-battle.bite.json` 기준):
  - `start` `{ duration: 10000 }` — lobby에서 **시작하기** 클릭 시, 그리고 result에서 **다시** 클릭 시 emit. 서버가 countdown→play 진행과 10초 타이머·`raceBoard` 리셋을 주관.
  - `tap` — play 페이즈에서 TAP 버튼을 누를 때마다 emit. 서버가 해당 플레이어의 누적 탭수를 +1 하고 `raceBoard`를 setVar로 전체 동기화. (페이로드 불필요 — 플레이어 식별은 세션이 보유.)
- 클라이언트 상태 전환은 모두 서버 broadcast `sessionPhase`(+ `sessionCountdown`)를 `onFrame` 가드로 읽어 lobby/countdown/play/result를 표시. 클라이언트가 자체 타이머로 종료하지 않음(서버 권위).
- **라운드 필요 여부: 불필요(단일 라운드).** 라운드별 콘텐츠 재방송 없음.

## 콘텐츠
- **서버 콘텐츠팩 불필요.** vote/quiz류처럼 질문·매치업·정답 같은 server-authoritative `roundContent`가 없다. 게임의 모든 "콘텐츠"는 **roster 기반**(플레이어 닉네임)과 **각자의 실시간 탭수**로 동적 생성된다.
- 서버 권위 상태(broadcast vars):
```json
{
  "sessionPhase": "lobby | countdown | play | result",
  "sessionCountdown": 3,
  "roster": [ { "id": "p1", "name": "민지" }, { "id": "p2", "name": "준호" } ],
  "raceBoard": [
    { "id": "p2", "name": "준호", "taps": 87 },
    { "id": "p1", "name": "민지", "taps": 81 }
  ]
}
```
  - `raceBoard`는 매 `tap` 수신 시 갱신·정렬되어 setVar로 전체 동기화(라이브 막대 = `taps`를 max로 정규화한 길이).
  - 클라이언트 로컬 표시용 `myTaps`(내 탭수)는 즉답 UX를 위해 탭 시 로컬 +1, 서버 `raceBoard`가 진실 소스.
- 한국어 카피 톤(고정 문구, 콘텐츠팩 아님): 격려 문구 구간(속도를 올려요 / 더 빠르게 / 상위권 페이스 / 미친 속도예요), 단위 '회'·'초'·'위', 결과 CPS('초당 X회').

## 성공 기준
1. lobby/countdown/play/result 4개 페이즈가 390x844 한 화면 안에 겹침 없이 들어오고, 서버 `sessionPhase` 변경 시 모든 클라이언트가 같은 페이즈로 전환된다.
2. 카운트다운 3·2·1이 전 클라이언트에서 동기화되어(±1프레임 수준) 동시에 play로 진입한다.
3. TAP 연타가 즉각 반응 — 매 탭마다 내 숫자가 데드타임 없이 +1(snappy), 격려 문구가 구간 경계에서 정확히 전환된다.
4. per-player 라이브 막대(`raceBoard`)가 다른 플레이어의 탭에 따라 실시간으로 길이·순위가 바뀐다(멀티 진실성: 내 `tap`이 남의 화면 막대에 반영).
5. 10초 종료 시 서버 권위로 전원이 result로 전환되고, 우승자(최다 탭)와 내 등수·CPS가 정확히 계산되어 표시된다. **다시** → 같은 멤버로 countdown 재진입.

## QA 검증 시나리오 (멀티클라이언트)
3개 클라이언트(C1·C2·C3)로 같은 `/p/tpl-tap-war-score` 링크 접속.

- **STEP 1 — 입장 & roster**: C1·C2·C3 순서로 링크 진입.
  - PASS: 각 클라이언트 대기실에 roster 칩이 **3명**(세 닉네임 모두) 동일하게 보이고, **시작하기** 버튼이 노출된다. 늦게 들어온 C3에도 기존 2명이 즉시 보인다.
- **STEP 2 — 시작 & 카운트다운 싱크**: C1에서 **시작하기** 클릭.
  - PASS: 세 클라이언트 모두 거의 동시에 lobby가 사라지고 카운트다운 화면으로 전환, **3 → 2 → 1**이 함께 흐른 뒤 동시에 play로 진입한다(어느 한 클라이언트만 먼저 시작하지 않음).
- **STEP 3 — 플레이 입력 & 라이브 막대**: play 동안 C2를 가장 빠르게, C1을 중간, C3를 가장 느리게 연타.
  - PASS: 각 클라이언트에서 자기 숫자가 탭마다 즉시 오르고, **세 화면 모두**의 `raceBoard` 막대가 실시간으로 길어지며 C2 막대가 1위로 올라가고 C1·C3가 그 아래로 정렬된다(내가 안 누른 동안에도 남의 막대가 자라는 게 보임). 남은 시간이 10→0으로 함께 카운트다운된다.
- **STEP 4 — 결과 집계**: 10초 종료.
  - PASS: 세 클라이언트 모두 동시에 result로 전환, **우승자 = C2**(👑 + 최다 탭수)로 동일하게 표시되고, 각자 화면에는 자기 최종 등수(C2=1위, C1=2위, C3=3위)와 CPS(초당 회수)가 보인다. 순위·총탭수가 세 화면에서 일치한다.
- **STEP 5 (선택) — 다시**: 아무 클라이언트에서 **다시** 클릭.
  - PASS: 세 클라이언트가 같은 roster를 유지한 채 다시 카운트다운으로 진입하고, `raceBoard` 탭수가 0으로 리셋된다.
