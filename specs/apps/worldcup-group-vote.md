# 이상형 월드컵 (같이 보는 버전) (멀티 · 세션)  —  id: worldcup-group-vote

## 한 줄
매 대결마다 방 전체가 동시에 한 표 — 우리 방의 챔피언을 함께 뽑는다.

## 왜 인기 (근거)
- 이상형 월드컵은 한국 인터넷에서 10년 넘게 검증된 초강력 바이럴 포맷이다. "둘 중 하나만 골라"를 반복해 마지막 한 명으로 좁혀지는 토너먼트의 정리되는 쾌감이 핵심.
- 기존 이상형 월드컵은 '내 취향 1인용'이라 끝나면 혼자 본다. 이 버전은 같은 링크를 연 2~8명이 매 매치업마다 동시에 투표해 "우리 방의 우승자"를 만든다 — 결과가 '나'가 아니라 '우리'라서 비교/논쟁/공유 욕구가 즉시 발생한다.
- 매 매치마다 라이브 % 막대가 움직여 "내 픽이 다수파인가?"를 실시간으로 보여준다(this-or-that의 검증된 라이브 폴 쾌감 + 토너먼트 구조 결합).
- 입력이 '탭 한 번'뿐이라 진입 장벽 0, 한 세션 60~90초로 휘발성 스낵에 정확히 맞는다.

## 세션 흐름 (화면별)
- **대기실(lobby)**: 방 제목('이상형 월드컵 · 같이') + 현재 주제 라벨 + 입장한 사람들의 roster(닉네임/색 도트, N명 표시) + 라임 `시작하기` 버튼. 시작은 누구나 누를 수 있고, 누르면 전원이 카운트다운으로 동시 전환된다.
- **카운트다운**: 화면 중앙 큰 숫자 3·2·1 (서버 타임드, 전 클라이언트 동기). "곧 1번째 대결!" 서브카피.
- **플레이(play)**: **멀티라운드**. 한 세션이 16강→8강→4강→결승→우승까지 여러 매치업 라운드를 돈다. 서버가 현재 매치업(후보 2명: 이미지+이름)을 `roundContent`로 브로드캐스트 → 좌/우(또는 상/하) 두 후보 카드로 표시. 각 클라이언트는 라운드 카운트다운(예 5초) 안에 한쪽을 탭해 한 표(일인일표). 화면 라이브 요소: (1) 내 픽 카드가 라임 하이라이트, (2) 두 후보 아래 라이브 % 막대가 방 전체 표로 실시간 갱신, (3) "N명 중 M명 투표함" 진행 뱃지, (4) 라운드 라벨('16강 · 3번째 대결'). 라운드 타이머가 끝나면 서버가 다득표 후보를 승자로 확정·승격하고 패자 탈락 → 다음 매치업을 새 `roundContent`로 브로드캐스트(per-round tally 리셋). 16→8→4→2→1로 좁혀진다.
- **결과(result)**: '🏆 우리 방의 챔피언' + 우승자 큰 이미지 + 이름 + "방 N명이 함께 뽑음" + (선택) 결승 매치 최종 % 리빌. 라임 `다시` 버튼 → 누르면 전원이 다시 카운트다운으로 복귀하고 서버가 새 브래킷(다음 콘텐츠팩 또는 셔플)을 시드한다.

## 컨트랙트 매핑
- **주 컨트랙트 = vote** (일인일표 매치업 폴). 매 매치업마다 서버가 `votesByOption`(후보키→표수)을 집계·브로드캐스트.
- **roster**: lobby 입장자 명단(누가 들어왔나, N명) 유지. 매치 진행 뱃지("N명 중 M명 투표")의 분모로도 사용.
- host event emit 타이밍:
  - `start`: lobby에서 `시작하기` 탭 시 1회. 서버가 COUNTDOWN→PLAY로 sessionPhase 진행 + 첫 `roundContent`(1번째 매치업) 브로드캐스트.
  - `vote`: play에서 후보 카드 탭마다. payload = {round, optionKey}. 같은 사람 재탭 시 표 교체(일인일표). 서버가 현재 라운드 `votesByOption` 갱신·브로드캐스트.
  - `tally`/`score`/`tap`: 사용 안 함(이 게임은 순수 vote).
- **라운드 필요: 예 (MULTI-round).** 서버가 라운드를 진행한다: 라운드 타이머 만료 시 다득표 후보를 winners에 누적, 다음 매치업으로 `roundContent` 재브로드캐스트, per-round `votesByOption`를 리셋. roundSize가 2가 되면(결승) 우승자 확정 후 RESULT phase로 전환. 동률 처리는 서버 규칙으로(선착 다수/랜덤 타이브레이크).

## 콘텐츠
- **서버 권위 콘텐츠팩(SERVER-AUTHORITATIVE).** 후보 풀과 매치 배정을 서버가 들고 `roundContent`로 매 라운드 동일하게 브로드캐스트 → 모든 클라이언트가 같은 매치업을 본다(클라가 후보를 자체 선택하지 않음).
- **roster 기반 아님**(후보는 플레이어가 아니라 콘텐츠팩의 인물/사물). 단 진행 뱃지·"방 N명"에만 roster를 쓴다.
- 필요한 콘텐츠: 같은 주제의 후보 16명(이미지 + 이름). 외모/대상으로 고르는 포맷이라 **이미지 진실성 필수**(이름과 실제로 일치하는 사진, generic 폴백 얼굴 금지).
- 제안 JSON 형식(콘텐츠팩):
```json
{
  "packId": "worldcup-group-vote-2026w26",
  "theme": "국민 첫사랑상",
  "bracketSize": 16,
  "candidates": [
    { "key": "c01", "name": "후보 이름", "img": "https://.../real-photo.jpg", "imgQuery": "Wikipedia 문서 제목" }
  ]
}
```
- 라운드별 서버 브로드캐스트(`roundContent`) 형식:
```json
{
  "round": 1,
  "roundLabel": "16강 · 1번째 대결",
  "roundSize": 16,
  "matchIndex": 0,
  "deadlineTs": 1719300000000,
  "optionA": { "key": "c01", "name": "...", "img": "..." },
  "optionB": { "key": "c07", "name": "...", "img": "..." }
}
```
- 이미지 소스 규칙: 명명된 실존 인물은 Wikipedia 문서 thumbnail 우선 해상, 미해상 시 이니셜/실루엣 플레이스홀더(이름과 무관한 가짜 얼굴 금지). 콘텐츠는 LLM이 KST 정시마다 신선한 후보 16명 생성 가능(주제 회전).

## 성공 기준
- 2~8명이 같은 `/p/tpl-worldcup-group-vote` 링크로 한 방에 모이고 lobby roster N이 실제 입장 수와 일치한다.
- `시작하기` 후 전 클라이언트가 ±0.5초 내 같은 숫자로 3·2·1 카운트다운을 본다(서버 타임드 싱크).
- 매 매치업에서 후보 탭→내 픽 라임 하이라이트가 데드타임 없이 즉시, 두 후보 % 막대 합이 항상 ≈100%이고 다른 사람 표가 추가 탭 없이 실시간 반영된다.
- 라운드 진행이 16강→8강→4강→결승으로 정확히 줄고(roundSize/라벨 일치), per-round 표가 라운드마다 0부터 다시 집계된다.
- 결승 후 전 클라이언트가 동일한 우승자(이미지+이름)와 "방 N명이 함께 뽑음"을 보고, `다시`가 전원을 새 브래킷의 카운트다운으로 복귀시킨다.
- 후보 이미지가 이름과 일치하는 실제 대상이고, 16명이 매 대결 서로 다르게 보인다(같은 얼굴 반복 금지).

## QA 검증 시나리오 (멀티클라이언트)
3 클라이언트(A=시작 주체, B, C)로 검증.

1. **입장 → roster 동기**: A·B·C가 같은 링크를 연다.
   - PASS: 세 기기 모두 lobby에서 roster 인원이 '3명'으로 같게 보이고, 늦게 들어온 C가 보일 때 A·B 화면 roster도 추가 탭 없이 3명으로 갱신된다.
2. **시작 → 카운트다운 싱크**: A가 `시작하기` 탭.
   - PASS: 세 기기가 거의 동시에 lobby를 벗어나 동일 숫자(3→2→1)로 카운트다운을 표시하고, 동시에 1번째 매치업(같은 후보 2명) play 화면으로 진입한다(세 기기 후보 이름/이미지가 동일).
3. **플레이 입력 → 라이브 집계(일인일표)**: 1번째 매치업에서 A·B가 optionA를, C가 optionB를 탭.
   - PASS: 각자 탭한 카드가 자기 화면에서 라임 하이라이트되고, 세 기기 모두 optionA 약 67% / optionB 약 33% 막대와 "3명 중 3명 투표"를 동일하게 본다. C가 마음 바꿔 optionA 재탭 시 총표는 3 그대로(일인일표 교체), 비율이 A 100%로 재계산되어 세 기기에 반영.
4. **라운드 진행 → 리셋·승격**: 라운드 타이머 만료.
   - PASS: 세 기기가 동시에 다득표 후보를 승자로 표시 후 다음 매치업으로 전환되고, 라벨이 '16강 · 2번째 대결'로 증가하며 % 막대가 모두 0%로 리셋된다(per-round tally 초기화). 8경기 후 라벨이 '8강 · 1번째'로 올라간다.
5. **결과 집계 → 다시**: 결승까지 진행해 우승자 확정.
   - PASS: 세 기기가 동일한 우승자 이미지+이름과 "방 3명이 함께 뽑음"을 보고, 누구든 `다시`를 누르면 세 기기가 함께 카운트다운으로 복귀해 새 브래킷 1번째 매치업으로 재시작한다(이전 표/우승자 상태가 깨끗이 초기화됨).
