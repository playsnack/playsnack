# 빨리 누르기 대결 `race-tap`  ·  game

**Verdict:** needs-fix  ·  **Mode:** multi (live-race / shared leaderboard tally — 같은 링크의 모든 플레이어가 각자 10초 기록을 emitHostEvent로 제출하고 서버가 leaderboard 배열을 setVar로 전체 동기화, result 화면의 LIVE TOP 10에서 실시간 비교)

## 주제 매력도
"10초 안에 누가 더 빨리 연타하나" 대결은 누구나 0초 학습으로 즉시 참여 가능한 검증된 캐주얼 포맷이다(터치 회수 측정 = cps test / "탭 연타" 미니게임 계열). 한국 단톡방·친구모임에서 링크 하나 던지고 "야 이거 누가 제일 빨라" 식으로 바로 경쟁이 붙는 주제라 매력적이다. 현재 콘텐츠 자체는 충분히 좋다. 더 끌어올리려면 결과 화면에서 "초당 탭수(CPS)"와 "전체 중 상위 몇%" 같은 자랑거리 수치를 한 줄 추가하면 공유 동기가 강해진다.

## 레퍼런스 (검증된 인기 포맷 모방)
- **모방 대상:** CPS Test / 탭 연타 스피드 테스트 (10-second click speed test)
- **구조 100% 복제:** 표준 클릭/탭 스피드 테스트 룰을 100% 모방: (1) 시작 버튼 → (2) 고정 시간(10초) 카운트다운 동안 한 영역을 최대한 연타 → (3) 시간 종료 시 자동으로 총 탭수 집계·표시 → (4) 리더보드/순위로 비교 → (5) 재도전. 시간 고정·탭수 누적·자동 종료·기록 비교의 흐름이 핵심.
- **우리 콘텐츠/디자인:** 콘텐츠: 한국어 격려 문구 단계(속도를 올려요→좋아요 더 빠르게→상위권 페이스→미친 속도예요), '점'/'초' 한국식 단위, '같은 링크의 모두가 10초 승부' 멀티 카피. 디자인: 블랙(#0b0c0e/#16181c) 배경 + 라임(#d9ff00) 거대 원형 TAP 버튼, 글로우 드롭섀도, iOS 카드 톤.

## 목적
친구들과 같은 링크에 모여 10초 동안 누가 가장 빨리 화면을 연타하는지 겨루는 즉석 스피드 대결. 머리 안 쓰고 손가락만 빠르면 되는 0초 학습 스낵으로, 단톡방에 링크 하나 던지면 바로 경쟁·도발·재도전 루프가 생기는 휘발성 재미를 준다.

## 핵심 루프
10초 카운트다운 동안 라임색 거대 TAP 버튼을 최대한 빠르게 연타 → 종료 시 점수가 실시간 공용 리더보드에 자동 제출 → 순위 확인 후 다시 도전.

## 시나리오
1. 사용자가 링크를 열면 ready 화면: 제목 '빨리 누르기 대결', ⚡ 라임 배지, '10초 동안 최대한 빠르게 탭하세요' 안내와 '시작하기' 버튼이 보인다.
2. '시작하기'를 누르면 → score=0, startedAt=$now 세팅 후 play 상태로 전환, 내 점수 0점 / 남은 시간 10초 표시.
3. 사용자가 거대 TAP 버튼을 연타하면 → 매 탭마다 score+1, 내 점수 카드 숫자가 즉시 증가하고 격려 문구(속도를 올려요→…→미친 속도예요)가 점수 구간 따라 바뀐다.
4. 매 프레임마다 남은 시간이 줄어들어 timerCard가 9초·8초…로 카운트다운된다.
5. 경과 시간이 10초(duration)에 도달하면 → best 갱신, emitHostEvent로 score 서버 제출, result 상태로 자동 전환.
6. result 화면: 이번 기록(finalScore), 예상 등수, '🏆 TOP 10' LIVE 리더보드(서버가 setVar로 동기화한 leaderboard 배열)가 표시된다.
7. '다시 도전하기'를 누르면 → score 리셋·play로 재진입해 다시 10초 승부. 다른 플레이어가 새 기록을 내면 리더보드가 실시간 갱신된다.

## 성공 기준
- ready/play/result 3개 화면이 겹침 없이 화면(390x844) 안에 들어오고, flex column 패딩·gap이 의도대로 정렬된다.
- TAP 연타가 즉각 반응: 매 탭마다 내 점수 숫자가 데드타임 없이 1씩 오른다(snappy).
- 타이머가 실제로 10→0으로 카운트다운되고 0초 도달 시 자동으로 result로 넘어간다.
- 격려 문구가 점수 구간(25/50/80)에 맞춰 정확히 바뀐다.
- result의 리더보드가 서버에서 받은 실제 점수로 채워지고, 비어있을 땐 '첫 기록을 기다리는 중' 안내가, 채워지면 emptyBoard가 숨겨진다.
- 멀티 진실성: 내가 낸 점수가 emitHostEvent로 제출돼 같은 링크의 다른 사람 화면 리더보드에도 반영된다.
- 블랙+라임 톤이 일관되고 라임 TAP 버튼이 명확한 1차 타겟으로 읽힌다.

## QA 검증 시나리오
- [ ] **QA1** 시작하기 버튼 클릭 시 play 상태로 전환되는가 → `ready 숨김, play 표시, 내 점수 0점 / 남은 시간 10초 노출`
- [ ] **QA2** TAP 버튼(tapBtn 컨테이너)을 연타할 때 score가 실제 증가하는가 → `매 탭마다 scoreCard.value가 1점씩 즉시 증가`
- [ ] **QA3** timerCard가 실시간으로 카운트다운되는가 → `onFrame 바인딩으로 '남은 시간'이 10초→0초로 매끄럽게 감소`
- [ ] **QA4** 10초 경과 시 자동 종료되는가 → `$now-startedAt>=10000 도달 시 result 상태로 자동 전환, finalScore에 내 점수 표시`
- [ ] **QA5** 격려 문구(comboText)가 점수 구간에 맞게 바뀌는가 → `score 25/50/80 경계에서 '좋아요 더 빠르게'/'상위권 페이스'/'미친 속도예요'로 변경`
- [ ] **QA6** 리더보드 repeat가 서버 leaderboard 배열을 렌더하는가 → `leaderList가 각 항목을 'N위 / X점' 행으로 표시, $index+1과 $item 정상 평가`
- [ ] **QA7** 빈 리더보드 처리 → `leaderboard.length===0일 때 emptyBoard 표시('첫 기록을 기다리는 중'), 데이터 있으면 숨김`
- [ ] **QA8** emitHostEvent score 페이로드가 실제 점수 값을 보내는가 → `payload.score가 score 변수 값(숫자)으로 평가돼 전송 — 문자열 'score' 리터럴이 아니라 변수값`
- [ ] **QA9** 다시 도전하기 클릭 시 재시작 → `score 0 리셋, startedAt 갱신, play 재진입`
- [ ] **QA10** 모든 텍스트가 겹치지 않고 화면 안에 들어오는가 → `readyTitle 2줄·playTip 2줄·리더보드 행이 잘리거나 겹치지 않음`

## 현재 깨짐 (진단)
- **[high]** emitHostEvent의 payload.score가 변수 평가가 아니라 문자열 리터럴 'score'로 전송될 위험. payload 값은 expr이 아닌 raw 값으로 처리될 수 있어 서버에 점수 숫자 대신 "score" 문자열이 들어가면 리더보드가 깨진다.
  - 근거: race-tap.bite.json:596-601 — "emitHostEvent","name":"score","payload":{"score":"score"}. 다른 응답들(setVar expr)은 표현식으로 평가되지만 payload는 평가 보장이 불명확. result 화면 스크린샷이 없어 실제 리더보드 채워짐을 확인 불가.
  - 수정: payload 값이 표현식으로 평가되는지 런타임 계약 확인 후, 평가 안 되면 명시적 expr 형태(예: {"score":{"expr":"score"}}) 또는 런타임이 요구하는 포맷으로 수정. result 화면을 실제 캡처해 leaderList가 채워지는지 검증.
- **[medium]** play 화면 스크린샷이 정지 상태(0점/10초)라 타이머 카운트다운과 점수 증가가 실제로 동작하는지 정적 검증 불가. onFrame 기반 타이머·자동종료가 런타임에서 실제 틱하는지 확인 필요.
  - 근거: race-tap-2.png와 race-tap-3.png가 바이트 동일(123582) = 동일 프레임. 둘 다 '0점/10초'로 시간 경과·연타 반영이 캡처되지 않음. play.bindings의 timerCard.value(564행), score 트리거(572-579행)는 코드상 올바르나 실행 증거 부재.
  - 수정: play 진행 중(예: 3초 경과+연타 후) 스크린샷을 새로 캡처해 timerCard 감소·scoreCard 증가·comboText 변경을 눈으로 확인. result 화면도 함께 캡처.
- **[medium]** result 화면 미검증 — 리더보드/순위/finalScore 레이아웃이 실제로 안 깨지고 채워지는지 확인된 바 없음. leaderboardCard(height:fill) 안에 emptyBoard와 leaderList가 공존하는데 둘 다 표시되거나 정렬이 어긋날 가능성.
  - 근거: 제공된 스크린샷 3장 모두 ready/play뿐, result 캡처 없음. result.bindings(613-620행)에 emptyBoard.visible 토글은 있으나 leaderList와의 시각적 공존 결과 미확인.
  - 수정: result 상태 스크린샷 캡처. 리더보드 데이터 0개/여러개 두 경우 모두 검증해 emptyBoard와 leaderList가 배타적으로 보이는지 확인.
