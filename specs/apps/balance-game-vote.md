# 밸런스게임 (멀티 · 세션)  —  id: balance-game-vote

## 한 줄
둘 중 절대 못 고르는 선택지 — 다 같이 고르고 갈라진 %로 소수파가 드러난다.

## 왜 인기 (근거)
밸런스 게임(딜레마 양자택일)은 한국에서 검증된 초강력 소셜 포맷이다. "평생 하나만", "둘 중 하나 포기" 류 질문은 카톡·인스타 스토리 투표 스티커·유튜브에서 끝없이 소비된다. 정답이 없어 실력/진입장벽이 0이고, 핵심 동력은 **"남들은 뭘 골랐을까 / 나만 이래?"**라는 호기심이다. 같은 방의 2~8명이 동시에 한쪽을 고르고 %가 50:50에 가깝게 팽팽히 갈릴수록 "헐 반반이네", "나 소수파였어"의 재미가 폭발한다. 멀티 세션에서는 **다수파/소수파 리빌**이 즉석 공감/반전 이벤트가 되어, 여러 라운드를 같이 도는 짧은 단톡방 놀이로 딱 맞는다.

## 세션 흐름 (화면별)
- **대기실(lobby)**: 방 제목("밸런스게임")과 입장한 사람들의 **roster(닉네임 + 현재 N명)**가 보인다. 방장(첫 입장자) 화면에는 **시작하기** 버튼이 활성, 나머지는 "기다리는 중…" 상태. 누군가 들어오면 roster가 실시간으로 늘어난다(서버 roster broadcast).
- **카운트다운**: 시작하기 누르면 전원 화면이 동시에 **3 · 2 · 1** 큰 숫자로 카운트(서버 broadcast `sessionPhase=countdown`, 클라는 onFrame 가드로 숫자 전환). 0이 되면 PLAY로.
- **플레이(play)**: **멀티라운드**. 매 라운드 서버가 `roundContent`(질문 + A/B 두 선택지)를 broadcast → 전원 같은 딜레마를 본다. 화면 = 상단 질문 헤더 + A/B 두 개의 큰 풀스크린 절반 탭 타깃 + 라운드 표시("1 / 5"). 한쪽을 탭하면 즉시 내 픽이 **라임으로 하이라이트**되고 `emitHostEvent('vote')` 전송, 하단에 **라이브 % 막대 두 개**가 실시간으로 차오른다(다른 사람 표가 들어오면 추가 탭 없이 비율이 움직임). 우상단에 **투표 진행 N/전체 N**(누가 아직 안 골랐는지) 표시. 전원 투표 완료 또는 서버 라운드 타이머(예 8초) 만료 시 RESULT로.
- **결과(result)**: 이번 라운드 **최종 비율**(예 64% vs 36%)과 **다수파/소수파 리빌**("당신은 소수파! 28%"), 그리고 가능하면 닉네임 칩으로 어느 쪽에 누가 갔는지 짧게 보여준다. 하단에 **다음 딜레마**(다음 라운드 있으면) / **다시**(마지막 라운드면 처음으로). 다시 = 서버에 `start` 재emit → 카운트다운으로 복귀하고 라운드 인덱스·tally 초기화.

## 컨트랙트 매핑
- **컨트랙트 = `vote`** (한 사람 한 표, 라운드별 1표 보장, 변경 시 이전 표 차감). 라운드별 `votesByOption`(A/B 카운트)을 setVar로 전원 broadcast → 막대 실시간 동기화.
- **`start`**: 방장이 lobby에서 시작하기 탭 또는 result에서 다시 탭 → emit. 서버는 `sessionPhase=countdown`→`play`로 전이, 라운드 인덱스 0으로 리셋, 첫 `roundContent` broadcast.
- **`vote`**: play 화면에서 A 또는 B 카드 탭 시 emit (payload: 선택 옵션 'A'/'B', 현재 roundIndex). 서버가 (방·유저·라운드) 단위로 합산, 같은 라운드 재탭이면 이전 표 차감 후 재집계. 갱신된 `votesByOption` broadcast.
- **라운드 진행**: 전원 투표 완료 또는 라운드 타이머 만료 시 서버가 `sessionPhase=result` broadcast(이 라운드 막대 freeze + 리빌). 방장 다음 딜레마 탭(또는 자동 진행) → 서버가 `roundIndex++`, 다음 `roundContent` broadcast + `votesByOption` 0으로 리셋 + `sessionPhase=countdown`(짧게) 또는 바로 `play`.
- **라운드 필요 여부**: **필요(멀티라운드)**. 한 세션에서 4~6개 딜레마를 순차 진행. tally/score/tap 컨트랙트는 사용 안 함.

## 콘텐츠
**서버 콘텐츠팩(서버 권위, `roundContent`로 라운드마다 broadcast)** — 모든 클라가 같은 질문/매치업을 보장하기 위해 클라가 아니라 서버가 보유.

```json
{
  "packId": "balance-kr-v1",
  "title": "밸런스게임",
  "rounds": [
    {
      "id": "q1",
      "question": "평생 하나만 가능하다면?",
      "optionA": { "key": "A", "label": "매일 1시간 더 자기", "emoji": "😴" },
      "optionB": { "key": "B", "label": "매일 1시간 더 놀기", "emoji": "🥳" }
    },
    {
      "id": "q2",
      "question": "연애할 때 더 힘든 건?",
      "optionA": { "key": "A", "label": "연락 안 되는 사람", "emoji": "📵" },
      "optionB": { "key": "B", "label": "집착하는 사람", "emoji": "🔒" }
    }
  ]
}
```

- 필드: `packId`, `title`, `rounds[]`(각 `id`/`question`/`optionA{key,label,emoji}`/`optionB{...}`). 정답 없음(취향 딜레마).
- broadcast되는 `roundContent` = 현재 라운드 객체 + `roundIndex` + `totalRounds`.
- **콘텐츠 큐레이션 원칙**: 50:50으로 팽팽히 갈리는 KR 공감·논쟁형(연애·돈·인간관계·소름 딜레마, 신조어 결합)을 우선. 보완재(같이 쓰는 것)는 대립 긴장감이 약하므로 배제. roster 기반 콘텐츠 아님(고정/동적 콘텐츠팩).
- 동적 옵션: dataSource→/api/content로 정시 갱신된 딜레마 팩을 받을 수 있음(기존 dynamic content system 규칙 준수).

## 성공 기준
1. A/B 카드 탭 시 데드타임 없이 내 픽이 라임으로 즉시 하이라이트되고 `emitHostEvent('vote')`가 전송된다(snappy).
2. 라이브 % 막대 두 개의 합이 항상 ≈100%이고, 다른 참여자 표가 추가 탭 없이 내 화면 비율에 실시간 반영된다(가짜/고정 0% 금지).
3. 2~8명이 같은 라운드에서 **동일한 질문/선택지**를 본다(서버 권위 `roundContent` 동기화 검증).
4. result에서 다수파/소수파 리빌 % 가 실제 서버 집계와 일치하고, 같은 라운드 재투표 시 중복 집계되지 않는다(1인 1표).
5. 멀티라운드가 끊김 없이 진행되고(N/전체 라운드 표시 정확), 마지막 라운드 후 **다시**로 라운드·tally가 초기화되어 루프가 닫힌다.

## QA 검증 시나리오 (멀티클라이언트)
3개 클라이언트(C1=방장, C2, C3)로 검증.

- [ ] **QA1 입장 → roster** — C1, C2, C3가 같은 `/p/tpl-balance-game-vote-…` 링크로 순차 입장 → **PASS 조건: 세 화면 모두 대기실 roster에 닉네임 3개와 "3명"이 보이고, 마지막 입장 직후 1초 내 동기화된다. C1 화면에만 시작하기 활성.**
- [ ] **QA2 시작 → 카운트 싱크** — C1이 시작하기 탭 → **PASS 조건: 세 화면이 거의 동시에(±1프레임 체감) 3·2·1 카운트다운을 같이 표시하고, 0 후 셋 다 play 화면(같은 질문 q1, 같은 A/B 라벨)으로 전환된다.**
- [ ] **QA3 플레이 입력 + 라이브 집계** — C1·C2가 A를, C3가 B를 탭 → **PASS 조건: 각 클라에서 자기 픽 카드가 라임으로 강조되고, 세 화면 모두 하단 막대가 A 67% / B 33%(2:1)로 동일하게 갱신, 합 100%. 우상단 "3/3 투표 완료" 표시.**
- [ ] **QA4 재투표(1인1표)** — C3가 A로 바꿔 탭 → **PASS 조건: 세 화면 모두 A 100% / B 0%로 재계산(C3의 B 표 차감, A로 이동). 총 표수는 여전히 3(중복 집계 없음).**
- [ ] **QA5 결과 집계 → 리빌** — 전원 투표 완료/타이머 만료 → **PASS 조건: 세 화면이 result로 전환되어 최종 비율과 다수파/소수파 리빌이 일치(예 C3 화면 "당신은… A, 다수파 100%")하고, A/B 어느 쪽에 누가 갔는지 닉네임 칩이 맞게 표시된다.**
- [ ] **QA6 다음 라운드 / 다시** — C1이 다음 딜레마 탭 → **PASS 조건: 세 화면이 새 질문(q2)으로 동시 전환, 막대 0%로 리셋, 라운드 표시 "2/N". 마지막 라운드에서 다시 탭 시 카운트다운으로 복귀하고 roster·라운드·tally가 초기화된다.**
