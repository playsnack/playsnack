# 초성 퀴즈 `quiz-choseong`  ·  quiz

**Verdict:** broken  ·  **Mode:** single

## 주제 매력도
초성 퀴즈(주어진 자음 초성을 보고 단어 맞히기)는 한국 모바일에서 검증된 국민 포맷이다 — 카카오톡 단톡방, 유튜브/틱톡 챌린지, 아이엠그라운드식 놀이로 누구나 즉시 이해한다. 진입 장벽 0, 정답을 맞히면 즉각 쾌감, 틀리면 '아 그거였네' 하는 미련까지 — 짧고 휘발성 강한 스낵에 최적이다. 현재 주제는 '동물/과일/장소' 등 일반 상식 위주인데, 더 끌리는 방향은 KR 트렌드 콘텐츠(요즘 밈/신조어, 아이돌·드라마 제목, 먹방 음식, 줄임말 'ㄱㅇㅇ=귀여워' 류)다. 단 신조어는 정답이 갈릴 수 있어 검증 가능한 고유명사/사물 중심을 유지하되 '요즘말' 1~2문제를 섞는 게 매력적이다.

## 레퍼런스 (검증된 인기 포맷 모방)
- **모방 대상:** 유명 초성 퀴즈 게임 (아카네코 초성게임 / 카카오 초성퀴즈 류 4지선다 버전)
- **구조 100% 복제:** 검증된 룰 100% 모방: (1) 화면 중앙에 큰 초성(자음만) 제시, (2) 짧은 힌트 한 줄, (3) 4지선다 보기 탭, (4) 탭 즉시 정답/오답 피드백 + 점수 가산, (5) 다음 문제로 진행, (6) N문제 후 점수 결과 화면 + 다시하기. 진행 흐름(문제→선택→즉시판정→다음→결과)을 그대로 따른다.
- **우리 콘텐츠/디자인:** 콘텐츠는 우리가 새로 채운 한국어 초성 문항 5개(정답+그럴듯한 오답 보기). 디자인은 우리 톤: 블랙(#0b0c0e) 배경 + 라임(#d9ff00) 강조, 초성은 라임 대형 타이포, 정답=라임/오답=레드(#ff6b6b) 피드백. iOS componentDef(NavBar/StatCard/OptionCard/Chip/Button) 재사용.

## 목적
초성 두세 글자만 보고 '이게 뭐지?'를 순간적으로 추리하는 한국식 두뇌 스낵. 신호등 멈춘 30초, 엘리베이터 기다리는 동안 5문제 빠르게 풀고 '나 몇 점?' 확인하는 재미. 맞히면 즉각 쾌감, 틀리면 정답 공개로 미련 남겨 한 판 더 돌리게 만든다.

## 핵심 루프
중앙의 초성+힌트를 보고 4개 보기 중 하나를 탭하면 즉시 정답/오답 판정과 점수 가산이 뜨고, '다음 문제'로 넘어가 5문제 뒤 결과를 본다.

## 시나리오
1. 사용자가 앱을 연다 → 첫 문제(초성 'ㄱㄹ', 힌트 '목이 아주 긴 동물')와 4개 보기 카드(기린/구름/가루/고리)가 보인다. 상단에 문제 1/5, 점수 0점.
2. 사용자가 정답이라 생각하는 카드 '기린'을 탭한다 → 즉시 피드백 텍스트가 '정답이에요! +1점'(라임색)으로 바뀌고 점수 카드가 1점으로 증가, 선택한 카드가 라임 강조된다.
3. 사용자가 '다음 문제' 버튼을 탭한다 → 초성/힌트/보기 4개가 2번 문제(ㅂㄴㄴ/노란색 과일/바나나·비누눈·분노나·보너느)로 전부 교체되고 진행이 2/5로, 피드백이 기본 안내문으로 리셋된다.
4. 오답을 탭한 경우 → 피드백이 '아쉬워요. 정답은 OO예요'(레드색)로 뜨고 점수는 오르지 않는다.
5. 3~5번 문제를 같은 방식으로 반복한다 → 매 문제마다 보기·초성·힌트가 갱신되고 점수/진행이 누적 표시된다.
6. 5번 문제를 답한 뒤 버튼이 '결과 보기'로 바뀐다 → 탭하면 결과 화면으로 전환된다.
7. 결과 화면에 'X / 5 정답'과 점수 구간별 칭호(초성 마스터/좋은 감각/다시 도전), 트로피 배지가 표시된다.
8. '다시 풀기'를 탭한다 → index·score·selected·answered가 초기화되고 1번 문제부터 다시 시작된다.

## 성공 기준
- 초성 대형 타이포가 라임색으로 한눈에 읽히고, 힌트·보기·점수 모두 화면 안에서 겹침 없이 정렬된다
- 보기 카드를 탭하는 즉시(데드타임 0) 정답/오답 피드백 색과 문구가 바뀐다 (snappy)
- '다음 문제'를 누르면 초성·힌트·보기 4개·진행·피드백이 모두 새 문제 내용으로 동시에 갱신된다
- 점수 카드와 진행 카드(N/5)가 실제 진행에 따라 숫자가 변한다
- 퀴즈 정답이 콘텐츠 진실: 초성이 정답 단어의 실제 자음과 일치하고(예 ㄱㄹ=기린의 ㄱ·ㄹ), 힌트가 정답을 가리키며, answer 인덱스가 옳은 보기를 가리킨다
- 5문제 후 결과 화면이 정확한 점수와 구간 칭호로 뜨고, 다시 풀기로 처음부터 재시작된다

## QA 검증 시나리오
- [ ] **QA1** 보기 카드 opt0~opt3 4개 모두 탭에 반응하는가 (click 트리거 존재) → `4개 모두 탭 시 selected/score/answered가 세팅되고 피드백이 갱신됨 (구조상 트리거 4개 정의됨, 동작 확인 필요)`
- [ ] **QA2** 보기 카드를 탭하면 점수 카드 값이 실제로 증가/표시되는가 → `정답 탭 시 점수 카드가 0점→1점으로 변경. 실측: 변하지 않음(FAIL, currentBreakage 참조)`
- [ ] **QA3** '다음 문제' 탭 시 보기 4개(opt0~opt3 label)가 새 문제 보기로 교체되는가 → `Q2에서 보기가 바나나/비누눈/분노나/보너느로 바뀜. 실측: 기린/구름/가루/고리 그대로(FAIL)`
- [ ] **QA4** 진행 카드(문제 N/5)가 다음 문제 진행 시 1/5→2/5로 변하는가 → `index 증가에 따라 갱신. 실측: 1/5 고정(FAIL)`
- [ ] **QA5** 텍스트가 겹치지 않고 화면 390x844 안에 들어오는가 → `NavBar/StatCard 2개/questionCard/보기 2x2/버튼이 세로 flex로 겹침 없이 배치 (PASS - 스크린샷상 양호)`
- [ ] **QA6** 초성이 정답 단어의 실제 자음과 일치하는가 → `ㄱㄹ=기린(ㄱ,ㄹ)✔, ㅂㄴㄴ=바나나(ㅂ,ㄴ,ㄴ)✔, ㅎㄱ=학교(ㅎ,ㄱ)✔, ㅋㅍ=커피(ㅋ,ㅍ)✔ 단 보기 '카페'도 ㅋㅍ로 초성 동일(중의성 문제), ㅅㄱ=사과(ㅅ,ㄱ)✔. 대체로 PASS, ㅋㅍ 문항 중의성 주의`
- [ ] **QA7** answer 인덱스가 옳은 보기를 가리키는가 → `Q1 answer:0=기린✔, Q2 answer:0=바나나✔, Q3 answer:1=학교✔, Q4 answer:2=커피✔, Q5 answer:0=사과✔ (PASS)`
- [ ] **QA8** 5문제 후 '결과 보기'로 라벨이 바뀌고 결과 화면으로 전환되는가 → `index>=4에서 nextBtn 라벨 '결과 보기', 탭 시 result state 전환. 단 nextBtn.label 바인딩도 component prop이라 갱신 안 될 위험(검증 필요)`
- [ ] **QA9** 오답 보기는 매력적 함정인가(콘텐츠 품질) → `오답이 그럴듯해야 함. Q2 비누눈/분노나/보너느는 비단어(말이 안 됨)라 함정이 약함 — 콘텐츠 개선 여지`

## 현재 깨짐 (진단)
- **[high]** 보기 카드(opt0~opt3)의 label이 다음 문제로 넘어가도 갱신되지 않는다. 스크린샷3은 Q2(초성 'ㅂㄴㄴ', 힌트 '노란색 과일')로 바뀌었는데도 보기는 여전히 Q1의 '기린/구름/가루/고리'다. OptionCard 컴포넌트 인스턴스의 propValues 바인딩(opt0.label 등)이 초기 렌더 이후 재전파되지 않음 — 정답을 고를 수 없어 게임이 근본적으로 깨짐.
  - 근거: quiz-choseong-3.png: 초성/힌트는 Q2로 갱신됐으나 4개 보기 카드는 '기린/구름/가루/고리'(Q1) 그대로. 구조상 states.quiz.bindings의 opt0.label='questions[index].options[0]'(line 467-470)이 component prop이라 재전파 실패
  - 수정: 옵션 라벨을 OptionCard 컴포넌트 prop 바인딩 대신, OptionCard 내부에 노출된 text 레이어를 직접 바인딩하거나, 각 옵션을 component가 아닌 container+text로 만들어 text.content를 state-level 바인딩(MEMORY: bindings must be state-level, doc-top component-prop don't re-propagate)으로 갱신. componentDef의 OptionCard lbl을 인스턴스에서 직접 타게팅 가능하게 노출.
- **[high]** 점수 카드(scoreCard.value)와 진행 카드(progressCard.value)가 변하지 않는다. 정답을 맞혀 피드백이 '정답이에요! +1점'으로 떴는데도 점수 카드는 0점, 진행은 1/5 그대로다. StatCard 컴포넌트 인스턴스 propValues 바인딩이 재전파되지 않는 동일한 결함.
  - 근거: quiz-choseong-2.png: feedbackText는 '정답이에요! +1점'(라임)으로 갱신됐으나 scoreCard '0점', progressCard '1/5' 고정. 구조상 scoreCard.value='`${score}점`'(line 464), progressCard.value(line 463)가 component prop
  - 수정: StatCard도 OptionCard와 동일하게 내부 val text 레이어를 직접 state-level 바인딩하도록 변경. 점수/진행 같은 핵심 HUD는 component-prop 우회 금지.
- **[medium]** feedbackText는 갱신되는데(plain text 레이어) 같은 화면의 component-prop 바인딩들은 안 됨 — 일관성 없는 갱신으로 사용자가 '맞혔다는데 점수는 0' 혼란. 근본 원인은 모든 동적 값을 component instance propValues로 바인딩한 설계.
  - 근거: chosungText/hintText/feedbackText(plain text shape, line 210-235)는 갱신 확인됨, 반대로 opt/stat(component shape)는 미갱신. 두 갱신 경로의 신뢰성 차이
  - 수정: 동적으로 변하는 모든 값은 plain text 레이어 + state-level content 바인딩으로 통일. component prop은 정적 라벨에만 사용.
- **[low]** 콘텐츠 품질: Q2 오답 보기 '비누눈/분노나/보너느'가 실재하지 않는 무의미 단어라 함정 매력이 떨어진다. 초성 퀴즈의 재미는 '그럴듯한 진짜 단어들 중 고르기'에 있는데 비단어는 정답을 너무 쉽게 노출.
  - 근거: variables.questions[1].options(line 50-55): 바나나/비누눈/분노나/보너느 중 3개가 비단어
  - 수정: 같은 초성을 공유하는 실재 단어로 오답 구성(예 ㅂㄴㄴ → 바나나/베네냐 같은 식은 어려우니, 초성 일부만 겹치는 실단어보다는 의미상 헷갈리는 실단어로). 또는 오답도 실재 단어(예 다른 과일)로 교체.

## 멀티 변형 아이디어 (별도 앱)
멀티 버전으로 만들면 매우 재밌다: 같은 초성 문제 세트를 여러 명이 동시에 푸는 live-race(라이브 스피드 대결) — 누가 먼저 정답 탭하는지 실시간 점수 레이스, 또는 turn 기반으로 돌아가며 출제. together-categories의 live-race 메커닉에 적합. 현재 앱은 single로 못박고, 멀티는 'quiz-choseong-race' 별도 앱으로 분리 권장(서버 setVar로 점수 동기화).
