# 라이브 스피드 퀴즈 (멀티 · 세션)  —  id: speed-trivia-score

## 한 줄
같은 문제를 동시에, 빠르고 정확할수록 고득점 — 카훗식 라이브 퀴즈쇼.

## 왜 인기 (근거)
- **검증된 포맷**: Kahoot!·Quizizz로 전 세계 교실·회식·MT에서 통한 "동시 풀이 + 속도 점수 + 라운드 사이 리더보드" 루프. 새 규칙을 가르칠 필요가 없다.
- **휘발성/스낵에 정확히 맞음**: 한 판이 N라운드(보통 5~7), 라운드당 수 초. 계정·스트릭·XP 없이 "지금 이 자리에서" 끝나는 micro-feel.
- **긴장 곡선 내장**: 매 라운드 끝마다 순위가 뒤집히는 리더보드 리빌 → "한 문제 남았을 때 역전" 드라마가 자연 발생. 끝까지 본다.
- **입력이 단 한 번의 탭**: 4지선다 색 버튼 탭. 키보드/그리기/카메라 불필요 → 모바일 세로 한 화면에 완벽히 맞는다.

## 세션 흐름 (화면별)
- **대기실(lobby)**: 방 코드/공유 링크(`/p/tpl-speed-trivia-score`), 들어온 사람 roster(닉네임 + 인원수 "3/8"), 총 라운드 수 표시, 호스트(첫 입장자)에게 **시작하기** 버튼. 최소 2명 모이면 활성화.
- **카운트다운**: 전 클라이언트 동기화된 3·2·1 (서버 `sessionPhase=countdown` 브로드캐스트). "곧 시작!" 문구.
- **플레이(play) — 멀티라운드**:
  - 서버가 `roundContent`(현재 라운드 문제 + 4지선다)를 모든 클라이언트에 broadcast → 전원 같은 문제를 동시에 본다.
  - 화면 상단: 라운드 표시("3 / 6"), 문제 텍스트, 라운드 제한시간 카운트다운 바(예: 15초, 서버 권위).
  - 화면 하단: 4지선다 컬러 버튼(빨/파/노/초 + 도형) 한 번 탭. 탭하면 본인 선택 잠금("선택 완료 · 결과 대기").
  - 라이브: "답한 사람 N/8" 진행 바가 차오름(정답 내용은 라운드 종료 전까지 숨김).
  - 점수 규칙: **정답 + 빠를수록 고득점**(예: 기본 500 + 남은시간 비례 보너스 최대 500, 오답 0). 라운드 종료 시 서버가 채점.
  - 라운드 종료 → 정답 강조 + 본인 획득 점수 → **라운드 사이 리더보드**(누적 점수 정렬, 상위 순위 강조) → 서버가 다음 라운드 `roundContent` 재송출 + 라운드별 응답 상태 리셋. 마지막 라운드까지 반복.
- **결과(result)**: 최종 누적 점수 리더보드 1·2·3등 시상대 강조, 1등 닉네임 크게. 본인 최종 순위/점수. 호스트에게 **다시** 버튼 → 새 문제 세트로 카운트다운부터 재시작(`sessionPhase=countdown`).

## 컨트랙트 매핑
- **주 컨트랙트: `score`** (per-player 누적 점수 → named leaderboard `raceBoard`). tally/vote 아님 — 점수가 단순 +1이 아니라 정확도·속도 가중치이기 때문.
- **라운드 필요: 예 (multiRound).** 서버가 라운드를 advance하고 `roundContent`를 매 라운드 재송출, 라운드별 응답 상태를 리셋.
- host event emit 시점:
  - `start` — 대기실에서 호스트가 **시작하기** 탭 → 서버가 `sessionPhase=countdown`→`play` 전이, 첫 `roundContent` broadcast.
  - `score` — 플레이 중 플레이어가 4지선다 한 버튼 탭 시 emit. payload에 `{ round, choiceIndex, clientTimeMs }`(또는 서버가 수신 시각으로 속도 측정). **점수 계산은 서버 권위**(정답 여부 + 응답 속도) → 클라가 보낸 raw 점수를 신뢰하지 않는다.
  - (tap/vote/tally는 사용 안 함.) 라운드 advance는 서버 타이머가 주도(제한시간 만료 또는 전원 응답 시 즉시 채점→리더보드→다음 라운드). 별도 host event 없이 서버가 `sessionPhase`/`roundContent`/`raceBoard`를 setVar broadcast.
- 서버→클라 broadcast 변수: `sessionPhase`(lobby/countdown/play/roundReveal/result), `roster`, `roundContent`, `roundIndex`/`roundTotal`, `answeredCount`, `raceBoard`(누적 점수 정렬된 named 리더보드), `roundDeadlineTs`(클라 카운트다운 바 동기화용).

## 콘텐츠
- **서버 권위 콘텐츠팩 필수.** 모든 클라이언트가 같은 문제·같은 정답을 보도록 서버가 보유 후 라운드마다 `roundContent`로 송출.
- 정답(`answerIndex`)은 채점 전까지 클라에 노출하지 않거나, 노출하더라도 서버가 채점의 단일 소스. (치팅 방지 위해 라운드 종료 전 정답 미전송 권장.)
- 콘텐츠팩 JSON 형식 제안:
```json
{
  "packId": "kr-trivia-general-v1",
  "title": "상식 스피드 퀴즈",
  "roundTimeSec": 15,
  "scoring": { "base": 500, "speedBonusMax": 500, "wrong": 0 },
  "rounds": [
    {
      "q": "대한민국의 수도는?",
      "choices": ["서울", "부산", "인천", "대구"],
      "answerIndex": 0,
      "category": "지리"
    }
  ]
}
```
- 한 세션 = 팩에서 N개 라운드(셔플 가능). roster 기반 아님(문제는 사람과 무관). 닉네임만 roster/`raceBoard` 표시에 사용.
- KR 신조어/밈/트렌드 팩으로 확장 가능(동적 콘텐츠 시스템 연계: 정시 LLM 콘텐츠 갱신).

## 성공 기준
1. 2~8명이 같은 링크로 입장 시 전원 roster에 정확한 인원/닉네임 표시, **동일한 문제**를 동시에 본다(콘텐츠 동기화율 100%).
2. 카운트다운 3·2·1이 모든 클라이언트에서 1초 이내 오차로 동기화된다.
3. 정답+속도 점수가 서버 채점과 모든 클라 표시값이 일치(불일치 0건), 빠른 정답자가 느린 정답자보다 항상 높은 라운드 점수.
4. N라운드가 끊김 없이 진행되어(라운드 종료→리더보드→다음 문제 전이 누락/멈춤 0건) 최종 1등이 단일하게 결정된다.
5. **다시** 시 새 문제 세트로 카운트다운부터 정상 재시작(이전 점수 리셋, 상태 잔여 0).

## QA 검증 시나리오 (멀티클라이언트)
2~3개 클라이언트(폰/탭)로 같은 `/p/tpl-speed-trivia-score` 링크 동시 접속.

1. **입장 → roster N**: A, B(필요시 C) 입장. PASS = 모든 화면 대기실에서 동일한 인원수("2/8" 또는 "3/8")와 서로의 닉네임이 roster에 보이고, 호스트(A) 화면에만 **시작하기**가 활성화되어 보인다.
2. **시작 → 카운트다운 싱크**: A가 **시작하기** 탭. PASS = 모든 클라이언트가 거의 동시에(±1초) 3·2·1 카운트다운을 보고, 끝나면 전원 동시에 **같은 1라운드 문제 + 같은 4지선다**가 보인다.
3. **플레이 입력(라운드)**: A는 정답을 빠르게, B는 정답을 느리게, C는 오답을 탭. PASS = 각자 탭 후 본인 선택이 잠기고("결과 대기"), 모든 화면의 "답한 사람 N" 진행 바가 같이 차오른다(정답 내용은 아직 숨김).
4. **라운드 종료 → 리더보드**: 제한시간 만료(또는 전원 응답). PASS = 모든 화면에서 정답이 동일하게 강조되고, A 라운드 점수 > B 라운드 점수(둘 다 정답이나 A가 빠름) > C(오답, 0점)가 표시되며, 라운드 사이 누적 리더보드가 같은 순위로 전 클라이언트 일치한다. 이어서 전원 동시에 2라운드 문제로 넘어간다.
5. **결과 집계**: 마지막 라운드 후. PASS = 모든 화면에 동일한 최종 1·2·3등과 1등 닉네임이 보이고, 누적 점수 정렬이 클라이언트 간 일치한다. A가 **다시** 탭 시 전원이 새 문제 세트로 카운트다운부터 재시작(이전 점수 0으로 리셋)된다.
