# 상식 트리비아 레이스 `race-trivia`  ·  quiz

**Verdict:** broken  ·  **Mode:** single

## 주제 매력도
상식 퀴즈는 한국에서 검증된 인기 포맷이다(EBS 장학퀴즈, 도전 골든벨, 카카오톡 단톡 퀴즈, 잼라이브/더 퀴즈 라이브 류 실시간 퀴즈쇼). "30초 안에 최대한 많이"는 진입장벽이 0이고 누구나 자기 상식을 즉석에서 시험해보고 싶어한다. 다만 현재 문항이 "세계에서 가장 큰 바다/물의 화학식/올림픽 오륜기 개수"처럼 교과서적이라 약간 올드하다 — 더 매력적으로 가려면 K-콘텐츠/밈/신조어/연예/맞춤법 같은 "공유하고 싶은" 한국형 상식으로 절반쯤 갈아끼우면 바이럴성이 커진다. 포맷 자체는 강력하므로 주제는 유지하되 문항 톤만 KR-트렌디하게 고도화 권장.

## 레퍼런스 (검증된 인기 포맷 모방)
- **모방 대상:** 잼라이브/더 퀴즈 라이브 (실시간 라이브 퀴즈쇼) + 표준 타임어택 트리비아(트리비아 크랙/큇업 류)
- **구조 100% 복제:** 검증된 타임어택 트리비아 룰을 100% 모방: (1) 시작 버튼 → (2) 카운트다운/제한시간 동안 4지선다 문제가 연속으로 흐름 → (3) 정답 탭 즉시 다음 문제(데드타임 0) → (4) 제한시간 종료 시 점수 자동 집계 → (5) 점수 화면 + 리더보드 순위. '빨리·많이 맞히기'가 핵심 동기. 단판 타임어택 + 랭킹 비교 구조.
- **우리 콘텐츠/디자인:** 콘텐츠: 한국형 4지선다 상식 문항 10개를 우리가 작성(역사/과학/문화/연예/밈 믹스). 디자인: 블랙(#0b0c0e) 배경 + 라임(#d9ff00) 액센트, iOS HIG 카드 톤. 구조는 라이브 퀴즈쇼와 동일하되 비주얼·문항은 우리 것.

## 목적
지하철에서, 친구 단톡에서 "나 상식 얼마나 되지?"를 30초 만에 즉석 확인하고 점수를 자랑하려고 연다. 4지선다를 빠르게 탭하며 시간 압박 속 정답 러시의 쾌감을 얻고, 끝나면 점수+리더보드로 비교·공유하는 휘발성 스낵.

## 핵심 루프
제한시간(30초) 동안 4지선다 문제를 보고 정답을 탭하면 즉시 점수가 오르고 다음 문제로 넘어가며, 시간이 끝나면 최종 점수와 리더보드 순위를 본다.

## 시나리오
1. 사용자가 앱을 연다 → ready 화면: '30초 안에 최대한 많이 맞히세요' 히어로 + 시작 버튼 노출
2. '시작' 탭 → score=0, currentQ=0, startedAt=$now 세팅 후 play 상태로 전환
3. play 화면: 상단에 맞힌 수/남은 시간 StatCard, 가운데 문제 카드(1/10 + 문항), 하단 2x2 4지선다 옵션
4. 사용자가 정답 옵션을 탭 → (정답이면) score+1, currentQ가 다음 문제로 순환, 즉시 새 문항 표시(데드타임 0)
5. 남은 시간 StatCard가 매 프레임 감소, 맞힌 수가 정답마다 증가
6. 30초 경과 → emitHostEvent('score') + result 상태 전환
7. result 화면: 🏁 + 최종 점수(N점) + TOP10 리더보드(다른 기록 들어오면 갱신)
8. '다시 도전' 탭 → score/currentQ 리셋 후 play로 재시작

## 성공 기준
- 옵션 카드에 실제 보기 텍스트(태평양/대서양/인도양/북극해)가 보여야 한다 — 'A/B/C/D' 플레이스홀더가 아님
- 정답을 탭하면 '맞힌 수'가 눈에 보이게 증가한다
- '남은 시간'이 30→0으로 실제로 카운트다운된다
- 문제·보기·힌트 텍스트가 서로 겹치지 않고 각자 영역 안에 들어온다
- 30초 후 자동으로 결과 화면으로 넘어가고 최종 점수가 정확히 반영된다
- 문항의 정답 인덱스(a)가 실제 정답과 일치한다(콘텐츠 진실성)
- 데드타임 0: 정답 탭 즉시 다음 문제로 전환된다(snappy)

## QA 검증 시나리오
- [ ] **QA1** play 화면에서 4개 옵션 카드에 questions[currentQ].opts의 실제 텍스트가 표시되는가 → `opt0~3에 '태평양','대서양','인도양','북극해' 등 실제 보기. 'A/B/C/D'면 fail`
- [ ] **QA2** 정답 옵션을 탭했을 때 '맞힌 수' StatCard 값이 +1 되는가 → `0점→1점 등 증가. 변화 없으면 fail`
- [ ] **QA3** 오답 옵션을 탭하면 점수가 그대로이고 다음 문제로만 넘어가는가 → `score 유지 + currentQ 증가`
- [ ] **QA4** '남은 시간'이 시작 후 실제로 30초에서 줄어드는가 → `수 초 경과 후 30초 미만 표시. 30초 고정이면 fail`
- [ ] **QA5** 제한시간(30초) 종료 시 자동으로 result 화면으로 전환되는가 → `result 화면 + 최종 점수 노출`
- [ ] **QA6** playHint 텍스트가 옵션 그리드와 겹치지 않는가 → `힌트가 옵션 영역 밖 하단에 단독 배치. 옵션 위에 겹치면 fail`
- [ ] **QA7** 모든 문항의 a(정답 인덱스)가 실제 정답과 일치하는가 → `예: 인체 최대 장기 a=1(피부) 정답, 물 화학식 a=2(H2O) 정답 — 전 문항 검수 통과`
- [ ] **QA8** result에서 다시 도전 탭 시 score/currentQ 리셋 후 재시작되는가 → `play로 복귀 + 점수 0부터`

## 현재 깨짐 (진단)
- **[high]** 옵션 카드에 실제 보기 텍스트가 아닌 'A/B/C/D' 플레이스홀더가 그대로 표시됨 — 퀴즈로서 플레이 불가
  - 근거: shots/race-trivia-2.png & -3.png: 문제는 '세계에서 가장 큰 바다는?'인데 4개 옵션이 'A','B','C','D'만 표시. play 상태 bindings(파일 line 686-689)가 opt0.label~opt3.label에 questions[currentQ].opts[n]을 바인딩하지만, OptionCard 인스턴스 propValues.label은 정적 'A'(line 410)이고 컴포넌트 내부 텍스트는 $props.label(line 1028)을 따름 → 인스턴스 .label 바인딩이 컴포넌트 prop으로 전파되지 않아 디폴트 A/B/C/D가 노출됨
  - 수정: 인스턴스 prop 바인딩 경로를 런타임이 지원하는 형태로 변경: bindings를 'opt0.propValues.label' 또는 OptionCard 내부 lbl 텍스트를 직접 타겟하는 방식으로. 검증된 방법은 옵션 텍스트를 component prop이 아니라 인스턴스가 노출하는 바인딩 가능한 텍스트 레이어로 두는 것(다른 동작하는 블록의 prop-binding 패턴과 동일하게 맞출 것).
- **[high]** playHint 텍스트가 옵션 그리드 위에 겹쳐 렌더됨(레이아웃 collapse/오버랩)
  - 근거: shots/race-trivia-2.png & -3.png: '빠르게 눌러도 괜찮아요. 문제는 계속 순환됩니다.' 문구가 A/B 옵션 카드 상단 안쪽에 겹쳐 표시됨. optionsGrid가 height:'fill'(line 397)로 남은 공간을 다 먹고, 그 뒤 형제인 playHint(line 462)가 그리드 영역과 겹쳐 배치됨
  - 수정: playHint를 optionsGrid 위로 올리거나 optionsGrid의 height:'fill'을 재배분(그리드를 hug+여백)하고 힌트에 고정 높이/순서 보장. 또는 힌트를 제거하고 옵션이 화면을 꽉 채우게 하여 겹침 원천 제거.
- **[high]** 남은 시간 타이머가 카운트다운되지 않고 30초로 고정, 점수도 0 고정으로 보임
  - 근거: shots -2(1/10)와 -3(2/10)에서 문제는 진행됐는데 '남은 시간'은 둘 다 '30초', '맞힌 수'는 둘 다 '0점'. timerStat.value 바인딩(line 683)이 $now 기반 onFrame 재평가에 의존하는데 프레임 루프/$now 갱신이 동작하지 않거나 StatCard value도 옵션과 동일한 인스턴스-prop 전파 문제로 갱신 안 됨
  - 수정: (1) StatCard value도 옵션과 같은 prop-binding 문제일 가능성 높음 — value를 바인딩 가능한 경로로 수정. (2) onFrame/$now 틱이 실제로 도는지 런타임에서 확인하고, 안 돌면 타이머를 setInterval성 호스트 틱 또는 검증된 프레임 패턴으로 교체.
- **[low]** 문항 콘텐츠 톤이 다소 교과서적/올드 (바이럴성 약함)
  - 근거: questions 배열(line 41-142): '물의 화학식','올림픽 오륜기 고리 개수' 등 정답 자체는 정확하나 공유 욕구를 자극하는 KR-트렌디 문항이 부족
  - 수정: 콘텐츠 진실성은 유지하되 절반 정도를 K-연예/밈/맞춤법/신조어 등 공유하고 싶은 한국형 상식으로 교체(dynamic content 시스템과 연동).

## 멀티 변형 아이디어 (별도 앱)
같은 타임어택을 '동시 라이브 레이스'로 만들면 매우 재밌다: 호스트가 시작하면 전원 같은 30초·같은 문제 순서를 동시에 풀고, 화면 하단에 실시간으로 다른 플레이어 점수 바가 차오르는 라이브 레이스(live-race 메커닉). 끝나면 즉시 TOP10 리더보드 확정. 이미 emitHostEvent 'score' + leaderboard 변수 스캐폴딩이 있으니 멀티 버전의 토대로 적합. 단 지금 앱은 single로 못박고, 멀티는 별도 앱으로.
