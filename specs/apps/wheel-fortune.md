# 행운의 룰렛 `wheel-fortune`  ·  random

**Verdict:** broken  ·  **Mode:** single

## 주제 매력도
"룰렛/돌림판 돌려서 운세·보상·벌칙 정하기"는 콘텐츠 무관하게 강력한 즉석 소비 포맷이다 — 결과를 운에 맡기는 쾌감 + 돌아가는 애니메이션의 시각적 두근거림이 핵심 매력이고, 메뉴·벌칙·복불복 등 어떤 주제든 얹을 수 있는 만능 그릇이다. 본 앱은 특정 주제(메뉴 결정 = `wheel-menu`)와 달리 '오늘의 운/보상' 이라는 가벼운 데일리 픽으로 잡아 범용 룰렛의 매력을 그대로 가져온다. 다만 현재 보상이 커피·칭찬·간식·스트레칭·꽝·물한잔·노래·벌칙 8개 고정이라 평범 — '오늘의 럭키 미션' / '복불복 벌칙' / KR 트렌드(요아정 쏘기·탕후루 사주기 같은 신조어 미션)로 주제 탭을 얹으면 공유 욕구가 커진다. 룰렛의 진짜 무기는 회전 애니메이션인데 그게 안 보이면(아래 깨짐 참고) 주제 매력 자체가 죽는다.

## 레퍼런스 (검증된 인기 포맷 모방)
- **모방 대상:** Spin the Wheel / 돌림판 룰렛 (wheelofnames·인스타 스토리 룰렛 식 픽커)
- **구조 100% 복제:** 검증된 룰렛 룰을 100% 모방: 보상 8칸 휠 → 단일 트리거(돌리기 버튼)로 빠르게 회전 시작 → 부드럽게 감속(ease-out) → 포인터가 가리킨 한 칸에 정지 → 큰 결과 카드 표시 → 즉시 다시 돌리기. ready→spinning→result 3단계 화면 전환, 회전은 cubic ease-out 3.4초. 데드타임 0, 1탭 1결과의 즉석 소비 루프.
- **우리 콘텐츠/디자인:** 콘텐츠는 데일리 보상/미션(커피 쿠폰·칭찬 3번·간식 타임·스트레칭·꽝·물 한잔·노래·벌칙)으로 우리가 채우고, 비주얼은 블랙(#0b0c0e)+라임(#d9ff00) 톤. 휠 그래디언트·중앙 허브(LUCK/SPIN)·포인터·결과 배지·StatCard(남은 시간/상태)는 우리 디자인 시스템(NavBar/Button/StatCard/Chip 컴포넌트)으로 구현.

## 목적
지루할 때 1초 만에 열어 탭 한 번으로 "오늘의 운"을 돌려보는 즉석 운세/보상 스낵. 결과보다 '돌아가는 과정의 두근거림'이 핵심 재미 — 빠르게 돌다 감속하며 한 칸에 멈추는 시각적 긴장감 + 마음에 안 들면 바로 다시 돌리는 가벼운 중독성.

## 핵심 루프
'룰렛 돌리기' 버튼을 탭하면 휠이 빠르게 돌기 시작해 3.4초간 부드럽게 감속하다 포인터가 가리킨 한 칸에 멈추고, 그 칸의 보상이 큰 결과 카드로 표시된다. 마음에 안 들면 '다시 돌리기'로 즉시 재추첨.

## 시나리오
1. 앱을 열면 블랙 배경에 8칸 보상 휠(라임→하늘→보라→코랄 그래디언트 링, 중앙 LUCK 허브)과 포인터(▼), '오늘의 운을 돌려보세요' 타이틀, 하단에 '룰렛 돌리기' 버튼이 보인다
2. 사용자가 '룰렛 돌리기' 버튼을 탭한다
3. 앱이 finalIndex를 0~7 랜덤으로 뽑고, finalAngle(2160 + finalIndex×45)을 계산한 뒤 spinning 화면으로 전환한다
4. spinning 화면에서 휠이 finalAngle까지 cubic ease-out으로 회전하고(3.4초), 상단 StatCard 2개가 '남은 시간(4→0초)'·'상태(빠르게→감속 중→곧 정지)'로 실시간 갱신된다
5. 3.4초가 지나면 onFrame 트리거가 result 화면으로 전환한다
6. result 화면에서 finalIndex에 매핑된 보상(예: '커피 쿠폰')이 라임 결과 배지에 크게 표시되고, 꽝/벌칙이면 라벨이 '오늘의 벌칙'으로 바뀐다
7. '다시 돌리기' 버튼을 탭하면 새 finalIndex로 spinning을 다시 돌려 새 결과가 나온다

## 성공 기준
- 탭→회전 시작까지 체감 지연 0, 회전 애니메이션이 실제로 화면에서 돌아가며(휠이 보이고 회전이 눈에 보임) 두근거림을 준다
- spinning 화면에 휠이 실제로 렌더되어 보인다 — 휠이 사라지면 안 됨(룰렛 앱의 존재 이유)
- 8개 보상 칸이 휠 위에서 명확히 구분되어(칸 경계/스포크 또는 명확한 섹터) '룰렛'으로 읽히고, 포인터가 어느 칸을 가리키는지 시각적으로 알 수 있다
- 모든 보상 라벨이 충분한 대비로 읽힌다 — 어두운 휠 위 어두운(#0b0c0e) 글자 금지
- 멈춘 결과(result 카드)가 회전이 멈춘 칸과 시각적으로 일치한다 — 포인터가 가리킨 칸 = 결과여야 룰렛으로서 신뢰감이 생김
- 휠/포인터/허브/라벨이 heroCard 안에 정렬되고 NavBar·StatCard·다른 영역을 침범하지 않는다
- '다시 돌리기'가 직관적이고, 매번 새 결과가 나온다

## 현재 깨짐 (진단)
- **[high]** spinning 화면에서 휠(wheelSpin/spinPlayArea)이 통째로 안 보인다. spinHero 카드가 거의 텅 비고 상단 포인터(▼)와 하단 힌트('멈추는 순간까지 결과는 비밀이에요')만 남는다. 룰렛 앱인데 정작 돌아가는 휠이 보이지 않아 핵심 인터랙션(회전 두근거림)이 완전히 죽는다.
  - 근거: wheel-fortune-2(spinning 상태) — '남은 시간 4초 / 상태 회전 중' StatCard는 정상 렌더되는데 그 아래 spinHero 카드 영역(300×300 휠이 있어야 할 자리)이 완전히 비어있음. ready 화면(wheel-fortune-1)에서는 동일 구조의 readyWheelWrap이 정상으로 보임 → spinning 상태에서만 휠 서브트리가 렌더 누락/회전 바인딩으로 깨짐.
  - 수정: spinning 화면의 wheelSpin 렌더 누락 원인 규명이 먼저. 의심 ① wheelSpin.rotation 바인딩(`finalAngle * (1 - Math.pow(...))`)이 회전 변환을 적용하며 휠을 뷰포트 밖으로 날리거나 크기를 0으로 만드는지(transform origin/anchor 미설정 → 좌상단 기준 회전으로 화면 이탈), ② spinHero가 ready의 readyHero와 달리 spinPlayArea를 flex로 잡는데 회전된 자식이 레이아웃에서 빠지며 collapse 되는지. transform origin을 휠 중심(150,150)으로 명시하고, 회전은 레이아웃 크기에 영향 주지 않도록(absolute 또는 고정 box) 보장. 메모리 'validate 통과해도 런타임 무음 실패'와 동일 계열.
- **[high]** 휠에 칸 구분(스포크/섹터 분할)이 없어 '룰렛'으로 안 읽힌다. 그래디언트 링 위에 8개 라벨이 둥글게 떠있을 뿐, 칸을 나누는 선·색 섹터·구분 경계가 전혀 없다. 포인터가 어느 '칸'을 가리키는지 알 수 없어 룰렛의 기본 가독성(어디서 멈췄나)이 무너진다.
  - 근거: wheel-fortune-1 — 라임→하늘→보라→코랄 그래디언트 단일 링 위에 커피/칭찬/간식/스트레칭/꽝/물한잔/노래/벌칙 라벨만 배치. 8등분 파이 섹터나 스포크 라인이 없음. 검증된 룰렛 포맷(파이 섹터로 칸이 명확)을 구조적으로 미모방.
  - 수정: 8등분 파이 섹터(번갈아 2~3색)나 최소한 8개 스포크 라인을 휠에 추가해 칸을 시각적으로 분할. 라벨을 각 섹터 중앙에 정렬하고, 포인터가 가리키는 섹터가 한눈에 보이게 한다. 이게 있어야 QA10(결과=가리킨 칸)도 성립.
- **[high]** 포인터(▼)가 휠 가장자리에 고정돼 휠을 가리키지 않고, 휠과 분리돼 따로 떠있다. ready에선 휠 '아래'에 라임 박스로 떨어져 있고, spinning에선 빈 카드 '위'에 떠있다. 룰렛 포인터는 휠 상단(12시) 가장자리에 닿아 안쪽을 가리켜야 하는데 그 관계가 없어, 회전이 멈춰도 '여기서 멈췄다'를 지시하지 못한다.
  - 근거: wheel-fortune-1 — ▼ 라임 박스가 휠과 타이틀 사이에 독립 배치(휠 12시 위치 아님). wheel-fortune-2 — 휠 없는 빈 카드 상단에 ▼만 떠있음.
  - 수정: 포인터를 휠 wrap의 12시 가장자리에 absolute로 고정(휠과 같은 좌표계, 끝이 휠 안쪽을 향하도록). 회전하는 건 휠, 포인터는 고정. finalAngle 계산도 '포인터가 finalIndex 섹터를 정확히 가리키도록' 보정(현재 2160 + index×45 = index×45° 회전인데 포인터 위치/섹터 오프셋과 정합 검증 필요).
- **[medium]** 멈춘 칸과 결과의 시각적 대응이 보장되지 않는다. finalAngle=2160(=6바퀴)+finalIndex×45°로 회전을 멈추지만, 포인터가 휠 12시에 고정돼 있지 않고(위 항목) 섹터 분할도 없어(둘째 항목), 사용자는 '포인터가 가리킨 칸 = result 보상'이라는 룰렛의 신뢰 계약을 시각적으로 확인할 수 없다. 논리(finalIndex→resultText)는 맞지만 보이지 않으면 의미 없음.
  - 근거: 구조상 result.resultText는 finalIndex로 결정되나, spinning 화면 휠 미표시(첫째 항목)+포인터/섹터 부재로 '멈춘 위치'가 화면에 존재하지 않음. 8칸인데 45°×index 회전이 포인터·섹터 0번 기준과 맞물리는지 미검증.
  - 수정: 첫째~셋째 항목 수정 후, finalIndex 0번 섹터가 정지 시 포인터 아래에 오도록 finalAngle 오프셋을 맞춘다(예: 섹터 폭 45°, 포인터 12시 기준 `finalAngle = 360*n - finalIndex*45` 형태로 방향·오프셋 검증). result 카드 색(라임 배지)도 멈춘 섹터 색과 연동하면 대응이 더 명확.
- **[medium]** 보상 라벨 저대비. '커피'(readyReward1/spinReward1)와 '벌칙'(readyReward8/spinReward8)이 color #0b0c0e(거의 검정)인데 어두운 inner wheel(#1e2127) 위에 올라가 거의 안 보인다. 나머지 6개는 흰색/코랄이라 보이는데 2개만 검정이라 일관성도 깨짐.
  - 근거: wheel-fortune-1 — '커피'(상단)·'벌칙'(좌상단)이 어두운 배경에 묻혀 흐릿. .bite.json readyReward1/readyReward8/spinReward1/spinReward8 color "#0b0c0e".
  - 수정: 해당 섹터를 밝은 색(라임/하늘)으로 칠해 검정 글자가 대비를 얻게 하거나(섹터 분할 도입 시 자연 해결), 라벨 색을 흰색/라임으로 통일.

## 멀티 변형 아이디어 (별도 앱)
멀티 버전이 매우 재밌을 주제다. 메커닉: spectate/turn 혼합 — 같은 방의 여러 명이 순서대로 한 명씩 룰렛을 돌리고(turn-taking), 나머지는 회전을 실시간으로 함께 보다가(spectate, setVar로 휠 각도·결과 전체 동기화) 결과에 다같이 반응하는 '복불복 룰렛'. 고도화: 보상 칸을 방장이 즉석 편집(오늘 술값 쏘기·심부름·벌칙) → 한 명씩 돌려 '걸린 사람' 확정, 이미 걸린 사람은 다음 라운드 제외(공정 룰렛)로 회식/모임 밈으로 바이럴. vote 변형: 칸 내용을 참가자 투표로 미리 채우는 것도 가능.
